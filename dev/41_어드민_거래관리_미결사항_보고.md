### 1. [돈] 반려 이의 인용 — 환불액 · 귀책 · 이미 결제된 재발송비

| 기획 | 시안 | 설계서 |
| --- | --- | --- |
| §38-5 반려 이의 인용(「인용의 효과 — 셋이 한 번에」) · §38-8 A-4 일부 반려의 재발송비 상계 · §39-3 집행 재확인 | 06b **B2** 반려 보류 상세 · 레일 인용 폼 / 06b **A3** 반려 보류 탭(재발송비 D-12) / 06c **M1** 「추가 결제」 행 | BE 38 7절 #4 · BE 39 7-2 #2 |

- 지금 코드: 환불액을 **운영자가 직접 입력**하고 `fee_bearer` · `fault_changed_to_seller`는 바뀌지 않는다. 소비자가 **재발송비를 이미 결제한 뒤** 이의가 인용되면 그 결제(`order_claim_payment PAID`)는 그대로 살아 있다.
- 왜 1순위인가: 운영자 입력 금액은 오입력 시 과다 · 과소 환불이 바로 PG로 나간다. 결제된 재발송비가 남으면 소비자는 환불을 받고도 재발송비를 떼인 상태가 된다 — **돈이 틀리는 유일한 경로**다.
- 결정 요청
  1. ~~환불액 = 서버 계산 — 확정 여부~~ → ✅ **확정(2026-10-09)** — 환불액은 **서버 계산**(`price × quantity` · 귀책 브랜드라 차감 없음)이고 운영자는 입력하지 않는다(§38-5 「수정 불가」). **코드 반영 필요** — 현재 `AdminTransactionDto.DisputeAcceptRequest.amount`를 받아 `OrderClaimService.acceptRejectionDispute`에 그대로 넘긴다. 요청에서 `amount`를 빼고 서버가 계산해 `refunded_amount` · 환불 큐에 적으며, 상세에 `disputeRefundAmount`를 내려 FE가 수정 불가 값으로 보인다
  2. ~~인용 시 `fault_changed_to_seller = true` 세팅 — 확정 여부(§38-5 ①)~~ → ✅ **확정(2026-10-09) · 즉시 반영** — 인용 UPDATE(`closeRejectedByDispute`)에 `fault_changed_to_seller = true`를 같이 세운다. 「귀책」 열 · 정산 집계가 이 값을 본다
  3. ~~결제된 재발송비 — 함께 취소 vs 06c 별도 처리~~ → ✅ **확정(2026-10-09) · 인용 트랜잭션에서 자동 취소** — 별도 처리는 누락이 생긴다. 교환 철회의 선결제 재발송비 반환(`releaseAfterCancel`)과 같은 경로: 청구 `PAID → REFUNDED`(`charge.refund`) + `order_claim_payment` 취소 선점(`requestCancel`) → 커밋 뒤 `ClaimPaymentService.executeCancel` · 실패분은 정리 배치가 재시도. 06c 상세의 「별도 취소 필요」 note는 「인용 시 결제 취소됨」으로 바뀐다
  4. ~~일부 반려에서 이미 차감된 재발송비 — 환원 여부(§38-8 A-4)~~ → ✅ **확정(2026-10-09) · 환원** — 차감 근거가 사라졌으므로. 청구 `DEDUCTED → VOID`로 바꾸고 차감액을 인용 환불액에 더한다
- 확정 계산식: **인용 환불액 = `price × quantity` + (차감된 재발송비 환원분)** — 서버 계산 · 운영자 입력 없음
- 3 · 4 공통 규칙 (코드 확인 결과 · 설계 결정)
  - **가드 확장** — 재발송비가 결제(`PAID`)되거나 차감(`DEDUCTED`)되면 `finalizeCollection` · 결제 완료가 반려 클레임을 `REJECT_HOLD → RESHIP_READY`로 옮긴다. 지금 가드(`REJECT_HOLD`만)로는 3 · 4의 경우에 **인용 자체가 409**다. 가드를 `REJECT_HOLD ∨ RESHIP_READY`로 넓힌다. 재발송 송장이 등록된 뒤(`RESHIPPING` 이후)는 계속 409 — 상품이 이미 소비자에게 가고 있다
  - **박스 단위 청구** — 재발송비 청구는 회수 묶음(박스)당 하나다. 같은 박스에 **다른 반려 건이 재발송 대상으로 남아 있으면**(`REJECT_HOLD · RESHIP_READY`) 취소 · 환원하지 않는다 — 지금 미결제 요청 `VOID`의 `othersOnHold` 규칙과 같다. 남은 건의 재발송에 그 비용이 그대로 쓰이기 때문이다
- 결정권자: 기획(2 · 4) · 대표(3) — **2026-10-09 권고안대로 확정**

- 권고: 「기타」 없음 · 3종 유지. 항목 단위는 금액으로 충분하다(항목 상태 전이가 없다).

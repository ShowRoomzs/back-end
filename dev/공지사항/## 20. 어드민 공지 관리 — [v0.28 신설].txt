## 20. 어드민 공지 관리 — [v0.28 신설]

대상 화면: `ui-admin-09-notice.html` (**rev.2**), 상태 6종(목록 1 · 페이지 3 · 모달 2). 셸·테이블·모달·배지는 §16 컴포넌트를 재사용했다. 근거 와이어는 `wf-admin-08-CS콘텐츠관리` F5~F10 중 공지 부분.

**성격 — §19(FAQ)와 같은 운영자 정적 콘텐츠지만 3가지가 갈린다.**

| 구분 | §19 FAQ | §20 공지 |
| --- | --- | --- |
| 등록·수정 UI | 모달 | **전체 페이지**(리치 에디터·이미지) |
| 내리는 방식 | **삭제**(복구 불가) | **게시 종료**(되돌릴 수 있음, 삭제 없음) |
| 순서 | 드래그 수동 지정 | **중요 고정 + 등록일 최신순** 자동 |

### 20-1. 상태 정의 — 2종 — `FE`·`BE`

| 상태 | 의미 | 배지 색 |
| --- | --- | --- |
| 게시 | 소비자 앱 공지사항에 노출 중 | **성공** |
| 게시 종료 | 노출 중단 — 목록에는 남아 있음 | **중립**(원칙 ②) |

| 항목 | 규칙 |
| --- | --- |
| **삭제** | **없다.** 내릴 때는 게시 종료로 처리한다 |
| **임시저장** | **폐지.** 초안 상태를 두지 않는다 |
| 와이어 대비 | 와이어는 `게시`와 (상품 문의의)`숨김`에 **같은 검정 배지**를 썼다. 하나의 색이 "정상 노출"과 "차단"을 동시에 뜻해 **원칙 ③ 위반**이라 분리했다 |
| **중요** | **상태가 아니라 분류다.** 중립·점 없는 배지로 제목 앞에 둔다 |

**삭제를 두지 않는 이유** — 공지는 **"그때 무엇을 알렸는가"가 기록으로 남아야 한다.** 정책 변경·점검 안내는 나중에 분쟁 시 근거가 된다. §19(FAQ)가 삭제 가능한 것과 갈리는 지점이다.

**임시저장을 폐지한 이유** — 초안 상태가 있으면 "쓰다 만 공지"가 목록에 쌓이고, 게시 판별이 상태 3종으로 늘어난다. 공지는 쓰면 바로 올리는 성격이다.

### 20-2. 상태 전이 — 폼 저장과 완전 분리 — `FE`·`BE`

| 현재 | 액션 | 결과 |
| --- | --- | --- |
| — | 등록(20-4) | **게시** — 즉시 노출 |
| 게시 | 게시 종료(20-5) | 게시 종료 |
| 게시 종료 | 게시(20-5) | 게시 — **등록일·수정일 갱신 없음** |
| 게시 / 게시 종료 | **수정 저장** | **상태 유지** |

| 항목 | 규칙 |
| --- | --- |
| **핵심 원칙** | **저장은 상태를 건드리지 않는다.** 게시 종료 상태에서 저장해도 재게시되지 않으며, 재게시는 목록의 `게시` 버튼에서만 일어난다 |
| 게시 종료 상태의 수정 | **허용한다** — 내려간 공지의 문구를 미리 손봐 두고 준비되면 게시하는 운영 흐름을 지원한다. 저장이 곧 게시가 되면 **의도치 않은 노출**이 생긴다 |
| 재게시 시 일시 | **등록일·수정일 모두 유지.** 갱신하면 오래된 공지가 목록 최상단으로 튀어 올라간다 — 재게시는 새 공지가 아니다 |
| 예약 게시·게시 기간 | **두지 않는다.** 종료 시점은 운영자가 수동으로 판단한다 |

| 행 상태 | 노출 버튼 |
| --- | --- |

| --- | --- |
| **정렬** | **중요 고정 상단 + 등록일 최신순.** 수동 순서 조정을 두지 않는다 — 공지는 시간순이 자연스러운 콘텐츠다 |
| 헤더 설명문 | 페이지 상단에 노출 규칙을 명시한다(소비자 앱 노출 · 중요는 상단 고정) |

| 표시 건수 | 20 / 50 / 100건씩 |
| 행 클릭 | **상세로 가지 않는다** — 수정 페이지 진입은 `수정` 버튼으로만(§19와 동일) |

**의도적으로 두지 않는 것** — 조회수 컬럼 · 작성자 컬럼(수정 페이지에서 확인) · 드래그 순서 조정 · CSV 내보내기.

### 20-4. 등록·수정 — 전체 페이지 — `FE`·`BE`

**모달이 아니라 전체 페이지다.** 리치 에디터와 이미지 삽입에 폭이 필요하다. §19(필드 3개, 모달)와 갈리는 지점이다.

| 영역 | 내용 |
| --- | --- |
| 좌측 | 제목(**필수**) + 본문 에디터(**필수**) |
| 우측 | 상태 + 메타 + **중요 체크박스** + 액션 + 안내문 |
| 헤더 | `목록` 버튼만 — 이전/다음 이동을 두지 않는다 |

**본문 에디터 요건**

| 항목 | 내용 |
| --- | --- |
| 툴바 | 본문 스타일 · 굵게/기울임/밑줄/취소선 · 불릿·번호 목록 · 링크 · **이미지** · 표 · 구분선 |
| 이미지 | **최대 3장 · 합계 10MB** |
| 글자수 | 공백 포함 카운터 표시 |
| **서버 검증** | 이미지 장수·용량을 **서버에서 다시 검증**한다. 클라이언트 제한은 우회 가능하다(§0-2 1번과 같은 사고 지점) |

**우측 게시 설정 — 상태별 차이**

| 상태 | 표시 | 주 액션 |
| --- | --- | --- |
| 등록 | `등록 후 상태: 게시` + 중요 체크박스 | **게시** |
| 수정(게시) | 등록일시 · 최종 수정 · 작성자 + 중요 체크박스 | **저장** |
| 수정(게시 종료) | 위 + **게시 종료 일시** + 안내문("저장해도 다시 노출되지 않습니다") | **저장** |

| 항목 | 규칙 |
| --- | --- |
| 필수 | 제목 · 본문 2종 |
| 노출 시점 | **등록 = 즉시 게시** |
| 노출 대상 | 본문이 **소비자 앱 공지사항에 그대로** 실린다 |
| 중요 체크 | 목록 상단 고정 노출. 수정 시 해제도 가능하다 |

### 20-5. 게시 종료 · 재게시 — `FE`·`BE`

**두 모달은 같은 컴포넌트에 문구·라벨만 반대다.**

| 항목 | 게시 종료 | 재게시 |
| --- | --- | --- |
| 진입 | 목록 `게시 종료`(게시 행) | 목록 `게시`(게시 종료 행) |
| 확인 모달 | **필수** · 소형(입력 필드 없음) | 동일 |
| 본문 | **대상 제목 원문** 삽입 | 동일 |
| 안내 | 앱에서 즉시 내려감 · **삭제되지 않고 목록에 남음** · 언제든 재게시 가능 | 앱에 즉시 노출 · **등록일·수정일 유지** · 중요 여부와 등록일 순으로 배치 |
| **주 액션 색** | **주 액션(파랑)** — 위험색이 아니다 | 주 액션(파랑) |
| 사유 입력 | **없음** | 없음 |

**게시 종료를 위험색으로 두지 않는 이유** — 삭제가 아니라 **노출만 중단**이며 되돌릴 수 있다. 위험색을 쓰면 복구 불가로 오인된다. §18-5(상품 문의 삭제, 위험색)와 갈리는 지점이다.

**사유를 받지 않는 이유** — 운영자 내부 콘텐츠라 소명할 상대가 없다(§19-6과 같은 논리).

1:1 / 상품 문의 분리 — 두 문의는 답하는 주체와 공개 범위가 다릅니다(1:1 = 운영팀 · 비공개 / 상품 = 판매자 · 상품 상세에 공개). 한 목록에 섞으면 "왜 이 답변은 늦지" 같은 오해가 생기므로 상단 탭으로 갈랐고, 탭마다 건수를 붙여 어느 쪽에 내역이 있는지 먼저 보이게 했습니다. 하단 CTA와 빈 상태 문구도 탭에 따라 바뀝니다(탭을 눌러 확인해 보세요). 활성 탭은 잉크 밑줄 — 로즈는 공구 신호 전용입니다.

행 구성 — 상태 배지 + 유형 + 작성일 한 줄 → (상품 문의는 상품명 한 줄) → 문의 본문 2줄 → (1:1은 연결된 주문 카드) → (답변 미리보기). 두 종류가 같은 골격을 공유하되 맥락 줄만 다릅니다.

펼치는 방식이 다른 이유 — 상품 문의는 아코디언(탭하면 전문과 판매자 답변이 그 자리에서 펼쳐짐), 1:1 문의는 상세 화면으로 이동합니다. 상품 문의는 질문 하나에 답변 하나로 끝나 목록 안에서 다 읽히지만, 1:1은 주문 카드·첨부 사진·추가 문의가 이어지는 스레드라 별도 화면이 필요합니다.

답변 대기는 펼치지 않습니다 — 셰브런도 그리지 않고 탭해도 열리지 않습니다. 펼칠 것이 없는데 화살표를 두면 눌러 보고 빈 안내만 확인하게 되고, "답변 대기"라는 상태 표기가 이미 같은 말을 하고 있습니다. 상태를 맨 앞에 둔 이유는 목록에서 가장 먼저 궁금한 것이 "답변이 왔는지"이기 때문입니다.

상태 색 — [답변 대기]는 로즈 채움, [답변 완료]는 중립 회색입니다. 로즈를 대기에 쓴 것은 사용자가 기다리는 상태가 눈에 걸려야 하기 때문이고, 완료는 이미 해결된 것이라 조용히 물러납니다.

필터 — [답변 대기만] 체크로 좁힙니다(눌러 보세요). 정렬 시트를 쓰지 않은 이유는 문의 내역은 항상 최신순이면 충분하고, 실제로 필요한 것은 "아직 답 안 온 것만 보기" 하나이기 때문입니다.

스레드 구조 — 상태·유형·날짜 머리 → 연결된 주문 → 내 문의(첨부 사진 포함) → 운영자 답변. 주문을 연결하지 않은 문의는 해당 블록을 아예 노출하지 않습니다(우측 Tweaks의 detailOrder로 전환) — 서비스·계정 문의는 주문과 무관하므로 빈 안내 블록이 오히려 잡음이 됩니다. 답변은 회색 블록으로 감싸 내 글과 구분했습니다. 채팅 버블(좌우 정렬)을 쓰지 않은 이유는 문의가 실시간 대화가 아니라 하루 단위 왕복이고, 버블은 짧은 대화에 맞는 형식이라 긴 답변에서는 가독성이 떨어지기 때문입니다.

이어서 문의하기 — 새 문의를 만들지 않고 같은 스레드에 추가합니다. 새로 접수하면 담당자가 앞의 맥락을 못 보고 사용자도 같은 설명을 반복해야 합니다. 파괴적이지 않지만 주 액션도 아니라 중립 외곽선입니다.

## 1. 범위와 판정 기준

- **대상**: 55 계획서 12-1 의 구현 39개 항목. 1단계 결함(S1 · S2 · M3-1 · P3) · 파트너센터(P1 · P4 · P5 · M10) · 스튜디오(S3 ~ S12) · 어드민 회원(M1 ~ M9) · 어드민 홈 · 게시물 · 스레드 · 지표(A1 ~ A5 · A7 ~ A12 · A14 · A15).
- **범위 밖**: 보류 4건(P2 공유 수 · A6 이의 신청 사유 · 첨부 · A13 과세 유형 · M3-4 약관 동의 버전) · 「기획 제외」 컨트롤러(CLAUDE.md) · FE 전용 표기(배지 색 · 문구 줄바꿈).
- **판정 우선순위**: 시안(1021 > 1017) → 계획서 결정(D1 ~ D26) → 원 설계서. 계획과 다르게 구현한 점(계획서 12-2)은 구현 쪽이 정본이다.
- **실행 환경**: 통합 테스트는 H2(MySQL 모드 · Hibernate ddl) 위 MockMvc 다. **Flyway 는 돌지 않는다** — V214 ~ V216 은 7절에서 실제 MySQL 로 따로 본다. JDBC INSERT 는 컬럼 DEFAULT 가 적용되지 않는다(NOT NULL 열은 값을 넣는다). 응답의 `LocalDateTime` 은 끝에 `Z` 가 붙는다.
- **시각 의존 케이스**(이번 달 경계 · 경과 일수 · 10분 만료 · 자동 해제)는 SQL 로 시각을 소급하거나 도메인 서비스를 `now` 인자로 부른다.

### 1-2. 공통 확인 방법

- **응답** — `jsonPath` 로 필드 존재 · 값 · null 을 본다. 새 필드는 「없음」과 「null」을 구분하지 않는다(Jackson 설정상 null 은 생략될 수 있다).
- **DB** — 상태 전이 · 이행은 `jdbc.queryForObject` 로 행을 직접 본다.
- **메일** — `MailService` 는 통합 테스트에서 mock 빈이다. 호출 인자(수신 주소 · 받는 쪽 · 이름 · 사유 · 안내)를 `verify` 한다. HTML 본문은 수동으로 본다(8절).
- **설정값** — `MemberProperties` 를 바꾼 테스트는 `finally` 에서 원래 값으로 되돌린다.

## 9. 교차 시나리오(E2E · 여러 역할)

자동 테스트는 대부분 단일 API 단위다. 아래는 역할을 넘나드는 흐름을 한 번에 본다(통합 테스트로 옮길 후보 · 스테이징 수동).

| ID | 흐름 | 확인점 |
| --- | --- | --- |
| E2E-01 | **브랜드 탈퇴 한 바퀴** — 파트너 계정 탭(BLOCKED · 내역) → 조건 정리 → 신청 → 어드민 브랜드 목록 대기 탭 · 상단 고정 → 상세 심사 카드 `conditions` → 반려(미종결 주문) → 메일 · 알림함 → 파트너 `lastRejection` → 재신청 → 승인 → 메일 → 로그인 차단 | 잠금이 신청 ~ 반려 사이에만 걸린다 · 목록 요약 · 홈 탈퇴 큐 · 배지가 같은 수 · 메일 2통 |
| E2E-02 | **계좌 변경 한 바퀴** — 스튜디오 계좌 변경 요청 → 지급 배치 실행(보류 유지) → 사업자 구분 변경 버튼 비활성 사유 → 어드민 변경 요청 승인 → PG 실존 확인 → 지급 | 확인 전에는 어떤 경로로도 지급되지 않는다 · 새 계좌로 지급된다 |
| E2E-03 | **정지 → 소명 → 해제** — 어드민 인플루언서 정지(종료일) → 스튜디오 홈 연장 카드 · 거절 가능 · 수락 막힘 → 운영팀 채널 답글 → 어드민 소통 스레드 목록 상단 고정 · 정보 바 정지 사유 · 기간 → 읽음 → 자동 해제 배치 | 고정 · 해제 · `term` 이 세 화면(스튜디오 · 어드민 상세 · 스레드)에서 같다 |
| E2E-04 | **소비자 정지 판단** — 어드민 소비자 목록 → 상세(실제 구매액 · 반품률 · 정지 이력) → 열람 해제(사유) → 10분 뒤 재마스킹 → 정지(종료일) → 소비자 앱 탈퇴 시도(설정 true 면 가능) | 로그 · 이력 · 다른 운영자 화면에는 해제가 보이지 않는다 |
| E2E-05 | **무료배송 기준 이행** — V214 전 0 인 브랜드로 장바구니 · 주문서 · 상품 상세 → V214 → 같은 화면 · 이행 전 결제된 주문의 일부 반품 | 이행 전에도 계산은 「없음」 · 옛 주문 반품 차감은 결제 시점 그대로 |
| E2E-06 | **홈 할 일 합계** — 계약 해지 요청 · 변경 요청 · 차감 미회수 · 소통 답글을 하나씩 만들고 홈 · 배지 비교 | 할 일 합계 = 배지 합(계약 포함 · 소통 스레드 제외) · 보조줄 |

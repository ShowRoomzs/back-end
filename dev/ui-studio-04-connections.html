근거: wf-studio-02-연결계약(F1·F2, 연결·소통 부분) · ui-partner-03-connections.html(컴포넌트·도메인 규칙 재사용) · SHOWROOMZ_거래플로우_상태정의서_v1.2 §2(연결)·§3(소통 스레드) · GNB #3(계약 관리는 별도 화면, 이번 스코프 밖)

[스코프 확정] 이번 작업은 연결·소통만 포함(1:1 소통 2패널 + 연결 요청함) — 이슈 스레드(3자 채널)와 계약 관리(GNB #3)는 별도 작업으로 분리(2026.08 확정).
[메인 셸 신규 구축] 쇼룸 스튜디오 로그인 후 메인 셸(GNB+탑바)을 이 화면에서 처음 구축 — 파트너센터(ui-partner-04) 선례와 동일하게 ui-partner-03-connections.html 셸 패턴을 그대로 재사용, GNB 라벨만 스튜디오 기준(wf-studio-02)으로 교체.
[구조 차이 — 수신 측] 파트너센터(발신 측)와 달리 [+ 연결 요청] 버튼 없음 — 연결은 항상 브랜드가 발신, 인플루언서는 수락/거절만 수행(wf-studio-02 F1·F2 근거). 좌측 목록은 연결됨 / 요청함 2탭 구조로 재구성.
[운영자 고정 채널 · 확정] SHOWROOMZ 운영팀 채널을 파트너센터와 동일하게 스튜디오에도 적용 — 연결된 브랜드 유무와 무관하게 "연결됨" 탭 최상단에 항상 고정 노출(2026.08 확정, wf-studio-02엔 미표기였으나 대칭 적용 결정).
[계약 확인 버튼 게이트] [계약 확인] 버튼은 해당 브랜드와의 계약이 존재할 때만 노출 — 없으면 버튼 자체를 숨김(파트너센터의 [계약 작성] 버튼과 동일 게이트 원칙, 방향만 반대).
[컴포넌트 재사용] 첨부·메시징 컴포넌트(mgrid/lightbox/vplayer/file-chip/th-input 등)는 ui-partner-03-connections.html과 완전 동일 마크업 재사용 — 프론트 리프트 시 컴포넌트 공유, 별도 재설계 없음. 도메인 규칙(500MB 용량 제한·20개 개수 제한·문서 첨부 확장 제안 등)도 동일하게 적용됨.
[제외 · 별도 작업] 이슈 스레드(브랜드+인플루언서+운영자 3자, wf-studio-02 F6)는 이번 스코프에서 제외 — 별도 작업으로 진행 예정.
S1연결·소통 · 기본 좌: 운영자(최상단 고정) + 연결된 브랜드만 노출(요청중은 목록에 없음) · [계약 확인]은 해당 상대와 체결·서명 대기 계약이 있을 때만 노출 · 연결 요청 발신 버튼 없음(브랜드가 발신 주체) · 전송 실패 시 타임스탬프 자리에 빨간 느낌표 + 말풍선 아래 [재전송]/[취소] 노출

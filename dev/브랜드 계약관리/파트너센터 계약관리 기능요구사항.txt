### 26-2. 검토 요청 — `FE`

`[검토 요청]` 버튼은 **서명도 결제도 하지 않지만**, 누르면 **편집이 잠기고 운영자 검토로 넘어간다.** 그래서 확인 모달을 **반드시 경유**한다.

**검토 대기(B3c)** — 공은 운영자에게 있고 브랜드가 할 조작이 없다. 아직 **서명이 일어나지 않았다.** 되돌리려면 `[요청 취소]`로 작성중에 복귀한다 — **자금이 움직이지 않았으므로 환불이 없다.**

**검토 반려(B3d)** — **경고색**이다(원칙 ① — 반려로 본 흐름이 멈추고 재작업이 필요하면 경고). **어느 항목이 문제인지를 함께 짚어야** 무엇을 고칠지 안다 — **반려 사유는 제목 + 상세 2단**으로 받는다(§28-4). 주 액션은 `[수정하고 다시 요청]`.

### 26-3. 서명 — `FE`

**4스텝 스텝퍼** — `어드민 검토` → `요청 발송` → `양측 서명` → `어드민 체결 처리`

**서명 진행중 3화면 — 상태값은 하나, 화면 온도가 다르다**

| ID | 구간 | 브랜드 조치 | 톤 |
| --- | --- | --- | --- |
| B4 | 양측 미서명 | `[서명 안내 다시 받기]` | 정보 |
| B4a | **내 서명 완료 · 상대 대기** | **없음** — 버튼이 사라지고 서명 완료 시각이 남는다 | 정보 |
| B4c | **상대 서명 완료 · 내 서명 필요** | **경고 톤 배너** + `[서명 안내 다시 받기]` | 배지는 정보 그대로 |

**B4c가 이 파일에서 유일하게 서명 진행중이 「내가 조치해야 하는」 상태다.** 누를 버튼이 없으므로(rev.7) **배너가 유일한 조치 신호**이고, 안내를 못 받았으면 `[서명 안내 다시 받기]`를 쓴다.

**체결 처리 대기(B4b)** — 양측 서명이 끝났지만 **아직 체결되지 않은 구간**이다. 브랜드 액션이 없고 정보색이다. **「공구는 아직 없다」는 사실을 명시한다** — 서명했으니 끝났다고 오해하면 **준비 일정을 잘못 잡는다.**

### 26-4. 체결 이후 — `FE`

| ID | 상태 | 주 액션 |
| --- | --- | --- |
| B5 | 체결완료 | **`공구 생성`** |
| **B5b** | 체결완료 · 고정 지급비 **지급 예정** | `지급 완료 기록` + `공구 관리에서 보기 ↗` |
| **B5a** | 체결완료 · 고정 지급비 **지급 기록됨** | `공구 관리에서 보기 ↗` |

**B5b에서 알려야 할 것은 「언제 얼마를 브랜드가 직접 지급해야 하는지」다** — 플랫폼이 대신 보내주지 않는다. **정보색**(정상 대기)이지만 **지급 주체가 브랜드라는 사실을 문구로 못박고**, 지급 후 `[지급 완료 기록]`으로 표시하게 한다.

### 26-5. 종결 · 재작성 — `FE`

| 상태 | 발생 | 안내 문구 성격 |
| --- | --- | --- |
| 거절 | 일방이 **사유 + 메모**와 함께 서명 거절 | 상대가 기각함 · 재협의 권유 |
| 만료 | 서명 기한 초과 → **운영자가 확인해 처리** | **거절이 아니라 무응답** · **열람 기록 유무**를 함께 표시 |
| 취소 | 브랜드가 **사유 + 메모** 입력 후 철회 | **내가 끝낸 계약** · 상대에게도 통지됨 |

종결 3종은 **같은 레이아웃**을 쓰고 문구만 다르다. **거절은 상대 메모가 있지만 만료는 없다** — 그 공백을 "계약서 열람 기록 없음" 같은 **사실**로 메운다. **종결은 계약만 종결시키고 연결은 끊지 않는다.** 플랫폼 결제가 없어 **환불 처리가 존재하지 않는다.**

**재작성 — 「이 조건으로 새 계약 작성」**

| 구분 | 항목 |
| --- | --- |
| **복사** | 계약 상대 · 공구명 · 상품 항목 · 고정 지급비 금액 · 콘텐츠 의무 전부 · 비고 |
| **비운 채로 열기** | **공구 기간**(시작 · 종료) · **게시 완료 기한** |
| **다시 받는 값** | **고정 지급비 확인 체크** — 지급 시점을 다시 고르므로 이전 동의를 승계하지 않는다 |
| **승계하지 않음** | 서명 이력 · 서명 기한 · 원 계약의 상태 |

**새 계약을 하나 더 만든다** — 원 계약은 종결 상태로 **그대로 남고**(이력 보존), **새 CTR 번호를 가진 작성중 계약**이 생성된다. **복사 직후 재검증**을 돌려(상품이 미진열로 바뀌었거나 정가가 내려갔을 수 있다) 위반 행에 에러 문구를 띄우고 `[검토 요청]`을 비활성으로 둔다. 작성 화면 상단에 **출처를 밝힌다.**

> **[화면 미제작]** 이 상태의 스냅샷은 만들지 않았다 — B1과 **값만 다른 같은 레이아웃**이다.

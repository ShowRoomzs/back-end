[상태 색 매핑] 답변대기=정보(브랜드 조치라 운영자에겐 진행 중) / 답변완료=중립 / 삭제 요청(브랜드)=경고(운영자 조치 필요) / 삭제=위험. 삭제를 원칙 ②의 중립이 아니라 위험색으로 둔 것은 ui-admin-04의 미진열 선례를 따른 것이다 — 소비자 노출이 실제로 막힌 상태는 즉시 눈에 띄어야 한다.
[와이어 수정 · 색 충돌] 와이어는 숨김과 게시에 같은 검정 배지를 썼다 — 하나의 색이 “차단”과 “정상 노출”을 동시에 뜻해 상태색 원칙 ③에 어긋난다. 상태를 “숨김” 1종에서 답변대기·답변완료·삭제·삭제 요청(브랜드) 4종으로 확정했고, 소비자 작성 폼(문의 유형 필수 · 내용 250자 · 비밀글 · 사진 최대 3장)에 맞춰 목록에 문의 유형 컬럼을 넣고 “공개/비공개”를 공개/비밀글로 바꿨다.
[와이어 수정 · 그 외] ⓐ 이모지(🔒)는 배지 텍스트로 대체했다. ⓑ 답변은 브랜드가 하므로 운영자 액션은 삭제 단독이다 — 상태와 무관하게 같은 레이아웃에 삭제 버튼만 노출한다(반려는 폐기). ⓒ 상태 컬럼은 맨 뒷열, 작성자·공개여부 컬럼은 상세에서만 확인한다.
[반려 경로 추가] 브랜드의 삭제 요청에 대해 운영자는 삭제와 반려 중 택일한다 — 반려 시 문의는 게시 유지, 상태는 답변완료로 복귀한다. 삭제 사유는 내부 기록용이지만 반려 사유는 요청 브랜드에 전달한다(요청자에게 결과 근거가 필요하므로). 작성자(소비자)에게는 어느 쪽도 통지하지 않는다. [신규제안 · 확인 필요] ⓐ 삭제 요청을 거쳐 삭제된 건은 삭제 요청 카드를 지우지 않고 문의 내용 카드 아래에 남긴다 — 브랜드가 왜 요청했고 운영자가 무엇을 근거로 집행했는지가 한 화면에서 대조돼야 분쟁 시 소명이 된다. 요청 없이 운영자가 직접 삭제한 건(C4)은 이 카드가 없다. ⓑ 삭제 사유는 내부 기록용이며 작성자에게 통지하지 않는다 — 우측 처리 카드에 사유·상세 사유를 함께 둔다.
[규격 정합] 테이블 본문 셀은 어드민 공통 규격대로 14px 16px · 행높이 50px(ui-admin-05 실측 13px과 1px 차이 — 디자인시스템 파일의 미결 항목). 상세 필드 행은 9px · 라벨 140px(.frow). 목록 툴바 오른쪽은 설명문이 아닌 표시 건수 드롭다운(.sel-sm)만 둔다.
[주석 분리] 설계 근거는 이 박스와 각 상태의 .state-spec에만 둔다 — .stage 안에는 규칙 메모를 넣지 않았다.

[범위 확정 · 2026.08] 서브탭 6개 중 4개만 대상: 사업자 정보 · 정산 계좌 · 담당자·CS · 계정(탈퇴 섹션 제외). 배송·반품 정책 / 택배 연동은 법률 검토 이후 제작 — 서브탭 위치만 확보하고 "준비중" 비활성 표기. 브랜드 탈퇴는 카드 자체를 넣지 않음(법률 검토 후 별도 화면 신설).
[rev.2 · 유효성 검사 신설] 수정 가능한 필드 전부에 검증·오류 문구 추가. 플레이스홀더·검증 규칙·오류 문구는 가입(ui-partner-02-signup) / 온보딩(ui-partner-03-onboarding)과 문자 단위로 동일하게 맞췄다. 검사 시점도 동일하게 blur 이후 → 이후 입력 변경 시 즉시 재검사. 조회 전용(disabled) 필드는 검증 대상이 아니다.
[rev.2 · 구조 변경 — 반품 수취 주소] rev.1의 단일 텍스트 입력 1개 → 온보딩과 동일한 4필드(수취인 이름 · 수취인 연락처 · 주소(우편번호 검색) · 상세 주소)로 확장. 주소는 검색 팝업 전용 readonly이며, 검색 완료 전까지 상세 주소는 비활성이다.
[rev.2 · 신규 — 비밀번호 재입력] 계정 탭 비밀번호 변경을 2필드 → 3필드(현재·새·재입력)로 확장. 가입 화면 Step1과 동일 구조.
[rev.2 · 신규 — 변경 요청 모달 3종] M1 사업자 정보 변경 요청 · M2 정산 계좌 변경 요청 · M3 접수 완료(공통). 요청 접수 후에는 해당 카드에 검토 중 배너가 뜨고 재요청 버튼이 비활성된다(중복 요청 방지).
[rev.6 · 변경 요청 결과 UI] 요청 상태를 검토 중 / 승인 / 반려 3단계로 배너에 표시한다. 색은 §9 상태색 원칙에 따라 검토 중=정보색(브랜드 조치 불필요한 정상 대기), 승인=성공색, 반려=위험색(브랜드가 서류를 고쳐 다시 요청해야 하는 상태 — 조치 필요). 반려 시에는 반려 사유를 브랜드에게 노출한다(인플루언서 입점 반려 사유가 내부 전용인 것과 다르다 — 변경 요청은 이미 심사를 통과한 브랜드이고, 사유를 알아야 재요청이 가능하기 때문). 반려 사유는 운영자가 드롭다운에서 정형 사유를 선택하고, 상세 사유는 선택 입력이다. 브랜드 화면에는 정형 사유가 항상 노출되고, 상세 사유는 입력된 경우에만 행이 추가된다(미입력 시 행 자체 비노출 — 2-F 참고). 승인·반려 배너 모두 [확인] 버튼으로 소멸하는 1회성 알림이며, 재요청은 배너를 닫은 뒤 [변경 요청] 버튼으로 한다(별도 [다시 요청] 버튼 없음). 재요청에 대기기간은 없다(브랜드 재등록 즉시 허용 규칙과 동일).
[신규제안 · 확인 필요] 반려 사유 드롭다운 항목 — 사업자 정보: ①증빙 서류 미첨부 ②증빙 서류와 요청 값이 일치하지 않음 ③서류 판독 불가(흐림·잘림) ④서류 유효기간 경과 ⑤변경 사유 불충분 ⑥기타. 정산 계좌: ①통장 사본 미첨부 ②예금주와 사업자 명의 불일치 ③계좌번호 오류·미개설 계좌 ④통장 사본 판독 불가 ⑤기타. ⑥/⑤ "기타" 선택 시에만 상세 사유 필수, 나머지는 선택.
[rev.4 · 로그인 이메일 변경 방식 확정] rev.2의 "변경 불가 · 운영자 문의"를 폐기하고 계정 탭에서 직접 변경한다(담당자 퇴사·도메인 변경 시 계정 통제권 상실 방지). 방식은 현재 비밀번호 확인 → 즉시 변경 확정이며, 인증 링크 방식은 rev.3에서 검토했으나 폐기했다. 대신 월 1회 변경 제한을 둔다. 변경 완료 시 구 이메일에 통지 발송(백엔드, UI 없음).
[rev.4 · 반품 수취 주소 = 카카오 주소 API] 주소 입력창을 클릭하면 카카오 주소 검색창이 열린다. 입력창은 readonly로 직접 입력 불가. 상세 주소는 주소 검색 여부와 무관하게 항상 입력 가능하다(rev.2~3의 "주소 검색 완료 전 상세 주소 비활성" 규칙 폐기).
[rev.4 · 버튼 문구] 변경 요청 버튼의 (운영자 검토) 병기를 제거하고 [변경 요청]으로 통일.
[rev.3 · 검토 후 유지 확정 — 재논의 금지] ① tax 확인용 이메일·브랜드 사이트 링크는 사업자 정보 탭에 그대로 둔다(정산 계좌 탭 이동안 검토했으나 폐기 — 두 값 모두 가입 Step2에서 사업자 정보와 함께 수집되므로 위치 정합이 맞다). ② tax 확인용 이메일 수정에 비밀번호 확인을 붙이지 않는다(기존 즉시 저장 방식 유지). ③ 가입 화면(ui-partner-02-signup) 라벨·필드 이동은 하지 않는다 — 이메일 2종의 라벨 정리안(로그인 이메일 / 세금계산서 수신 이메일)은 미채택.
[rev.8 · 디자인시스템 폼 규격 정합] 입력·셀렉트·텍스트영역을 SHOWROOMZ_웹_디자인시스템_v1.2 폼 규격에 맞췄다 — 높이 36 → 32px, 패딩 8px 12px → 6px 10px, 라벨 하단 여백 6 → 4px. 연동 조정: 행 라벨 baseline padding-top 9 → 7px, 비밀번호 표시 토글 28 → 26px, 주소 검색 버튼 36 → 32px(입력 높이와 일치). 셀렉트 화살표는 기존부터 DS 셰브론을 써 변경 없음.
[rev.7 · M1 구조 변경 — 새 값 입력형] 기존 M1은 변경 항목 + 사유만 받아 운영자가 대조할 "요청 값"이 없었다(어드민 대조표의 데이터 소스 부재). 이제 체크한 항목마다 현재 값이 표시되고 바로 아래에 바꿀 값을 입력한다 — M2(정산 계좌)와 동일 구조로 통일. 백엔드 brand_change_request는 두 유형 모두 {항목, 현재값, 요청값} 배열 하나로 담긴다. 브랜드가 요청한 값이 레코드에 남으므로 분쟁 시 책임 소재가 명확해진다.
[rev.7 · 사업자등록번호 제외 — 재논의 금지] 변경 항목 체크박스에서 사업자등록번호를 뺀다(7종 → 6종). 번호가 바뀌면 법적으로 다른 사업자이므로 정보 변경이 아니라 신규 입점 신청 대상이다. 목록에 두면 브랜드가 체크할 수 있고 운영자는 매번 반려해야 한다.
[rev.7 · 증빙 첨부 필수] M1 증빙 파일을 선택 → 필수로 변경(M2 통장 사본과 동일). 증빙 없는 신원정보 변경은 승인 근거가 없다.
[신규제안 · 확인 필요] ⓒ 검토 중 재요청 차단 — 동일 항목 중복 요청 방지.

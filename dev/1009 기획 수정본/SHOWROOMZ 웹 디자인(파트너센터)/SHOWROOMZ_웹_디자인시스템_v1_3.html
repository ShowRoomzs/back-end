상태색 — 조치 주체 축 (v1.3 신설)

v1.2의 4원칙은 ①에서 “운영자 조치 필요=경고/위험”만 규정해 파트너센터의 절반을 덮지 못했다 — 미답변 문의(답변대기)·신규 주문·입고 확인·서명 대기는 모두 브랜드 본인의 조치 대기다. v1.3은 조치 주체를 묻지 않고 “조치가 필요한가”만으로 색을 결정한다. 주체 구분은 색이 아니라 화면의 라벨·배치가 맡는다.

색의미군판정 기준
경고조치 필요(주체 불문)누군가가 손을 대야 다음으로 넘어가는 상태. 브랜드 조치(미답변·신규 주문·반송완료·내 서명 대기)도, 운영자 조치(재검토 대기·정산 보류)도 동일하게 경고
위험부정 결과 확정요청이 기각되어 그대로 종결된 상태 — 변경 요청 반려·삭제 요청 반려·계약 거절·분쟁. 단순 조치 대기에는 쓰지 않는다.
같은 ‘반려’라도 본 흐름이 멈추면 경고다 — 판정 기준은 반려 후 본 흐름이 계속 가는가이다. 요청만 기각되고 대상은 멀직히 살아있으면(문의는 그대로 게시, 기본정보는 기존 값 유지) 위험 — 브랜드가 아무것도 안 해도 진행에 지장이 없는 결과 통보다. 반면 반려로 본 흐름이 멈추고 재작업해야 풀리는 경우는 경고다(원칙 ① — 누군가 손을 대야 다음으로 넘어간다).
예외 2건: 진열 상태 ‘미진열’ 배지(공식 확정 예외) · 공구 게시물 ‘반려’(경고 — 공구가 준비중에서 멈추고 재등록해야 열린다)
정보정상 진행 · 대기아무도 손대지 않아도 시간·시스템이 다음으로 넘기는 상태(회수중·배송중·정산대기·상대 서명 대기)
성공정상 완결구매확정·환불완료·이체완료·답변완료·체결완료·활성
중립취소·종료·해지·미시작v1.2 원칙 ② 유지 + 아직 시작되지 않은 상태(준비중·작성중)도 여기
색은 의미군 표시일 뿐 값 구분자가 아니다. 한 목록 안에서 서로 다른 값이 같은 색을 쓰는 건 정상이다(예: 진행중·정산완료 둘 다 성공색). 값의 구분은 라벨이 한다 — 구분을 위해 색을 늘리지 않는다(원칙 ③).

인플루언서가 작성 · 브랜드는 열람만 · 확정 9종		 미작성작성중승인대기반려예약노출중숨김종료중단 공구 상태와 별 축이라 목록에서도 별 열로 둔다 — 미작성·작성중→준비중 / 승인대기→준비중(검토 중·미지급) / 반려→준비중에서 멈춤 / 예약→준비완료(승인·지급 완료) / 노출중·숨김→진행중 / 종료→종료 이후 / 중단→공구 중단(공구와 같은 위험색 — 정상 종료와 강제 끊김을 가른다). 승인대기·반려·예약은 제출·기각·통과 세 결과를 각각 맡는다 — 예약 하나로 승인 전후를 겸하면 공구가 열렸는지·돈이 나갔는지가 구분되지 않는다. 게시물은 공구를 따라가는 값이며, 공구를 움직이는 건 예약→노출중 전이 하나다.
경고색은 반려와 숨김 둘뿐인 이유 — 나머지 여섯은 정상 흐름이지만 이 둘은 운영자가 개입해 진행이 멈추거나 노출이 끊긴 상태다. 반려는 공구가 준비중에서 더 나아가지 못하고, 게시물을 고칠 권한은 인플루언서에게 있어 브랜드가 할 일은 스레드에서 확인·재등록 요청이다. 숨김은 공구는 진행중인데 게시물만 끊긴 유일한 어긋남이라 두 열의 색이 갈리는 게 정상이다. 둘 다 브랜드가 직접 고칠 수 없지만 움직여야 하는 상태라 경고다(원칙 ①). 변경 요청 반려·삭제 요청 반려가 위험색인 것과 갈리는 지점은 반려 후 본 흐름이 멈추느냐다(「상태색 — 조치 주체 축」 위험 행 참조).
미작성·작성중·종료는 전부 중립 — 미작성(상대가 착수도 안 함, 스레드에서 확인할 일)과 작성중(진행 중, 기다리면 됨)은 브랜드에게 의미가 다르지만 구분은 색이 아니라 라벨이 한다(원칙 ③)

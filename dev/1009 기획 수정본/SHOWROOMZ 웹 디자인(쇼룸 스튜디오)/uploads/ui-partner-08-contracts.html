[역할 · 방향성 · 서명 순서 확정] 파트너센터는 발신 측이다 — 브랜드가 계약을 작성·발송하고 인플루언서(쇼룸 스튜디오)가 받는다. 서명 순서도 같은 방향이다:
브랜드 작성 → [발송 = 브랜드 서명 동시] → 서명대기 → 인플루언서 서명 → 체결완료 (└ 거절 / 만료)
발송이 곧 브랜드의 서명이라 브랜드는 두 번 서명하지 않는다. 그 결과 「내 서명 차례」라는 상태가 존재하지 않고, 서명대기는 인플루언서 서명 대기 한 형태뿐이다 — 브랜드 화면에서 서명대기는 항상 "내가 할 일 없이 기다리는 중"을 뜻한다(정보색이 맞는 이유). 상대가 서명하면 브랜드 재확인 없이 즉시 체결된다.
[그래서 발송 모달이 필수다] 발송 버튼은 서명 버튼이기도 하므로 라벨을 [서명 후 발송]으로 쓰고 확인 모달(C3)을 반드시 경유한다. 되돌릴 방법은 상대 서명 전 취소뿐이다.
[상태 6종 · 확정] 아래가 유일한 값이며 새 값을 만들지 않는다.
작성중계약 시작 후 협의항목 입력 중(발송 전·임시저장)진행작성중
서명대기계약서 생성·발송 완료, 당사자 서명 대기진행서명대기
체결완료양측 서명 완료 → 계약 성립 · 공구 생성 게이트종료(성공)체결완료

[종류 축은 색이 아니다] 종료(실패) 3종이 같은 분류여도 색은 갈린다 — 거절만 위험이고 만료·취소는 중립이다. 거절은 상대가 명시적으로 기각한 부정 결과 확정이고, 만료·취소는 아무도 손대지 않아 시간·철회로 닫힌 건이라 원칙 ②(취소·종료=중립)에 속한다. 원칙 ④ 기획문서 태그와 UI 상태색은 별개가 이 경우다.
[rev.2 · 회수(작성중 복귀)는 채택하지 않음] 작성 스펙 §11에는 발송 취소(회수) → 작성중 복귀와 철회 → 취소가 함께 적혀 있었다. 둘은 같은 일(발송 되돌리기)을 다른 결과로 처리하는데 브랜드가 어느 쪽을 눌러야 하는지 판단할 근거가 화면에 없고, 무엇보다 확정 상태표에 취소는 종료(실패)로 못박혀 있어 작성중 복귀는 표현할 상태가 없다. 그래서 서명대기의 되돌림 경로는 [계약 취소] 하나로 두고 항상 종결시킨다. 회수가 필요하면 상태값 추가 여부를 먼저 정해야 한다.
[취소 = 발송 철회로 확정] 취소는 발송 후 서명 완료 전에만 가능하다 — 작성중에는 취소할 게 없고(삭제·임시저장 폐기), 체결완료 후에는 취소가 아니다. B3·B4의 [계약 취소]가 이 전이의 유일한 입구이며, 발송 전 화면(B1·B2)에는 취소 버튼을 두지 않는다.
[지적 · 체결 후 해지 값이 없다] 6종 어디에도 체결완료 이후를 닫는 값이 없다. 공구가 이미 진행 중인 계약을 중단해야 하는 상황(브랜드 재고 소진·인플루언서 콘텐츠 미이행·분쟁)에서 표현할 상태가 없다. 이 시안은 그리지 않았다 — 값을 임의로 만들지 않는 규칙에 따른다. [결정 필요] 해지 값을 추가할지, 공구 상태(중단)로만 처리할지.
[서명대기를 쪼갤 필요가 없어졌다] 발송=브랜드 서명이므로 브랜드 쪽 서명 대기 구간이 애초에 생기지 않는다. v1.3 배지 사전의 상대 서명 대기 / 내 서명 대기 2분리와 「조치 주체 축」(내 서명 대기=경고)은 폐기한다 — 표현할 상태가 없다. 서명대기는 값 하나·색 하나(정보)로 3서피스 동일하게 쓴다. 진행 위치는 상태가 아니라 4스텝 진행 단계가 보여준다.
[rev.2 · 「이 조건으로 새 계약 작성」 동작 규칙 · 화면 미제작] 종결 3종(거절·만료·취소)의 이 버튼은 새 계약을 하나 더 만든다 — 원 계약은 종결 상태로 그대로 남고(이력 보존), 새 CTR 번호를 가진 작성중 계약이 생성되어 작성 화면(B1)이 열린다. 종결된 계약을 되살리는 것이 아니다.
  · 복사 — 계약 상대, 공구명, 상품 항목(공구가·리워드율·최소 물량), 고정 지급비 금액, 콘텐츠 의무 전부, 비고.
  · 비운 채로 열기 — 공구 기간(시작·종료)과 게시 완료 기한. 과거 날짜를 그대로 복사하면 "시작 일시 ≥ 발송일 + 7일" 하드 규칙에 즉시 걸리고, 게시 완료 기한은 기간에 연동되므로 함께 초기화한다.
  · 다시 받는 값 — 고정 지급비 확인 체크. 선결제가 새로 실행되므로 이전 동의를 승계하지 않는다.
  · 승계하지 않는 것 — 서명·선결제·환불 이력, 서명 기한, 원 계약의 상태.
  · 복사 직후 재검증 — 그 사이 상품이 미진열로 바뀌었거나 정가가 내려가 공구가 > 정가가 됐을 수 있다. 진입 즉시 하드 검증을 돌려 위반 행에 에러 문구를 띄우고 [서명 후 발송]을 비활성으로 둔다.
  · 화면 표기 — 작성 화면 상단에 출처를 밝힌다(예: "봄 클렌저 공구의 조건을 복사했습니다"). [화면 미제작] 이 상태의 스냅샷은 만들지 않았다 — B1과 값만 다른 같은 레이아웃이라, 필요해지면 B1 변형으로 추가한다.
[rev.2 · 종결 스텝도 배지와 같은 색] 진행 단계의 종결 칩은 상태 배지와 같은 색 체계를 쓴다 — 거절만 위험(.stop), 만료·취소는 중립(.halt). 같은 화면에서 배지는 중립인데 스텝은 위험색이면 어느 쪽이 진짜인지 읽을 수 없다.
[상태색] 작성중=중립(아직 시작 안 함) · 서명대기=정보(정상 진행 대기) · 체결완료=성공(공구 생성 게이트가 열리는 실질적 성취라 문의의 "답변완료"와 달리 성공색) · 거절=위험(부정 결과 확정) · 만료·취소=중립(원칙 ② 취소·종료).
[상태는 탭 · 종결은 묶는다] 상태는 배타적 축이라 1단 탭. 탭 「종료」는 종료(실패) 3종(거절·만료·취소)이고, 종료(성공)인 체결완료는 별도 탭이다 — 브랜드가 가장 자주 찾는 값이고 공구 생성의 입구라 실패군과 같은 서랍에 넣지 않는다. 목록 배지는 개별 값 그대로 표시한다.
[rev.2 · 작성중과 서명대기는 같은 화면] 라우팅이 바뀌지 않는다 — /contracts/new 한 화면에서 편집 잠금 + 서명 카드 추가로만 변한다. 상태 3단계: 작성중(전 필드 입력 가능 · 하단 [임시저장]/[서명 후 발송]) → 서명대기(전 필드 읽기 전용 + 서명 영역 노출) → 종결(읽기 전용 + 체결 PDF·인증서 또는 종결 사유). rev.1의 "작성 화면과 계약서 화면을 분리" 판정은 폐기한다.
[rev.2 · 고정 지급비 신설] 매출과 무관하게 인플루언서에게 지급하는 금액. 계약서 발송 시 선결제되고 인플루언서가 공구 게시물을 쇼룸에 등록한 시점에 지급된다. 0원 초과를 입력하면 접히지 않는 고지 블록 + 확인 체크(필수)가 나타난다 — 지급 이후 콘텐츠 미이행은 환급되지 않고 회수도 실익이 없어, 발송 전 고지가 유일한 방어선이기 때문이다. 선결제는 발송·서명보다 먼저 실행된다(§10 순서 ③→④).
[권한 3분류] 계약 조건 전체(공구명·기간·상품 항목·고정 지급비·콘텐츠 의무·비고) = 발송 전 ①직접 수정 / 발송 후 ③변경 불가 — 발송 시점에 내 서명이 날인돼 있어 수정은 서명 위조가 된다. 수정하려면 취소 후 재작성 · 정산 조건·표준 조항 = ③변경 불가(표준 조항 자동 삽입, 브랜드 편집 불가) · 계약 상대 = 발송 전에도 연결됨 상대만 선택 가능(스레드 경유 진입 시 변경 불가).
[rev.2 · 샘플·단독은 협의 변수가 아니라 표준 조항] 샘플 제공과 독점(단독) 여부를 삭제하고 표준 조항으로 옮겼다 — 두 항목이 마지막이라 「협의 조건」 카드 자체가 없어졌다 — 값이 하나로 고정돼 있어(샘플은 항상 무상 제공, 판매는 항상 단독) 선택지를 주는 것 자체가 거짓이다. 고를 수 없는 항목을 입력 필드로 두면 "아니오"인 계약이 존재하는 것처럼 읽힌다. 유상 샘플의 정산 상계가 불가능한 이유는 ① 자금 방향이 한 방향 ② 비사업자 원천징수 3.3%가 총액 기준이라 순액이 음수면 세무 처리가 성립하지 않음 ③ PG 3자 분배에 음수 배분이 없음. 규칙 없는 데이터가 쌓이는 것을 막기 위해 값 자체를 잠근다 — rev.1의 유상 샘플비 차감 안내는 삭제했다.
[원가 판정 없음] 공구가의 원가 이하 여부는 판정하지 않는다 — 상품 객체에 원가 필드가 없고, 브랜드 원가는 플랫폼이 알 권리가 없는 정보다.
[rev.2 · 하드 / 경고 2단 검증] 하드는 발송을 막는다 — 공구가가 정가 초과·10원 단위 아님, 리워드율 0~90% 밖, 기간 3~30일 밖, 시작 일시가 발송일+7일 미달, 콘텐츠 수량 합계 0, 상품 항목 0건, 고정 지급비 체크 미완. 경고는 막지 않고 발송 확인 모달에서 열거 + 체크를 받는다 — 할인율 70% 초과, 리워드율 40% 초과, 기간 14일 초과, 시작일이 발송일+60일 이후, 상품 10건 초과, 고정 지급비 100만원 초과. 통과된 경고는 어드민 공구 오픈 승인 화면에 플래그로 전달된다(계약 단계에 운영자 승인이 없어 유일한 사후 실마리).
[에러 문구 vs 비활성] 필수 미입력은 에러 문구 없이 [서명 후 발송] 비활성(B1). 에러 문구는 규칙 위반에만 쓴다(B2). 전량 통과 시 버튼이 활성된다(B3). 상품을 고르면 정가를 읽기 전용 컬럼으로 병기하고 예상 리워드를 자동 계산해 위반과 오해를 미리 막는다.
[rev.2 · 2차 활용 기간 되살림] 2차 활용권(허용/불허)과 2차 활용 기간(기간 지정 N개월 / 무기한)을 별도 행으로 둔다 — 허용일 때만 기간을 입력하고, 무기한을 고르면 개월 입력이 비활성된다(기본 12개월). 허용/불허만 두고 기간을 비고로 내렸던 처리를 되돌린 것이다 — 비고는 검증도 구조화도 없는 자유 입력이라, 기간이 비면 기한 없는 영구 허용으로 해석될 여지가 생긴다(wf-partner-03 [2026.07 추가]가 못박은 지점). 허용 범위는 문장이라 비고에 남긴다.
[rev.2 · 사전 검수 설명 명시] 있음/없음만으로는 무엇이 달라지는지 알 수 없어 한 줄을 붙였다 — 있음이면 인플루언서가 게시 전 초안을 연결·소통 스레드로 보내고, 브랜드 확인 없이 올린 콘텐츠는 이행으로 보지 않는다. 이행 판정의 조건이 바뀌는 항목이라 계약서 문구와 같은 수준으로 화면에 적어야 한다.
[rev.2 · 콘텐츠 의무 항목 정리] 게시 시점(공구 전/중)과 유지 기간(게시일로부터 N일)을 삭제했다 — 둘 다 외부 SNS 연동이 없어 시점·유지 여부를 시스템이 확인할 수 없고, 실제로 다투게 되는 건 약속한 수량을 언제까지 다 올렸는가 하나다. 그래서 콘텐츠 제출 기한 → 게시 완료 기한으로 바꿨다: "이 날짜까지 게시 포맷·수량 전부를 올린다"는 하나의 약속으로 통합하고 필수로 만든다. 이행 확인은 브랜드와 인플루언서가 연결·소통 스레드에서 직접 한다 — 운영자 수기 확인 경로를 두지 않는다(운영자가 개입할 근거도 수단도 없고, 두 당사자가 이미 상시 대화 채널을 갖고 있다). 미이행은 금전 회수가 아니라 계정 제재·재계약 차단으로 처리한다.
[rev.2 · 최소 물량은 상품 단위] 최소 준비 물량을 계약 단위 입력에서 계약 상품 항목의 열로 이동했다 — 상품이 여러 개인 계약에서 계약 하나에 물량 하나면 어느 상품 몫인지 알 수 없고, 판매·재고 대조도 상품 단위로만 가능하다.
[출생지 규칙] 계약 상품 항목이 공구가·리워드율·최소 물량의 출생지다. 리워드율은 상품 항목 단위(상품마다 차등)이며 정산이 이 값을 그대로 쓴다. 공구 기간은 계약 단위이고 공구가 이를 상속한다.
[공구명은 내부 식별명] 브랜드가 입력하는 내부 관리용 이름이다. 소비자에게 보이는 게시물 제목은 인플루언서가 쇼룸 스튜디오에서 따로 쓴다 — 두 값을 같은 것으로 취급하지 않는다.
[목록 진입] 행 전체 클릭. 관리 열에 [보기]·[이어 작성] 링크를 두지 않는다(v1.3 「목록 상호작용 규칙」) — 와이어의 관리 열은 삭제했다. 작성중 행을 클릭하면 작성 모드로, 나머지는 계약서 모드로 열린다.
[rev.2 · 기간은 달력에서만 선택] 공구 기간은 직접 입력 필드가 아니라 달력 모달(C1·C2)에서 고른다. 제한값은 에러로 알리는 게 아니라 선택 자체를 잠근다 — 발송일 + 7일 미달, 기간 30일 초과는 회색 취소선으로 비활성된다. 그 결과 기간 관련 하드 오류 문구가 도달 불가능해져 B2의 에러는 직접 입력 필드(공구가)에만 남는다. 경고(기간 14일 초과 등)는 잠그지 않고 트리거 아래 힌트 + 발송 확인 모달에서 처리한다. 시작 일시와 종료 일시는 각각 다른 모달이며, 종료 모달은 시작이 정해진 뒤에만 열린다 — 종료의 잠금 범위가 시작값에 의존하기 때문이다. 달력은 한 달씩 보여주고 ‹ › 로 이동한다(선택 가능일이 없는 방향은 잠금). 시각은 각 모달 하단에서 시 드롭다운(00~23) + 분 드롭다운(5분 단위)으로 고른다 — 자유 입력이 아니라 값 자체를 제한한다.
[rev.2 · 기간 규칙 확정] 공구 시작 일시는 발송일 + 7일 이후(하드), 공구 기간은 3~30일(하드). 7일은 인플루언서 서명 → 게시물 등록 → 운영자 오픈 승인(SLA 3영업일)에 필요한 리드타임이고, 30일 상한은 상시 판매와의 구분·정산 지연 방지다. 서명 기한 = 공구 시작 일시 − 3일로 자동 설정된다(rev.1의 "발송일 + 7일" 잠정치는 폐기).
[근거 대기] ① 전자서명 업체·자체구축(감사추적인증서 전제) ② 서명 시 본인확인 수준 ③ 인플루언서 서명 위치(스튜디오 내부 vs 외부 링크) ④ 표준 조항·위약금 문안(법률 검토) ⑤ PG 수수료율 ⑥ 원천징수 처리(세무) ⑦ 대가관계(유료광고) 표시 의무 연동 [쟁점 A] ⑧ PG 자문 문항8 — 회신이 부정이면 고정 지급비 섹션 전체가 비활성된다 ⑨ 전자계약 파트너의 기안자 선서명 지원 여부 — 미지원이면 서명 순서를 인플루언서 1순위로 되돌려야 한다. 상태값 6종 자체는 확정이며, 남은 값 관련 결정은 위 「체결 후 해지 값이 없다」 하나다.

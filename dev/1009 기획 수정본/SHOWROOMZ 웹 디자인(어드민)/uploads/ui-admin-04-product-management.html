ui-admin-04-product-management — 어드민 상품 관리

근거: wf-admin-04-상품관리 · SHOWROOMZ_웹_디자인시스템_v1.2 · 필터 영역(다중선택) 컴포넌트 신설 반영

[신규제안] 진열 상태(진열/미진열/재검토대기)와 공구 상태(준비중/준비완료/진행중/연결없음)를 완전히 독립된 두 축으로 분리 — 도메인모델 §6-1 진열상태 enum이 2종→3종으로 바뀌는 변경이라 김화창님 ERD 동기화 필요.
[확정] 품절 = 재고 0일 때 자동 표시(회색 중립 배지). 별도 필터 카테고리로 두지 않고 재고(SKU) 컬럼에 부가 표시만 함.
[참고] 공구 상태 4종 중 종료·정산완료·취소된 공구는 "연결 없음"으로 합산 표시(공구 이력의 소스오브트루스는 어드민 §5 공구 관리).
[rev.2] 파트너센터 상품 등록 폼(ui-partner-04) 기준 대조 — 브랜드상품코드 제외(도메인모델상 "브랜드 내부 관리 코드·ERP 매칭용"으로 명시된 브랜드 전용 정보라 상세에서 제외, 목록 검색 편의용으로 리스트에는 유지), 나머지 등록 항목(상품 이미지·상품 설명·상품 정보 제공 고시 전체 11개 필드)은 전부 상세에 반영. 처리 이력에 상세 사유 표시 영역 추가 — 미진열 처리 시 입력한 자유 텍스트가 있으면 이력 항목 아래 인용 박스로 노출.
[rev.3] 미진열 배지 색상을 중립 회색 → 위험색(빨강)으로 변경(§9 4원칙 예외 — 소비자 노출이 실제로 막혀 있는 상태라 즉시 눈에 띄어야 한다는 판단). 목록 관리 열 삭제(행 전체 클릭으로 대체). 상품명 190px 말줄임 처리. 재고(SKU)·진열 상태·공구 상태 컬럼 및 SKU 옵션표 전 컬럼(조합명 제외) 가운데 정렬. 페이지당 건수 선택을 검색 필드 우측, 정렬 선택을 총 건수 옆(좌측)으로 재배치. 목록·상세 이미지에 확대 가능 표시(hover 강조) 추가. 카테고리 대/중/소분류 전부 표기.
[신규규칙 · 확인필요] 미진열 사유가 "브랜드 요청"인 경우, 브랜드가 이후 상품 정보를 수정해도 재검토 대기로 전환하지 않고 그대로 진행합니다(다른 3개 사유는 재검토 대기 전환 유지). 브랜드 스스로 요청한 미진열은 정보 오류로 인한 조치가 아니므로 수정 시 운영자 재검수가 불필요하다는 논리입니다. 거래플로우 상태정의서·도메인모델에 조건부 분기로 반영 필요 — 김화창님 확인 요청.
[rev.4] 품절 배지에서 재고 "0" 숫자 제거(배지만 표시). SKU 옵션표 컬럼 정렬 오류 수정(table-layout:fixed + colgroup 적용 — 내용 길이에 따라 헤더·데이터 폭이 어긋나던 문제). "등록 즉시 진열(검수 없음)" 이력 항목 삭제 → "상품 등록"으로 대체. 브랜드 상품정보 수정은 재검토 대기 전환 여부와 무관하게 항상 처리 이력에 기록(위 신규규칙 적용 시에도 로그 자체는 남김, 문구만 "(재검토 대기로 전환)" 없이 표시). 검색 필드·버튼을 필터 영역 우측 하단으로 이동, 목록 상단 툴바는 정렬순·건수 드롭다운만 우측에 배치. 상품명 영역 130px로 추가 축소, 나머지 컬럼 간격(좌우 패딩) 확대.
[rev.5] 미진열(요청) 회색 배지 신설 — 미진열 사유가 "브랜드 요청"인 건은 정보 오류·법 위반 의심 등 문제 상황이 아니므로 빨간 "미진열"과 시각적으로 구분(목록 예시 7행 참고). SKU 옵션표 헤더·데이터 정렬이 어긋나던 근본 원인 확인: .sku-tbl th의 text-align:left 규칙이 명시도(specificity)에서 .t-c보다 앞서 헤더에 먹혀 데이터만 가운데 정렬되고 헤더는 항상 왼쪽에 남아있었음 — 헤더 기본값을 가운데로, 첫 열(조합명)만 예외로 왼쪽 지정하는 방식으로 수정. 상품명 열에 고정 폭(170px) 지정해 브랜드 열과의 간격 좁힘(폭 미지정 시 남는 공간을 전부 상품명이 차지해 브랜드가 밀려나던 문제).
[rev.6] 등록/수정일 열 가운데 정렬 추가. 필터 영역 검색 행이 초기화 버튼과 다른 우측 지점에서 끝나던 문제 수정(패널 전체에 걸려있던 우측 여백을 첫 행에만 적용하도록 변경) · 검색 입력·버튼을 같은 컨테이너로 묶어 간격 정상화. B3 "상세 · 미진열(요청)" 상태 신설 — 재검토 대기 배너 대신 중립 안내 배너, 회색 배지, 처리 이력에 "브랜드가 상품 정보 수정"이 재검토 대기 전환 없이 그대로 기록되는 예시(위 신규규칙 실제 적용 화면).
[rev.7] 목록 검색 플레이스홀더에서 존재하지 않는 필드였던 "상품번호" 제거 — 실제로는 브랜드상품코드만 존재("상품명 · 상품번호 · 브랜드명"→"상품명 · 브랜드상품코드 · 브랜드명"). SKU 옵션표 "조합 진열" 컬럼이 잘못해서 3종(진열/미진열/미진열(요청))으로 표시되고 있던 것을 진열/미진열 2종으로 정정 — 조합(SKU) 단위 진열 여부는 단순 노출 on/off이고, "요청" 사유 구분은 상품 단위 개념이라 SKU 레벨에 내려오면 안 됨(B3의 SKU 표에서 발견). B4 "상세 · 미진열" 상태 신설 — 기존엔 진열중(B1)·재검토대기(B2)·미진열(요청)(B3)만 있고 사유가 있는 일반 미진열(빨간 배지, 정보고시 오류 등) 상세 화면이 빠져 있었음. 수분 진정 토너 200ml(목록 3행) 예시로 위험 배너·재검토 대기 게이트 적용 대상임을 보여줌.
[rev.8] "상품번호" 재확인 결과 실제 사용 필드로 유지 — 검색 플레이스홀더에 다시 반영("상품명 · 상품번호 · 브랜드상품코드 · 브랜드명 검색"). B4의 "사용기한·개봉 후 사용기간" 필드에 넣었던 "누락 — 브랜드 재작성 필요" 표시 삭제 — 상품정보제공고시 필드는 파트너센터 등록 폼에서 전부 필수(*) 항목이라 애초에 비워둔 채 등록될 수 없으므로 "누락"이라는 상태 자체가 성립하지 않음(모순된 예시였음). 어떤 사유로 미진열 처리했는지는 처리 이력의 사유·상세 사유만으로 충분하며, 고시 항목 자체에 결함 표시를 추가로 얹을 필요 없음 — 정상적으로 채워진 값으로 되돌림.

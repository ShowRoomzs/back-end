# SHOWROOMZ 웹 디자인 작업 규칙

## 작업 순서
- **제안표 단계 없음.** 요청받으면 바로 HTML을 작성한다.
- 다만 작업 중 판단한 것은 **작성 후 보고**한다 — 와이어와 규칙이 충돌해 한쪽을 택한 경우, 와이어에 없던 것을 추가한 경우, 와이어의 오류를 고친 경우.
- **구조적 문제나 규칙 충돌이 화면 구성을 좌우할 정도면** 작업 전에 그것만 짧게 지적하고 확인을 받는다(표 형식 아님, 2~3줄).

## 작업 단위
- 화면 분할은 **사용자가 정해서 준다.** 임의로 여러 하위메뉴를 한 파일에 합치지 않는다.
- 받은 단위 그대로 한 파일로 만든다.

## 소스오브트루스
- `SHOWROOMZ_웹_디자인시스템_v1_2.html` — 색·타이포·컨트롤 토큰. `<style>` 블록 ①~⑯을 통째로 복사해 쓴다.
- 어드민 셸은 새로 만들지 않는다(사이드바 240px · 탑바 56px · 본문 패딩 24px).
- 미결 항목은 디자인시스템 파일의 `.rule` 박스에 기록돼 있다.

## 산출물
- 단일 HTML · 인라인 CSS · 외부 의존성 없음 · 1440×1024
- 파일명 `ui-admin-0N-화면명.html`
- 상태별 정적 스냅샷을 세로 나열: `.state-bar` + `.stage`
- `.stage` 안쪽 텍스트만 실제 UI. 설계 근거 메모는 `.doc-head`의 `.rule` 박스에만.

## 절대 규칙
- 액센트 인디고 `#3B5BDB` 단일. 어드민에 검정 예외 없음. 밀도 Compact. 다크모드 없음.
- 금칙어: 크리에이터→인플루언서 / 마켓·판매자→브랜드 / 구매자→소비자 / 크리에이터 스튜디오→쇼룸 스튜디오 / 앱 내 인플루언서 페이지→쇼룸.
  예외 허용: "판매자 정보(소비자 앱 법정 표기)", "브랜드(판매자) 약관", "판매자/추천인 분리 표기"
- 상태색 4원칙: ①운영자 조치 필요=경고/위험, 정상 진행·대기=정보/성공 ②취소·종료·해지=중립 회색 ③하나의 의미는 하나의 색 ④기획문서 태그와 UI 상태색은 별개 체계
- 필수 미입력은 에러 문구 없이 **버튼 비활성만**. 에러 문구는 형식 오류·중복·파일 형식/용량 오류에만.

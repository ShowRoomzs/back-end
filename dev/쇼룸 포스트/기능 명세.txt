## 24. 쇼룸 스튜디오 게시물 (일반 게시물) — [v0.32 신설]

대상 화면: `ui-studio-07-posts.html` (**rev.1**), 상태 11종(목록 2 · 작성/수정 4 · 모달 3 · 운영자 조치 2). 셸은 `ui-studio-04-connections` 복사본. GNB **#5 게시물**.

**성격 — 파트너센터에 짝이 없는 단독 화면이다.** 게시물은 **인플루언서 소유 콘텐츠**이고 브랜드는 열람만 한다. 공유 컴포넌트는 카드·폼·모달·빈 상태 수준에서만 재사용한다.

**일반 게시물과 공구 게시물을 한 목록에 섞지 않는다**

|  | 일반 게시물 (본 섹션) | 공구 게시물 (공구 관리 #4) |
| --- | --- | --- |
| 제목 | **없음** | 필수 |
| 사진 | **최대 20장** | 본문 글만 |
| 수정 | **상시 가능** | 노출중 잠금 |
| 대가관계 표시 | **없음**(광고가 아니므로) | 자동 삽입 |

작성 규칙·상태 전이·수정 가능 시점이 전부 다르다. 대신 목록 하단에 어디로 가야 하는지 한 줄로 안내한다.

### 24-1. 상태 정의 — 3종 — `FE`·`BE`

| 상태 | 의미 | 배지 색 |
| --- | --- | --- |
| 작성중 | 임시저장 — 쇼룸에 노출되지 않음 | **정보**(내 손에 있는 대기) |
| 게시중 | 쇼룸 노출 중 | **성공** |
| 노출 중지 | **운영자 조치** — 이의 신청 기간 진행 중 | **위험** |

| 항목 | 규칙 |
| --- | --- |
| **자율 숨김 없음** | 인플루언서가 스스로 내리는 방법은 **삭제(불가역)뿐**이다 |
| 노출 중지가 위험색인 이유 | **기한 내 대응하지 않으면 영구 삭제로 끝나는 상태**다(원칙 ①) |
| 상태 전환 UI | 드롭다운이 아니라 **탭** — **개수가 함께 보여야** 조치가 필요한 게시물을 바로 찾는다 |
| 목록 카드 구분 | 작성중 = 점선·회색조 / 노출 중지 = 이미지 딤 처리 |

### 24-2. 사진 — 파일·비율 — `FE`·`BE`

| 항목 | 규칙 |
| --- | --- |
| **허용 형식** | **JPG · PNG만.** 영상은 지원하지 않는다 |
| 용량·장수 | 장당 **20MB** · 게시물당 **최대 20장** |
| 대표 사진 | **첫 번째** — 쇼룸 격자 썸네일이자 게시물 비율의 기준 |
| 순서 변경 | **셀 드래그.** 화면에 문구로 안내하지 않고 커서·드래그 상태로만 드러낸다 |

**영상을 받지 않는 이유** — 릴스·영상 콘텐츠는 **인스타그램에 직접 올리는 것이 계약상 콘텐츠 의무**다. 쇼룸은 사진만 받는다.

**비율 — 연속 범위 클램프 (프리셋 없음)**

| 항목 | 규칙 |
| --- | --- |
| 허용 범위 | **1.91:1(가로) ~ 4:5(세로)** |
| 범위 안 | **원본 비율 그대로**(3:2 → 3:2 유지) |
| 범위 밖 | 가장 가까운 **경계값으로 크롭**(16:9 → 1.91:1 / 9:16 → 4:5) |
| 게시물 단위 통일 | **첫 번째 사진의 비율이 나머지 전부에 적용** |
| 크롭 모달 컨트롤 | **드래그 + 확대뿐.** 비율 선택 컨트롤·정사각 강제 옵션을 두지 않으며 비율 수치는 **표시만** 한다 |

**비율을 고르게 하지 않는 이유** — 인스타와 동일한 방식이다. 프리셋을 주면 사용자가 매번 판단해야 하고, 게시물 단위 통일 규칙과 충돌한다.

**따라오는 영향 — 구현 시 주의**

| 화면 | 크롭 |
| --- | --- |
| **소비자 쇼룸 피드** | **게시물마다 높이가 다르다**(1.91:1 ~ 4:5 사이 임의 값) → **고정 높이 카드로 구현하면 안 되고, 서버가 게시물별 비율값을 함께 내려줘야 한다** |
| 스튜디오 목록 격자 · 쇼룸 격자 | **균일 4:5 센터 크롭** — 관리 목록에서 카드 높이가 제각각이면 훑어보기 어렵다 |

**사진 넘기기**

| 항목 | 규칙 |
| --- | --- |
| 화살표 | **마우스를 올렸을 때만** 노출 — 격자에 상시 떠 있으면 시선이 분산된다 |
| 경계 | 첫 장·마지막 장에서는 해당 방향 화살표를 숨긴다. 1장이면 화살표 없음 |
| 인디케이터 | **현재 / 총 장수 카운터.** 점 인디케이터는 장수가 많을 때 셀 수 없어 폐기 |

### 24-3. 작성·수정 — `FE`·`BE`

| 필드 | 필수 | 규칙 |
| --- | --- | --- |
| 사진 | **게시 시 최소 1장 필수** | 24-2 |
| 본문 | **선택** | 2,000자 |
| 제목 | — | **없다** |

**본문을 선택으로 두는 이유** — 사진만 있는 게시물을 허용한다. 인스타의 캡션 없는 게시물과 같다.

| 버튼 | 활성 조건 |
| --- | --- |
| **임시저장** | 사진 1장 **또는** 본문 1자 이상 — 무엇이든 남길 게 있어야 저장이 성립한다 |
| **게시하기** | **사진 최소 1장** |

두 조건 모두 **에러 문구 없이 비활성만**으로 표현한다.

**게시 후 수정**

| 항목 | 규칙 |
| --- | --- |
| 수정 | **제한 없음**(공구 게시물의 노출중 잠금과 다르다) |
| 팔로워 알림 | **재발송하지 않는다** |
| 내리기 | **삭제만 가능** · 되돌릴 수 없음 · 좋아요 수도 함께 사라짐을 모달에 고지 |

### 24-4. 업로드 실패 처리 — `FE`

| 항목 | 규칙 |
| --- | --- |
| 실패 파일 | **그리드에 칸으로 남긴다** — 칸 안에 **파일명 + 사유**(용량 초과 / 미지원 형식)를 적는다 |
| 장수 집계 | **포함하지 않는다**(`2 / 20`). 저장·게시 대상도 아니다 |
| **전 액션 잠금** | 오류가 떠 있는 동안 **`+` · 임시저장 · 게시하기를 모두 잠근다** |
| 해제 경로 | **실패 칸의 `✕`로 그 파일을 제외하는 것 하나뿐** |

**칸으로 남기는 이유** — 문구로만 알리면 **여러 장을 한꺼번에 올렸을 때 무엇을 다시 골라야 하는지** 알 수 없다.

**전부 잠그는 이유** — 문구를 못 보고 그대로 게시해 버리는 일을 막는다. **확인하지 않고 빠져나갈 길은 두지 않되**, 어디를 눌러야 할지는 칸 위에 그대로 보인다.

> **에러 문구 범위** — 사진·본문 미입력은 **버튼 비활성만**. 에러 문구는 **파일 형식·용량 오류에만** 쓴다.
> 

### 24-5. 운영자 조치 — 노출 중지 · 이의 신청 — `FE`·`BE`

신고·규정 위반 게시물은 **즉시 노출 중지**되고 **이의 신청 기간**이 함께 시작된다. 이 기간이 결과를 가른다.

| 경로 | 결과 |
| --- | --- |
| 기간 내 신청 → **승인** | **재게시** — 좋아요·인사이트 유지 |
| 기간 내 신청 → **반려** | **영구 삭제** |
| 기간 내 **미신청** | **영구 삭제** |

| 항목 | 규칙 |
| --- | --- |
| **조치 시 고지** | **사유 · 근거 규정 · 조치 시각 · 처리자 · 기한**을 화면에 남기고 알림을 보낸다 — **알리지 않고 사라지는 경우는 없다** |
| 중지 중 수정 | **불가** — **심사 대상이 도중에 바뀌면 안 된다** |
| 액션 | **`이의 신청` 하나로 통일** |
| 신청 횟수 | 게시물당 **1회** |
| 좋아요·인사이트 | 중지 기간에도 **보존**, 재게시 시 복원 |
| 심사 중 | **액션 없음** — 상태와 예상 소요만 표시. 대기는 **정보색**(원칙 ①)이나 카드 배지는 **여전히 노출 중지**(사실이 바뀐 게 아니다) |

**`소명하기`·`수정 후 재검토 요청` 2안을 폐기한 이유** — **반려 시 영구 삭제이므로 "고쳐서 다시"라는 경로가 성립하지 않는다.**

**중지 중 본인 삭제 — 허용한다**

| 시점 | 삭제 |
| --- | --- |
| 노출 중지 | **가능** |
| **심사 중** | **불가** — 신청 후 도중에 지우면 처리 결과가 붕 뜬다 |

다투고 싶지 않은 인플루언서에게 **출구**가 필요하다. 기한을 기다려 자동 삭제되는 것을 보고만 있게 하면 **자기 콘텐츠에 대한 통제권을 빼앗는 셈**이다. "증거 인멸" 우려는 성립하지 않는다 — 삭제해도 서버 비공개 보관 + 알림 이력이 영구 보존된다. 단 확인 모달에 **"삭제하면 이의를 신청할 수 없고 되돌릴 수 없습니다"**를 명시한다.

### 24-6. 영구 삭제의 정의 — `BE`

**"영구 삭제"는 인플루언서 기준의 삭제다.** 목록·쇼룸·인사이트에서 사라지고 본인도 복구할 수 없으며 별도 화면을 두지 않는다.

**다만 즉시 완전 삭제(hard delete)하지 않는다.** 서버는 누구에게도 노출되지 않는 **비공개 상태로 N개월 보관**한 뒤 파기하고, 그동안은 **운영자 콘솔에서만** 조회된다.

| # | 보관하는 이유 |
| --- | --- |
| ① | 플랫폼이 내린 삭제 판단의 **정당성 입증 자료**가 남아야 한다 |
| ② | 표시광고·명예훼손·저작권 건은 사후 **수사·행정기관 자료 요청**이 들어온다 |
| ③ | 공구와 이어진 게시물은 **전자상거래법상 기록 보존 대상**과 겹칠 수 있다 |

| 항목 | 규칙 |
| --- | --- |
| 삭제 이력 | 삭제 사실·사유·심사 이력은 **알림 이력에 영구 보존**한다 |
| **유예 기간** | 반려 통지 후 곧바로 지우지 않고 유예를 둔다. 그동안은 내려간 상태로 남기고 **본인만 사진 원본을 내려받을 수 있게** 한다 — 인플루언서가 자기 콘텐츠 원본을 잃는 상황이 분쟁으로 이어진다 |

> **⚠️ 약관 근거 조항 필수** — 위 보관은 **이용약관에 근거가 있어야** 가능하다. **"위반으로 삭제된 게시물은 일정 기간 비공개로 보관될 수 있다"**를 명시하지 않으면 보관 자체가 문제가 된다. **인플루언서 약관 초안에 반드시 반영해야 한다**(24-8 미결 1번).
>

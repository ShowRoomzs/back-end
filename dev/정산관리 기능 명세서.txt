### 41-2. 흐름 · 상태 5종 — `FE`·`BE`

```
공구 종료 → 주문 전부 종결(공구 관리) → 정산 생성 · 금액 공개
  → [정산 확인 중] 3영업일
       ├─ 요청 없음 → 마감 다음 날 00:00 자동 확정 → [지급 예정] → PG 3자 분배 → [지급 완료]
       │                                                              └─ 한쪽 몫 반환 → [분배 실패] (어드민 전용)
       └─ 정산 조정 요청 → [조정 협의] 전액 보류 · 이슈 스레드(§42)
              ├─ 합의 → 합의 금액으로 확정 → [지급 예정]
              └─ 합의 기한 경과 → 원래 금액으로 확정 → [지급 예정]
```

| 상태 | 색 | 의미 | 노출 |
| --- | --- | --- | --- |
| **정산 확인 중** | 정보 | 확정 금액이 양측에 공개됐고 조정 요청 창이 열려 있다 — 조치가 필수는 아니다 | 3서피스 |
| **조정 협의** | **경고** | 조정 요청으로 **전액 보류** · 금액이 바뀔 수 있고 합의 기한이 흐른다 | 3서피스 |
| **지급 예정** | 중립 | 확정 · PG 분배 대기 — 조치할 것 없는 대기 | 3서피스 |
| **지급 완료** | 성공 | 분배 완료 | 3서피스 |
| **분배 실패** | **위험** | 한쪽 몫만 PG에서 반환 — 금액은 맞고 **전달만 실패** | **어드민 전용** |

| 항목 | 규칙 |
| --- | --- |
| **폐기된 상태** | 정산 대기 · 확정 대기 · 정산 확정 · 정산 보류 — 화면·이력·약관 인용에서 함께 걷어낸다 |
| 「예정」 금액 | **존재하지 않는다.** 정산은 금액이 확정된 뒤에만 생기므로 회색·예정 배지를 쓰지 않는다 — 「지급 예정」의 예정은 **날짜**다 |
| 위험색 | **분배 실패 하나뿐**이다. 보류는 금액이 바뀔 수 있는 상태(경고), 실패는 금액은 맞고 전달만 실패한 상태(위험)다 |
| 조정 협의와 운영자 배지 | 경고색이지만 **다음 차례가 당사자**라 어드민 GNB 배지에 세지 않는다 |
| 공구 상태와의 관계 | 정산이 **지급 완료**가 되면 공구는 **정산완료**(§29-2)다. 「이체 완료」 표현은 쓰지 않는다 — 운영자가 이체하지 않는다 |
| 정산 단위 | **공구 1건 = 정산 1건** · 정산번호 `STL-YYMM-NNN`(체계 임의 · §46 C-12) — 날짜형 회차·「정기 정산」 표현을 쓰지 않는다(A-30) |

### 41-3. 정산 확인 기간 — 확정 금액을 보고 판단한다 — `FE`·`BE`

| 항목 | 규칙 | 근거 |
| --- | --- | --- |
| 시작 | **정산 생성 = 공구의 마지막 주문 항목 종결** — 그 시점에 금액을 양측에 공개한다 | 07a L2 · 07b D2 |
| 길이 | **3영업일**(주말·공휴일 제외) · 마감 = 3영업일째 **23:59** | `[근거 대기 · 운영정책 위임]` |
| 기산 | 생성 **다음 영업일**부터 세는 것으로 본다 `[확인 필요]` — 시안 예시 날짜가 서로 다르다(§46 D-23) | §46 B-3 |
| 자동 확정 | 마감 **다음 날 00:00** · 처리 주체 = **시스템** · 이력 「자동 확정 · 확인 기간 경과 · 조정 요청 없음」 | 07b D3 · D7 |
| **간주 규칙 없음** | 요청이 없다는 것 **자체가 결과**다. 「무응답 = 이행」 같은 간주를 두지 않는다 — §33-3 D-1 해소 | 13 D2 · 12 D1 |
| 공개 범위 | 금액 분해 = **확정값**(예정 표시 없음) · 3자 분배 · 지급 정보 · 증빙은 **「확정 후 표시」** · 정산 명세 다운로드 **비활성** | 13 D2 · 07b D2 |
| 요청 버튼 | 파트너 D2 · 스튜디오 D1의 **`[정산 조정 요청]`** — 이 상태에서만 활성 · 마감이 지나면 **비활성**(에러 문구 없음) | §42-1 |
| **입구는 정산 관리 하나** | 공구 관리 종료 화면에 「정산 확인」 카드·조정 요청 버튼을 두지 않는다 — 공구 관리는 **주문 종결 대기(남은 N건)**와 정산 관리 링크까지다 | X-01 · §29-11 |
| 안내 문구 | 「{MM.DD} 23:59까지 금액을 확인하고 필요하면 정산 조정을 요청할 수 있습니다. 요청이 없으면 다음 날 자동 확정됩니다.」 — 어드민 기준 확정 문구(스튜디오는 해요체) | 13 D2 · 12 D1 |

**확인 기간이 주문 종결 뒤에 시작하는 이유** — 미확정 금액을 보고 조정을 요청하면 나중에 반품 결과로 금액이 또 바뀌어 **요청이 무의미해진다.** 확정 금액을 본 뒤에만 판단하게 한다. 공구 종료부터 주문 종결까지의 대기(교환이면 최대 「교환 처리 기간 + 7일」)는 **공구 관리의 「주문 종결 대기(남은 N건)」**가 보여준다.

### 41-4. 금액 산식 — 두 축 — `BE`

**브랜드 축** — 파트너센터 분해 · 어드민 분해 상단

| 순서 | 행 | 규칙 |
| --- | --- | --- |
| ① | 총 주문 금액 | 공구 결제 총액(상품 결제금액 기준) |
| ② | − 취소 차감 · 반품 차감 · 배송 예외 차감 | 건수 병기 |
| = | **확정 거래액** | 소계 — 리워드율이 곱해지는 기준 |
| ③ | − PG 결제 수수료 | **3.0% 잠정** `[자문대기-PG]` · PG가 결제금에서 **먼저** 차감 — 자금 흐름 순서대로 리워드보다 **위**에 둔다 |
| ④ | − 플랫폼 수수료 | **베타 0% · 정상 2%** — 0원이어도 **행을 지우지 않는다**(2%가 붙을 때 새 항목처럼 보이지 않게) |
| ⑤ | − 판매 리워드 | 확정 거래액 × 리워드율 · **상품 항목별** 계산 후 합산 |
| ⑥ | − 리워드 부가세 | **⑤ × 10% · 별도** — SHOWROOMZ 세금계산서 발행분 · 일반과세 브랜드는 매입세액 공제 |
| ⑦ | + 재발송비 | 교환·반려 재발송비 — **브랜드 수취액에만 가산** · 리워드 기준 판매금액에 넣지 않는다 |
| = | **브랜드 수취액** | 총계 |
| ⑧ | − 차감 반영 | 이전 정산 뒤 환불분(§41-7) — 있으면 **「이번 지급액」**을 따로 적는다 |

**인플루언서 축** — 스튜디오 분해 · 어드민 분해 하단

| 구분 | 산식 | 증빙 |
| --- | --- | --- |
| **비사업자** | 판매 리워드 − 차감 반영 − 원천징수 3.3%(소득세 3% + 지방소득세 0.3% · **차감 후 금액 기준**) = 실지급액 | 원천징수영수증(SHOWROOMZ 발행) |
| **사업자** | (판매 리워드 − 차감 반영) + 부가세 10% = 실지급액(세금계산서 합계) · 원천징수 없음 | SHOWROOMZ 앞 정발행 세금계산서 |

| 항목 | 규칙 |
| --- | --- |
| **검산** | 확정 거래액 = 브랜드 수취액 + 인플루언서 실지급 + 원천징수액 + 플랫폼 몫(리워드 부가세 · 플랫폼 수수료) + PG 수수료 — 사업자 건은 리워드 부가세가 인플루언서 실지급에 들어가 플랫폼 몫이 0이다. 재발송비·차감이 있는 회차는 그 금액을 더하고 빼서 맞춘다 |
| 세율·요율 | 3.3% · 10% · PG 3% · 플랫폼 2%는 **백엔드 변수** — 문구에 고정하지 않는다(플랫폼 종사자 세율 개정 가능성) |
| 원 단위 | 시안마다 다르다 — 리워드 부가세 **반올림**(07b D4) · 원천징수 **절사**(12 D3) · 조정 상한 **10원 미만 절사**(13 C1) → §46 B-2 |
| 소비자 결제 배송비 | 분해 표에 **최초 배송비 가산 행이 없다**(재발송비만 있다) — 정산체계 v1.1 §4 「브랜드 지급액에 전액 가산」과 대조 필요 → §46 B-6 |
| 반품·교환 배송비 | 주문 결제금과 **별도 결제** — 분해 · 명세의 정산 반영액에 **포함하지 않는다**(파트너 블록 §43-4) |
| **금액의 단일 소스** | **정산은 돈의 사실, 성과 관리는 해석**이다. 성과 관리의 수취 예정액 분해는 **같은 로직**을 쓰고 따로 계산하지 않는다 — 어긋나면 어느 쪽도 신뢰받지 못한다. 스튜디오 성과 관리의 「내 리워드」는 **세전**, 정산 실지급액은 **세후**라 숫자가 다르다(어긋난 게 아니라 기준이 다르다) |

### 41-5. 3자 분배 · 지급 — `BE`

| 항목 | 규칙 |
| --- | --- |
| **PG 직접 분배** | 소비자 결제금은 PG에서 **브랜드 · 인플루언서 · 플랫폼에게 각각 직접** 지급된다. 플랫폼이 대금을 보관했다 나눠주는 구조가 아니다 — 「돈이 안 들어왔다」는 문의에 **누구에게 물어야 하는지**가 이 사실로 갈린다 |

| 플랫폼 몫 | 비사업자 건 = **리워드 부가세**(플랫폼 신고·납부) · 사업자 건 = 0(부가세는 인플루언서에게 지급) · 플랫폼 수수료(베타 0) — **원천징수액은 플랫폼이 예수**해 신고·납부한다(어드민 「납세 대리로 보유」) |
| **지급 예정일** | **자동 확정일 + 3영업일**(공휴일 제외 — 예: 10.06 확정 → 10.09 한글날 제외 → 10.12) `[근거 대기 · PG 계약]` |
| 사업자 인플루언서 | 인플루언서 몫만 **세금계산서 확인일 + 3영업일** — 같은 회차의 브랜드 몫은 원래 날짜에 나간다. 그 밖에는 **브랜드·인플루언서 분배일이 같다** |
| 조정 협의 종결 후 | 합의 · 기한 만료로 확정되면 **지급 예정**으로 넘어간다 — 지급 예정일 산정 기준이 시안에 없다(「보류 해제 후 결정」) → §46 B-5 |
| 날짜 표기 | 지급 예정일 옆에 **계산 근거**(자동 확정일 + 3영업일 · 제외한 공휴일)를 함께 적는다 |
| **앞당기기 없음** | 지급일은 규칙으로 정해지고 **협상 대상이 아니다** — 지급 요청 · 앞당기기 버튼을 두지 않는다(어드민 포함) |
| 조정 협의 중 | **모든 몫 「보류 — 지급 정지」** — 합의 금액이 리워드와 브랜드 수취액을 **함께** 옮기므로 브랜드 몫을 먼저 내보내면 조정할 돈이 없다 · **차액 선지급 없음** |
| 정산 확인 중 | 3자 분배 · 지급 정보는 **「확정 후 표시」** — 일정과 계좌가 아직 정해지지 않았다 |
| 지급 정보 블록 | 입금 계좌(마스킹) · 예금주 · 「입금 계좌 변경은 기본정보 관리에서」 · 지급 예정일 · 실지급일 · **PG 거래 참조번호**(지급 시 부여 · 노출 범위 미정) |
| **분배 실패** | 한쪽 계좌가 막히면 **그 몫만 반환**되고 나머지는 정상 지급된다 — 어드민 전용 상태(§45-6). 수취자 화면은 그대로 **「지급 완료」**라 운영자가 먼저 알아야 한다 → 수취자 측 표시는 §46 A-4 |
| 지급 완료 시 | 원천징수영수증 자동 발급(비사업자) · 공구 정산완료 |

> ⚠️ **약관과 충돌** — 파트너 제21조①은 「마지막 구매확정 완료일로부터 **5영업일 이내** 지급」이다. 현 흐름은 종결 후 **확인 3영업일 + 지급 3영업일 = 6영업일 이상**이고 조정 협의 시 **최대 10영업일**이 더 붙는다. **결정 필요** — §46 A-1(X-04).

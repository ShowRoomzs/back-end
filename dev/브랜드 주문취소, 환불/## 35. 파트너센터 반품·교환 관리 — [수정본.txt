## 35. 파트너센터 반품·교환 관리 — [v0.38 신설 · v0.39 거절 보류 개정]

대상 화면: `ui-partner-11-claims.html` (**rev.1 · 거절 보류 개정본** — 2026.10.04 수령, 시안의 rev 표기는 미갱신), 상태 18종(목록 10 · 상세 모달 6 · 모달 2). GNB **#6 판매 관리** › 대탭 **반품·교환 관리**. 셸·토큰은 `ui-partner-10c`(rev.5)에서 이식. 근거 와이어 `wf-partner-05-판매관리` F4~F6. 주문 관리(§34)와 **같은 GNB의 다른 대탭**이며 송장 셀·엑셀 왕복·상세 모달 셸을 공유한다.

**범위 밖** — 신청 접수(소비자 앱 C10) · 환불 집행 · 재배송비 결제 링크(운영자) · 이의 중재(1:1 문의 · 운영자).

### 35-0. 성격 — 브랜드는 검수 판정까지만 — `FE`·`BE`

**이 화면에 없는 세 가지는 누락이 아니라 정책이다.**

| 없는 것 | 규칙 |
| --- | --- |
| **`승인`·`수락`·`신청 거절`** | 소비자 신청은 **브랜드 승인 없이 즉시 접수**(약관 파트너 제20조①). **모든 거절은 물건을 받아 검수한 뒤에만** 가능하다. 부당해 보이는 건도 회수는 진행되고 창구는 **`운영자 문의`**(소통 스레드)뿐이며 **회수를 중단할 권한이 브랜드에게 없다** |
| **회수 송장 입력** | 회수는 **소비자가 직접 발송**하고 택배사·송장번호도 **소비자가 입력**한다. 브랜드의 회수 접수·송장 등록·일괄 업로드는 **전부 삭제** |
| **금액 입력 · 환불 실행** | 브랜드는 **검수 판정까지만** 한다. **환불은 운영자 집행**(§34-0 설계 원리 — 돈의 방향은 이해당사자가 만지지 않는다) |

**단위** — **주문 항목(SKU)** · 접수번호 `CLM-NNNN` 1건 = 항목 1건 · 수량 부분 신청 가능(주문 수량 2 중 1).

**반품과 교환을 탭으로 나누지 않는다** — 접수 → 회수 → 검수까지 흐름이 같고 **검수 이후에만 갈라진다.** 나누면 같은 작업을 두 곳에서 하고 오늘 할 일이 쪼개진다. **「유형」 열 + 필터**로 구분하고 유형 배지는 **색 없이 텍스트만**.

### 35-1. 단계 · 결과 — `FE`·`BE`

**단계 6종 = 탭**

| 단계 | 진입 | 주체 | 브랜드 액션 |
| --- | --- | --- | --- |
| **회수 대기** | 소비자 신청(**자동 수락**) | 소비자 | 없음 — 기본 진입 탭 |
| 회수 중 | **소비자가 회수 송장 입력** | 소비자 | 없음 — 추적 자동 갱신 |
| **입고·검수** | 추적상 브랜드 도착 | 시스템 | **`입고 확인` → `검수`** |
| **재발송** | 교환 검수 통과 / 거절 후 소비자 재배송비 결제 | 브랜드 / 소비자 | **송장 등록** |
| 거절 보류 | 검수 거절 | 브랜드 | 없음 — 소비자 결제 대기 |
| 완료 | 종결 | 운영자 / 시스템 | 없음 — 조회 전용 |

**결과 3종 — 완료일 때만**

| 결과 | 경로 | 색 |
| --- | --- | --- |
| 환불 완료 | 반품 통과 → **운영자 환불 집행** | 중립 |
| 교환 완료 | 교환 통과 → 재발송 → **도착** | 중립 |
| 거절 종결 | 거절 → 반송 완료 / **보관 기간 만료 후 폐기** | **중립** — 부정 결과지만 절차가 끝난 종결(원칙 ②) |

| 항목 | 규칙 |
| --- | --- |
| **단계와 결과는 다른 축** | 결과는 완료 단계의 하위 값. **재발송 사유는 판정 결과에서 파생**한다(따로 저장하지 않는다) |
| 입고·검수의 하위 상태 | `입고 확인 전` / `검수 대기` — 관리 열 버튼이 이 값으로 **교체**된다(동시 노출 금지) |
| 「지연」 | **저장 상태가 아니라 계산값**(§35-6) |
| 탭 | 전체 · **회수 대기**(기본) · 회수 중 · 입고·검수 · 재발송 · 거절 보류 · 완료 — 7개 |

### 35-2. 화면 공통 — KPI · 조회 조건 · 컬럼 — `FE`

**KPI 4칸** — 회수 대기 · 입고·검수 · 재발송 · **지연**. **「지연」만 경고색**이고 나머지는 중립 — 정상 작업 큐를 전부 경고로 칠하면 무엇이 급한지 사라진다. 빈 상태에서는 전부 0 · 경고 톤 해제.

**조회 조건** — 유형(반품/교환 체크 · 건수 병기) · 사유(전체 + 5종) · 기간(오늘 · 7일 · **1개월 기본** · 3개월 · 직접 입력) · 검색(`접수번호 · 주문번호`).

**컬럼**

| 탭 | 컬럼 | 기본 정렬 |
| --- | --- | --- |
| 회수 대기 | 접수번호 · 유형 · 소비자 · 상품·옵션 · 수량 · **사유** · **경과** | 신청일시 오래된순 |
| 회수 중 | … · 회수 택배사 · 회수 송장 · **최근 추적** · 경과 | 오래된순 |
| 입고·검수 | … · 사유(+증빙 N장) · **입고 확인** · **검수 경과** · 관리 | 도착 오래된순 |
| 재발송 | 접수번호 · 유형 · 소비자 · **보낼 상품·옵션** · 수량 · **재발송 사유** · 택배사(편집) · 송장번호(편집) · 경과 · 관리 | 확정 오래된순 |
| 거절 보류 | … · **보관 중인 상품** · 수량 · 거절 사유(+증빙 N장) · 거절일시 · **고지 · 보관 기한**(`2회 고지` + `보관 ~ 11.23 · 최종 고지 08.23`) | 거절 오래된순 |
| 완료 | … · 사유 · **결과** · **금액** · 종결일시 | 최신순 |
| 전체 | … · 사유 · 신청일시 · 경과 · **단계** | 최신순 |

| 규칙 | 내용 |
| --- | --- |
| **단계 열 = 전체 탭만** | 단일 단계 탭에서는 정보가 0. 전체 탭 **단계 배지는 전부 중립**(진행 순서일 뿐) · 기한 초과만 경과 열 경고색 |
| 전체 탭 | **관리 열 없음** — 단계마다 다음 행동이 달라 한 열로 표현할 수 없다 |
| 교환 표기 | 상품·옵션에 `50ml → 리필` |
| **회수 그룹** | 같은 박스로 오는 항목을 **그룹 1행**(`CLM-3021 외 2건`) + ▼/▶ 토글 · **기본 닫힘** · 펼치면 항목별 행. **표시 단위일 뿐 처리 단위가 아니다** — 검수·거절은 항목마다 |
| **행 확장(전체 탭)** | ▸로 **원 주문의 항목 전체** — 주문 항목 · 주문 수량 · **신청 수량** · 공구가 · 항목 상태. 신청분과 살아 있는 분이 갈려야 **멀쩡한 항목을 회수·환불하는 사고**를 막는다 |
| 빈 상태 | 「신청이 없다」는 좋은 상태라 **중립 톤** · CTA는 `주문 관리로 이동` |
| 검색 결과 없음 | 조건·탭 유지 · 결과 영역만 교체 · KPI·탭 카운트 유지 |

### 35-5. 검수 판정 — `FE`·`BE`

|  | 반품 | 교환 |
| --- | --- | --- |
| 통과 | `검수 통과` → **운영자 환불 집행** | `검수 통과 · 재발송 처리` → 재발송 탭(새 옵션 출고) |
| 거절 | `검수 거절` → 거절 보류 | `검수 거절` → **교환 취소** → 거절 보류(반송 대상은 **회수한 원래 상품**) |
| 사유 번복 | — | **없음** ⚠️ §35-9 A-1 |

| 항목 | 규칙 |
| --- | --- |
| 순서 | 목록 `입고 확인` → `검수` → **상세 모달에서 판정** |
| 상세 구성 | 신청 정보(접수번호 · 유형 · 소비자 **연락처 마스킹** · 상품·옵션 · 교환 옵션 · 수량 · 사유 · 교환비 청구 여부 · 상세 내용 · 신청일시 · 회수 송장 · 입고 확인 · **검수 기한**) · 환불 예정액(반품) · 소비자 첨부 · 우 레일(판정 · 처리 이력) |
| 환불 예정액 | 금액 + 산정 근거(`불량이라 반품비 차감 없음` / `상품 − 반품비`) — **표시만.** 브랜드는 금액을 입력·수정하지 않는다 |
| 교환 조건 | **같은 상품의 다른 옵션 맞교환 · 차액 없음**(거래플로우 교환 규칙) |

**거절 폼 — 우 레일 인라인 확장(모달 위 모달 금지)**

| 필드 | 규칙 |
| --- | --- |
| 거절 사유 * | 개봉·사용 흔적 / 포장 훼손 / 상품 불일치 / 기간 경과 / 기타 |
| 상세 설명 * | 자유 입력 |
| 증빙 사진 * | PNG · JPG · **10MB 이하** |
| 미입력 | **에러 문구 없이 `거절 제출` 비활성** |
| 버튼 | **위험색** — 이 화면에서 위험색은 여기에만 쓴다 |
| **확정** | **제출 = 즉시 확정**(운영자 사전 심사 없음 — 거래플로우 v1.3 쟁점 H 해소) |
| 전달 | 사유·설명·증빙이 **소비자에게 그대로 전달**(약관 제20조③) |

**세 필드가 모두 필수인 이유** — 즉시 확정되고 그대로 전달되므로 **근거 없이 거절할 수 없게 폼이 막는다.**

### 35-7. 재발송 — `FE`·`BE`

**주문 관리 상품준비중(§34-5)과 같은 송장 등록 패턴** — 셀 입력 → `N건 송장 등록` 확정 · 형식·중복 하드 차단 · 빈 값 조용히 제외 · 택배사 11종 목록.

| 재발송 사유 | 대상 | **보낼 물건** |

| 교환 재발송 도착 | **배송완료 복귀 · 구매확정 7일 재시작** · **정산 금액 불변** |

| 기준의 출처 | 시안 규칙 박스 — **「올리브영 기준을 따른다」**. 원문 조항 대조는 미완(§35-9 C-17) |
| **정산과 무관** | 거절 확정 = 즉시 구매확정(§29-11)이므로 **보관 3개월이 정산을 묶지 않는다** |

| 완료 | **조회 전용** · 결과 열(환불 완료 / 교환 완료 / 거절 종결) · 금액은 **운영자가 집행한 결과** |

| 소비자 이의 | **1:1 문의 → 운영자 중재** |

### 35-9. 확정 필요 · 미결 — `[대표 확정]`

#### A. 구조 확정

| # | 항목 | 상태 |

| 1 | **교환 검수 「사유 번복」 폐기 ↔ 약관 제20조②** — 약관은 교환 검수를 **통과 / 사유 번복(단순 변심으로 재분류) / 거절** 3판정으로 규정하고 거래플로우 v1.3은 **「교환비 결제대기」** 상태를 둔다. 시안은 **2판정**. 시안대로면 **약관 개정 + 거래플로우 상태 삭제**, 약관대로면 **판정 추가**. 폐기 시 「불량 신청이지만 실제는 단순 변심」인 건은 **무료 교환(브랜드 부담) 또는 거절**뿐이다. 약관 제25조② 제재표의 「사유 번복」 문구도 동반 정리 | ⬜ **대표 확정** · `[약관수정필요]` 후보 |

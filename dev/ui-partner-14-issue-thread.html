GNB #3 연결·소통 · 셸 = ui-partner-05-connections · 반대편 = ui-admin-20b-issues(2026.10.06 전면 개정) · 개설 계기 = 공구 관리 정산 확인의 [정산 조정 요청] · 결과 반영 = 정산 관리 보류 탭

[2026.10.07 · 근거 첨부 삭제] 조정 요청·다른 금액 제안 카드에서 「근거」 행을 뺐다. 요청 입력은 금액 · 사유뿐이고, 근거 자료는 카드 바로 아래 요청자의 일반 말풍선(사진·파일 첨부)으로 올린다 — 파일 올리는 곳이 한 군데여야 무엇이 근거인지 흐려지지 않는다. 운영팀은 열람만 하므로 근거를 받아 판정하는 절차가 없다.
[rev.5 · 양측 직접 합의 모델 · 2026.10.06]
  · 입구는 「정산 조정 요청」 — 종료 후 정산 확인 기간에 한쪽이 조정할 리워드 금액 · 사유(필수)를 내면 정산이 전액 보류되고 시스템이 스레드를 연다. 「이행 확인 · 미이행」은 폐기 — 미이행은 계약 위반 판정이라 협의 전에 감정을 상하게 하고 금액은 따로 정해야 했다. 요청이 없으면 원래 금액으로 정산한다.
  · 응답 3가지 — 동의 · 다른 금액 제안 · 반대. 다른 금액 제안은 새 요청이 되어 처음 요청한 쪽이 답한다. 반대는 사유 없이 등록하고 의견은 대화로 남긴다. 반대해도 협의는 합의 기한까지 이어진다.
  · 동의 = 금액 변경 + 보류 해제 + 종결(시스템 · 동시 · 운영자 승인 없음).
  · 합의 기한 = 개설 + 10영업일(주말·공휴일 제외) — 몇 번을 주고받아도 늘어나지 않고, 합의가 없으면 원래 계약 금액으로 확정·종결(D-1 통지). 「무응답 = 동의 간주」는 없다.
  · 금액 범위(리워드 0 이상 · 브랜드 수취액 이내)를 벗어나면 에러 문구 없이 버튼 비활성.
  · 운영자는 열람만 — 조정안 제시 · 답변 기한 설정이 없고, 금액을 정하는 주체는 당사자뿐이다. 운영팀 말풍선도 이 스레드에는 두지 않았다.
[절차는 시스템 카드, 대화는 말풍선] 조정 요청 · 다른 금액 제안 · 반대 · 기한 통지 · 종결 결과는 카드로 고정한다. 버튼은 가장 최근 요청 카드에만 있고 이전 카드는 응답 결과로 굳는다.
[고정 카드] 공구 · 보류 금액 · 요청 금액 · 합의 기한(D-N).
[상태색] 내 응답 필요=경고 · 상대 응답 대기=정보 · 합의 완료=성공 · 기한 만료=중립.
[약관수정필요] 인플 제20조(이행 확인 · 미이행 · 중재 의견)와 파트너 대응 조항을 정산 확인 · 정산 조정 요청 · 양측 합의 · 합의 기한 경과 시 원래 금액 확정으로 개정.
[근거 대기] 정산 확인 기간(종료 후 3일).

## 21. 어드민 약관 및 정책 관리 — [v0.29 신설]

대상 화면: `ui-admin-10-terms.html` (**rev.2**), 상태 7종(목록 1 · 페이지 4 · 모달 2). 셸·테이블·모달·배지는 §16 컴포넌트를 재사용했다.

> **[v0.29] 메뉴 위치 이동** — `8. CS·콘텐츠 관리` → **`10. 설정 > 약관·정책 관리`**. 약관은 소비자 문의 대응 콘텐츠가 아니라 **서비스 운영 규정**이라 수수료·정책과 같은 층이 맞다. 결과적으로 **CS·콘텐츠 관리 하위는 4개**(1:1 문의 · 상품 문의 모니터링 · FAQ 관리 · 공지 관리), **설정 하위는 3개**(운영자 계정 · 수수료·정책 · 약관·정책 관리)가 된다. §17-7·§19-7 기술을 갱신했다.
> 

**성격 — 앞선 정적 콘텐츠 화면과 결정적으로 다르다.**

| 구분 | §19 FAQ | §20 공지 | §21 약관 |
| --- | --- | --- | --- |
| 원문 수정 | 가능 | 가능 | **불가** |
| 내리기 | 삭제(복구 불가) | 게시 종료(복구 가능) | **불가 — 새 버전으로 대체만** |
| 이력 | 없음 | 없음 | **영구 보관** |

**원문을 수정할 수 없는 이유** — 동의 기록이 **"동의한 버전"을 참조**한다. 원문이 바뀌면 누가 무엇에 동의했는지가 무너진다. 개정은 오직 **새 버전 등록**으로만 이뤄지고, 과거 버전은 조회 전용으로 **영구 보관**된다.

### 21-1. 상태 정의 — 3종 — `FE`·`BE`

| 상태 | 의미 | 배지 색 |
| --- | --- | --- |
| 시행중 | 현재 적용되는 버전 | **성공** |
| 시행 예정 | 등록됐으나 시행일 전 — **소비자 화면에 노출되지 않음** | **정보** |
| 구버전 | 후속 **문서**로 대체돼 더는 시행되지 않는 문서 | **중립**(원칙 ②) |

**용어 2단 — 층이 다르다**

| 층 | 용어 | 의미 |
| --- | --- | --- |
| 문서 목록 | **구버전** | 후속 **문서**로 대체된 문서 전체 |
| 버전 이력 | **과거 버전** | 같은 문서 안에서 교체된 지난 **버전** |

색은 둘 다 중립이지만 **대상이 다르므로 용어를 섞지 않는다.**

### 21-2. 문서 구조 — `FE`·`BE`

| 항목 | 규칙 |
| --- | --- |
| 문서 : 버전 | **1 : N** — 문서 1건이 여러 버전을 갖는다 |
| **유형** | 이용 약관 / 개인정보처리방침 / 마케팅 동의 — **등록 후 고정** |
| **대상** | 전체 / 소비자 / 브랜드 / 인플루언서 — **등록 후 고정** |
| 문서 범위 | 현재 **8종**(이용 약관 3 · 개인정보처리방침 2 · 마케팅 목적 개인정보 수집·이용 동의 3) |
| 운영정책 편입 | **미정** — 21-6 미결 3번 |

**유형·대상을 고정하는 이유** — **대상이 바뀌면 동의 대상 집단이 달라진다.** 같은 문서로 볼 수 없으므로 문서를 새로 만들어야 한다. 등록 화면에 이 경고를 명시한다.

> 마케팅 동의는 **대상별로 문서를 따로 둔다**(소비자·브랜드·인플루언서 3건). 동의 시점·범위가 각각 다르기 때문이다.
>

**컬럼 6종**

| 컬럼 | 정렬 | 비고 |

| 문서명 | 좌 |  |
| 대상 | 좌 | 전체 / 소비자 / 브랜드 / 인플루언서 |
| 버전 | 좌 | 고정폭 숫자 |
| 상태 | 가운데 | 시행중 / 시행 예정 / 구버전 |
| 시행일 | 가운데 | 고정폭 숫자 |
| **관리** | 가운데 | `새 버전 등록` — **구버전 행은 비운다**(`—`) |

| 항목 | 규칙 |
| --- | --- |
| **문서 1건 = 1행** | 표시 버전은 **현재 시행중(또는 시행 예정) 1개**만. 과거 버전은 문서 상세의 이력에서 본다 |
| **상세 진입** | **행 클릭.** 관리 열에 `[상세]` 버튼을 두지 않는다 — 디자인시스템 규칙("행 클릭으로 상세 이동, 별도 상세 버튼 금지")과 충돌한다 |
| 구버전 행 | 새 버전을 붙일 대상이 아니므로 **조회만** 가능하다 |
| 툴바 좌측 | `총 N건 · 시행 예정 N건 · 구버전 N건` |
| 검색 | `문서명` 단일 입력 |

**의도적으로 두지 않는 것** — 대상·상태 셀렉트(문서가 10건 안팎이라 **유형 탭 + 문서명 검색**으로 충분하고 대상은 목록 열에서 바로 읽힌다) · 버전 전체 나열(8종이 20행 넘게 늘어난다) · CSV 내보내기.

**와이어 대비 개편** — 카드 나열 + 하단 이력 → **문서 목록(표) + 문서 상세**. 문서가 늘어나면 카드 나열은 세로로 무한히 길어지고 **검색·필터를 붙일 자리가 없다.**

### 21-5. 등록 — 신규 문서 vs 새 버전 — `FE`·`BE`

**두 화면은 분리한다.** 잠금 분기가 화면 전체에 퍼지는 것을 막기 위해서다.

| 항목 | 문서 등록(신규) | 새 버전 등록(개정) |
| --- | --- | --- |
| 진입 | 목록 `＋ 문서 등록` | 문서 상세·목록 행 `새 버전 등록` |
| 문서명·유형·대상 | **입력**(이후 고정) | **고정 표시** |
| 버전 번호 | **v1.0 자동 부여** — 입력받지 않는다 | **입력** |
| 교체 대상 | 없음 | **현재 시행 버전 카드 표시** + 과거 버전 전환 안내 |
| 시행일 · 본문 | 입력(필수) | 입력(필수) |
| 등록 후 상태 | **시행 예정** | **시행 예정** |

**입력 규칙**

| 항목 | 규칙 |
| --- | --- |
| 버전 번호 | **접두 `v`는 필드 밖 고정** · 숫자와 점만 · 공백 입력 차단. **서버에서 중복·역행 번호를 검증**한다 |
| 시행일 | **오늘 이후만** 선택 가능 · 읽기 전용 인풋 + **달력 모달** |
| 본문 | 원문 전체를 붙여 넣는다. **등록 후 수정 불가**를 화면에 명시 |
| 필수 미입력 | 에러 문구 없이 **등록 버튼 비활성만** |
| 확인 모달 | **필수** — 유형 · 새 버전 · 시행일 · **교체 대상**을 요약. 파괴적이지 않으므로 **주 액션(파랑)** |

**첫 버전을 v1.0으로 고정하는 이유** — 최초 등록에 버전을 고르게 하면 `v0.9` 같은 값이 들어온다.

**접두 `v`를 필드 밖에 두는 이유** — 사용자가 `v3.2`·`V3.2`·`3.2`를 섞어 입력하는 것을 막는다.

**시행일을 오늘 이후로 제한하는 이유** — 과거 시행일은 **이미 시행됐어야 할 문서를 뒤늦게 등록하는 셈**이라 동의 기록과 어긋난다.

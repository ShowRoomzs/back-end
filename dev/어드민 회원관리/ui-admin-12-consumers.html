소비자 회원 목록 · 근거: SHOWROOMZ_웹_디자인시스템_v1_2.html · 셸·테이블·배지는 ui-admin-05-change-requests.html rev.6 재사용 · 소비자 상세는 별도 화면

[컬럼 9종 · 신규 5종] 회원번호 · 이름 · 휴대폰 · 누적 주문을 새로 넣었다. 회원번호는 상세 URL에만 있어 CS 대응 시 목록에서 찾을 수 없던 문제를 해결한다 — 첫 열에 두고 등폭 숫자로 표기해 문의받은 번호를 눈으로 대조한다.
[마스킹 원칙] 이름은 가운데 1자, 휴대폰은 가운데 4자리를 가린다 — 목록은 훑어보는 화면이고 전체 값이 필요한 순간은 CS 대응 1건 단위이므로 상세에서만 해제한다. 마스킹 상태로도 CS 확인이 가능한 이유는 휴대폰 뒤 4자리가 남기 때문이다(검색도 뒤 4자리 기준).
[미결 · 마스킹 해제] 상세에서 전체 값을 볼 때 해제 버튼 + 조회 로그를 둘지, 처음부터 전체를 보일지 미정 — 개인정보 보호법상 접근 기록 의무와 맞물리므로 법률 자문 대기다.
[상태 색 매핑] 활성=성공 / 정지=위험(운영자 조치 · 원칙 ①) / 탈퇴=중립(원칙 ② 해지). 정지·탈퇴 처리일은 목록에 두지 않고 상세에서 본다 — 배지 아래 날짜를 붙이면 그 행만 2줄이 되어 행높이가 들쭉날쭉해지고, 50px 균일 행이 훑어보기의 전제이기 때문이다. 처리일이 목록에서 필요해지면 배지 아래가 아니라 별도 열로 넣는다(정지 탭 전용 열도 가능).
[가입 수단] 4종(카카오 · 네이버 · Apple · Google)은 상태가 아니라 속성이라 배지를 쓰지 않고 색점 + 이름으로 표기한다 — 상태색 체계를 침범하지 않기 위함이다. 색점은 각 사업자 식별색이며 어드민 액센트와 무관하다.
[누적 주문] 0건은 회색으로 낮춰 주문 이력 있는 회원이 먼저 눈에 들어오게 한다.
[확인 필요] ⓐ 누적 주문의 정의 — 취소·환불 건 포함 여부 미정(현재 시안은 결제 완료 기준 누적) ⓑ 탈퇴 회원의 개인정보 보관 기간과 목록 노출 기간 ⓒ 정지 사유를 목록 열로 노출할지(현재는 상세에서만) ⓓ 엑셀 내려받기에 마스킹 해제 값을 포함할지 — 포함한다면 권한·로그 규칙이 필요하다.
[규격 정합] 테이블 본문 셀 14px 20px · 행높이 50px(좌우 여백 20px 통일). 설계 근거는 이 박스와 .state-spec에만 둔다.

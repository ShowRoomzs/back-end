# 브랜드 공구관리 기능 테스트 상세

## 1. 범위와 판정 기준

- 대상: 파트너센터 공구관리 목록·상세·모달 34개 시안 상태(A 3, B 23, C 8), `/v1/seller/group-buys` API, 계약·쇼룸·어드민·판매·정산·스레드 연계.
- 기준 자료: [`ui-partner-09-groupbuys.html`](ui-partner-09-groupbuys.html) rev.4, [`공구관리 브랜드 기능명세서.txt`](공구관리 브랜드 기능명세서.txt) §30, [`공구관리 공통 기능명세서.txt`](../공구관리%20공통%20기능명세서.txt) §29. 백엔드 요청·응답과 에러 코드는 [`30_파트너센터_공구관리_BE_설계서.md`](30_파트너센터_공구관리_BE_설계서.md) §4를 대조한다.
- 시안 HTML은 **정적 상태 예시**다. 화면 테스트는 실제 파트너센터 FE가 연결된 환경에서 수행한다. HTML의 설명 문장은 테스트 요구사항의 근거로 사용하며, 실행 지시로 취급하지 않는다.
- 아래 케이스는 **테스트 명세**이며 통과 표시가 아니다. `현행 제약` 절에 적은 의존 기능은 실제 연결 후 목표 동작을 판정한다. 현재 스텁의 503·`null`을 목표 동작의 통과로 기록하지 않는다.
- 날짜·시각은 서버의 `Asia/Seoul` 기준으로 고정한다. 자동 전이는 스케줄러를 직접 실행하거나 테스트 시계를 고정해 재현한다. 시안의 2026년 날짜와 건수는 예시이므로 실제 고정 fixture 값과 비교한다.

### 공통 준비 데이터

| 데이터 | 구성 |
| --- | --- |

| 계약 | 체결 전 1건, 체결 완료 1건, 이미 공구가 연결된 계약 1건. 상품 2개·공구가 27,200/25,600원·리워드율 12/15%·최소 물량 300/200개·고정 지급비 300,000원인 계약을 기준 fixture로 둔다. |

| 게시물 | 미작성·작성중·승인대기·반려·승인·숨김·해제·종료 상태를 만든다. 게시물 상태는 공구 상태와 별도로 확인한다. |

### 공통 확인 방법

1. UI에서 보이는 상태·문구·버튼·색과 API 원값을 함께 기록한다. `GET /v1/seller/group-buys/{id}`의 `permissions`가 버튼 노출의 기준이다.
2. 성공 요청 후 목록·상세·요약을 다시 조회해 상태, 기한, 이력, 상대방 화면, 상품 구매 가능 여부가 함께 바뀌었는지 확인한다.
3. 실패 요청은 HTTP 상태와 `code`를 확인하고 DB에 요청·이력·스레드·첨부 등 부수 효과가 남지 않았는지 확인한다.
4. 시안에만 있는 문구와 백엔드 설계가 충돌하면 8절에 기록하고 임의로 통과시키지 않는다.

| GB-D19 | B5e 이슈 스레드 열림 | 종료 후 C5로 이슈 개설 | 열린 이슈의 유형·시각·스레드 이동 표시, `[이슈 스레드 열기]` 제거, 중복 개설 차단. 이슈만으로 정산 보류하지 않음. **스레드 포트 연결 후 목표 케이스**. |
| GB-D20 | B5d 조기 마감 종결 | 조기 마감 요청을 운영자가 승인 | 결과 상태는 `ENDED`, `closeType=EARLY_CLOSED`. 원래 예정 종료일·실제 종료 시각 병기, 접수 주문 배송·정산 유지, 재오픈 불가. |
| GB-D21 | B6 정산완료 | 주문 종결·이행 확인 후 정산 이체 완료 이벤트 | `SETTLED`, 확정 실적·지급 정보는 원장과 일치. 잠정 수치를 확정액으로 재사용하지 않음. 계약 조건은 그대로, 재오픈·추가 요청 불가. **판매·정산 연결 후 목표 케이스**. |
| GB-D22 | B7 요청 승인 중단 | 브랜드의 중단 요청을 운영자가 승인 | `SUSPENDED`, `closure.source=REQUEST`, 첫 정보는 브랜드 요청 사유. 게시물 종료·재개 불가, 이미 접수된 주문의 배송 의무와 고정 지급비 회수 불가 표시. |
| GB-D23 | B7a 운영자 직권 중단 | 사전통지 집행 또는 긴급 직권 중단 | `closure.source=ADMIN_NOTICE/ADMIN_EMERGENCY` 구분, 요청자 없음 명시. 운영자 근거 전문을 첫 정보로, 이의 제기 이슈 경로와 기존 주문 배송 의무 표시. **이슈 경로는 스레드 연결 후 실행**. |

## 4. 모달 8종·실행 API

모달 공통: 제목은 질문형, 왼쪽은 `[닫기]`, 필수값 미입력 시 에러 문구 대신 주 버튼 비활성. 닫기·X·Esc가 가능하면 서버 요청 없이 원래 상세로 돌아가야 한다. 여러 번 빠르게 클릭해도 요청은 1건만 남는다. 확인 직전 현재 상태가 바뀌면 서버가 거절하고 최신 상세를 다시 표시한다.

## 6. API 응답·오류 확인표

| 대상 | 반드시 확인할 값 |

**완료 판정:** 34개 시안 상태와 8개 모달이 실제 FE에서 재현되고, 성공/실패 API·권한·상태 전이·판매·정산·스레드 연계가 모두 기대 결과를 만족해야 한다. 기존 자동 테스트 통과만으로 화면·외부 포트의 완료를 선언하지 않는다.

## 8. 기획·시안 불일치 및 미결 판정

다음 항목은 테스트 실패와 분리해 기획 결정 또는 시안 정정으로 기록한다. 결정 전에는 한쪽을 임의로 합격 기준으로 삼지 않는다.

| 항목 | 확인할 충돌·미결 사항 |
| --- | --- |
| A1 비고 | 브랜드 기능명세는 7개 열과 독립 비고 열을 요구하지만 rev.4 HTML의 목록은 6개 열이고 일부 비고가 상태 배지 밑에 있다. |
| A2 생성 안내 | HTML에는 계약 상세에서 공구를 생성한다는 문구가 남아 있다. 공통 명세와 현재 백엔드는 **계약 체결 시 자동 생성**이다. |
| B4c/B4d/B4e/B4b/B4h 버튼 | 시안은 결과별 일부 요청 버튼을 숨기지만 백엔드 `permissions`는 원칙에 따라 더 넓게 허용한다. FE와 서버의 최종 버튼 조합을 확정해야 한다. |
| 모달 버튼 라벨 | 기능명세는 모달을 연 버튼과 확정 버튼의 문자 일치를 요구한다. C1·C2·C6·C7 등 시안의 실제 라벨은 서로 다른 곳이 있어 문구 기준을 확정해야 한다. |
| 운영 정책값 | 연장 총 30일·12시간 컷오프, 이행 확인 기한 3일, 소명 첨부 5개 등은 설계서의 설정 기본값 또는 근거 대기 항목이다. 테스트는 환경 설정값을 먼저 고정한다. |
| 겹치는 상품 | 같은 상품의 기간이 겹치는 공구를 계약에서 차단할지 미정이다. 상품 상태 동기화는 테스트하되 소비자 공구가 선택은 별도 결정이 필요하다. |

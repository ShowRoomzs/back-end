
## 39. 어드민 거래 관리 — 환불 관리 — [v0.42 신설]

대상 화면: `ui-admin-06c-refunds.html` (**rev.1**), 상태 5종(목록 3 · 다이얼로그 2). GNB **6 거래 관리 › 환불 관리** — 배지 = **집행 대기 + 실패**. §37 · §38의 **`환불 대기 편입`이 들어오는 곳**이다.

**범위 밖** — 환불 사유 판단·편입(§37-5 · §38-5) · 반품 검수(브랜드) · 소비자 입금 안내(소비자 앱).

### 39-0. 성격 — 환불은 자동이 기본 — `BE`

| 환불 경로 | 처리 | 이 화면 |
| --- | --- | --- |
| 결제완료 소비자 취소 · 취소 요청 승인(자동 승인 포함) · 브랜드 직권 취소 · **반품 검수 통과** · **반송 완료** | **PG 즉시 자동** | 완료 탭 **조회만** |
| **운영자 사유 환불** | **운영자 집행** | 집행 대기 → `집행` |
| **자동 환불 실패** | 시스템 1회 재시도 후 | 실패 → `재시도` |

**운영자가 손대는 것은 둘뿐**이라 탭이 셋이다 — 집행 대기 · 실패 · 완료.

### 39-1. 편입과 집행의 분리 — `FE`·`BE`

```
§37 상세(위해성 리콜 · 기타) ┐
                             ├─ [환불 대기 편입] ─▶ 집행 대기 ─ [집행] ─▶ 재확인 다이얼로그 ─▶ PG 취소
§38 상세(반려 이의 인용)     ┘     사유 · 근거 · 편입자
```

| 항목 | 규칙 |
| --- | --- |
| **사유 판단은 원 화면에서** | 주문·클레임의 근거를 읽고 판단한다 |
| **집행은 이 화면에서만** | 돈이 나가는 순간을 **한 화면 · 한 다이얼로그**로 모은다 |
| **2인 승인 없음** | 재확인 다이얼로그 1회 |
| **일괄 집행 없음** | 사유가 건마다 다르다 |
| 저장 | **편입자 · 편입 시각**과 **집행자 · 집행 시각**을 따로 |
| 편입 시 부수 효과 | 반려 이의 인용이면 **재발송비 결제 요청이 편입 시점에 취소**된다(집행 시점이 아니다) |

### 39-2. 목록 — `FE`

| 항목 | 규칙 |
| --- | --- |
| 탭 3종 | **집행 대기**(기본) · 실패 · 완료 |
| 경로 | 셀렉트 — 전체 / 취소 / 반품 / 반송 / 운영자 사유 |
| 검색 | 환불번호 · 주문번호 · PG 거래번호 |
| 요약 건수 | 건수 + **합계 금액** · 실패 탭은 **소비자 대기 N일** · 완료 탭은 기간 + 출처별 건수 |
| 정렬 · 건수 | 일시 최신순 · 환불액 높은순 / 20 · 50 |
| 컬럼 10종 | 환불번호(`RFD-`) · 주문번호 · **경로** · **출처** · 브랜드 · **결제** · 환불액 · 상태 · 일시 · 관리 |
| 경로 | 환불의 원인 — 반려 이의 인용 · CLM번호 / 취소 요청 자동 승인 / 반송 완료 / 위해성 리콜 / 반품 · 일부 반려 / 결제완료 소비자 취소 / 교환 재발송비 등 |
| **출처** | **PG 자동**(중립) / **운영자 사유**(경고 — 사람이 판단한 돈) |
| **결제** | 결제수단 + **원래 / 추가 / 원래 부분** |
| 관리 | 집행 대기 = `집행` · 실패 = `재시도` · 완료 = — (표 안 버튼 28px) |
| 색 | 집행 대기 = **경고** · 환불 실패 = **위험**(소비자 돈이 멈춘 부정 결과 — **위험색은 여기에만**) · 환불 완료 = 성공 |
| **완료 탭** | **PG 자동까지 전부 조회** — CS 1순위 「환불 언제 들어와요?」에 경로와 상관없이 답한다. 일시는 **PG 승인 시각**이고 카드사 입금 소요 안내는 소비자 앱 몫 |

### 39-3. 집행 재확인 다이얼로그 — `FE`·`BE`

**돈이 나가는 유일한 실행 버튼**이다(520px 확인 모달).

| 행 | 내용 |
| --- | --- |
| 환불번호 · 주문번호 | — |
| 사유 | 사유 · 클레임 번호 · **편입자 · 편입 시각** |
| 근거 | 편입 때 적은 값 그대로 |
| **취소 대상** | **결제 건별** — 원래 결제(결제수단 · PG 거래번호 · 금액 · 전액/부분) |
| 추가 결제 | 있으면 별 행 · 없으면 「없음 · 재발송비 결제 요청은 편입 시 취소됨」 |
| **정산** | 정산 전이면 「클로백 없음」 · **정산 확정 건이면 클로백(다음 정산 차감)** |
| 경고 | 「집행하면 **PG 취소가 즉시 요청**되고 되돌릴 수 없습니다. 소비자·브랜드에게 통지되며 이력에 집행자 · 시각이 남습니다.」 |
| 버튼 | `취소` · **`{금액}원 집행`** — **라벨에 금액** |

| 항목 | 규칙 |
| --- | --- |
| 금액 입력 | **없다** — 서버 계산값 |
| 중복 방지 | 연타·동시 클릭에도 PG 취소 요청은 **1회** |

### 39-4. 실패 · 재시도 — `FE`·`BE`

| 항목 | 규칙 |
| --- | --- |
| 진입 | PG 자동 환불 실패 → 시스템 **1회 자동 재시도**(시안 값) → 실패 탭 |
| 원인 | 결제수단이 카드·간편결제뿐이라 **PG 쪽뿐**(응답 오류 · 취소 가능 잔액 불일치) |
| 목록 문구 | **운영자 말**로(「PG 응답 오류 · 재시도 1회 실패」) · **코드는 다이얼로그에만** |
| 재시도 다이얼로그 | 환불번호 · 경로 · 취소 대상 · 실패(원인 · 코드 · 시각) · 자동 재시도 결과 |
| **값 변경 불가** | 「금액과 경로는 바꿀 수 없습니다 — 원래 요청을 그대로 다시 보냅니다」 |
| 반복 실패 | 수동 처리 경로 `[근거 대기 · PG 계약]` |

### 39-5. 결제 건별 취소 — `BE`

| 경우 | 취소 |
| --- | --- |
| 원래 결제 + **추가 결제**(교환 · 반려 재발송비) | PG 거래가 따로라 **취소도 따로** · 취소 가능 잔액도 건별 |
| **일부 반려 · 항목 단위 환불** | 원래 결제 **부분 취소** |
| 계좌 환불 | **없다** — 결제수단이 카드·간편결제뿐(⚠️ §39-6 A-2) |

## 37. 어드민 거래 관리 — 주문 조회 — [v0.41 신설]

대상 화면: `ui-admin-06a-orders.html` (**rev.4** · 2026.10.05 — `<title>`은 rev.3), 상태 14종(목록 6 · 상세 모달 8). GNB **6 거래 관리 › 주문 조회**. 기준 파일은 `ui-partner-10a~10e`(§34)이고, 같은 메뉴의 `06b` 반품·교환(§38) · `06c` 환불 관리(§39) · `06d` 예외 관리(§40)는 `[v0.42]` **신설**됐다. 사이드바 배지 — 반품·교환 = 소비자 이의 · 환불 관리 = 집행 대기 + 실패 · 예외 관리 = 처리 지연 + 배송 예외.

**범위 밖** — 반품·교환 처리(§38) · 환불 집행·실패 처리(§39) · 배송 예외·처리 지연 큐(§40).

### 37-0. 성격 · 단위 — `FE`·`BE`

| 항목 | 규칙 |
| --- | --- |
| **조회 화면** | 목록에 **액션 버튼 · 체크박스 · 일괄 처리가 없다.** 운영자 조치는 **상세 모달 우 레일에서만** 시작한다 — 남의 거래에 개입하는 일이라 근거를 읽고 눌러야 한다 |
| **행 = 주문(결제 1건)** | 파트너센터(§34)는 **하위주문**이 행이다. CS에 들어오는 말은 「주문 하나 했는데요」다 |
| 확장 | **하위주문 1단에서 끊는다** — 항목(SKU)은 상세 ②블록. 3단을 같은 열 골격에 얹으면 **열 의미가 행마다 바뀐다** |
| 운영자 조치 | **5종** — 송장 대행 등록 · 배송완료일 정정 · 직권 취소 · 운영자 사유 환불 · 반품 대신 열기(§37-5) |
| 조치 없는 상태 | 반송 완료 · 취소 요청 · 교환 진행 — 레일에 「조치할 것이 없습니다」와 이유를 적는다(§37-6) |

### 37-2. 목록 — 필터 · 툴바 — `FE`

**필터는 한 컴포넌트 3줄**이다(디자인시스템 `.filter > .tabs + .search` 확장).

| 줄 | 구성 |
| --- | --- |
| ① | 탭 **전체 · 배송 이상 · 취소** + **상태 셀렉트** + 검색 대상(주문번호 / 소비자 / 송장번호 / PG 거래번호) + 검색어 + `검색` |
| ② | **결제일** 프리셋(오늘 · 7일 · **1개월** 기본 · 3개월 · 직접 입력) + 기간 표시 + **적용됨 칩** + `상세 조건 ▾` |
| ③ 펼침 | 브랜드 · 공구 · 인플루언서 · 결제수단 + `조건 초기화` |

| 항목 | 규칙 |
| --- | --- |
| **탭 3 + 상태 셀렉트** | 디자인시스템 §6 — 탭은 4~5개까지, 그보다 많으면 **묶음 탭 + 상태 셀렉트**. 탭은 **운영자가 여는 축**만 둔다(반품 환불은 반품·교환, 환불 실패는 환불 관리 소관이라 「취소」만 남는다) |
| 상태 셀렉트 | 결제완료 · 상품준비중 · 배송중 · 배송완료 · 구매확정 · 취소·환불 — **건수 병기** |
| **축 연동** | 배송 이상 탭에서는 같은 자리가 **이상 유형 셀렉트**(집화 확인 필요 · 추적 정지 · 반송 중) |
| 상세 조건 | **같은 필터 안에서 늘어난다** — 패널·드로어 금지. **공구는 브랜드 종속**(브랜드 미선택 시 비활성) |
| **적용됨 칩** | 고르는 즉시 붙고 **접어도 남는다** — 다른 화면에서 조건을 달고 넘어와도 「왜 0건인가」를 잃지 않는다 |
| 요약 건수 | 툴바 좌측 — `총 N건 · 배송 이상 N건 · 처리 지연 N건` · 배송 이상 탭은 유형별 건수(합 = 탭 숫자) |
| 정렬 | 결제일시 최신순(기본) · 오래된순 · 결제금액 높은순 / 배송 이상 탭 = **이상 지속 오래된순**(기본) · 결제일시 최신순 |
| 표시 건수 | **20** · 50 · 100 |
| 정렬 설명문 | **UI에 쓰지 않는다** — 툴바 우측에는 컨트롤만(디자인시스템 §8) |
| 폐기 요소 | 상태 분포 줄 · 관리 `[상세]` 버튼 열 · 자체 필터 박스 · 세그먼트 · KPI 카드 — rev.3에서 제거. **되살리지 않는다** |

### 37-3. 목록 — 컬럼 · 상태 2축 — `FE`·`BE`

**컬럼 8종** — 주문번호 · 결제일시 · 소비자(**마스킹**) · 브랜드(여럿이면 `N개 브랜드`) · 공구명 · 결제금액(우측 정렬) · **상태** · **배송 이상**. 상세 진입은 **행 클릭**이다.

| 축 | 뜻 | 값 |
| --- | --- | --- |
| **상태** | 진행 단계 | 결제완료 · 상품준비중 · 배송중 · 배송완료 · 구매확정 · 취소·환불 · **혼합**(하위주문이 갈리면 조합 부기) |
| **배송 이상** | 그 단계에서 벌어진 사고 | 집화 확인 필요(등록 후 N시간) · 추적 정지(N일 무갱신) · 반송 중(감지일) · — |

| 항목 | 규칙 |
| --- | --- |
| **두 축을 합치지 않는다** | 「배송중인데 반송 중」이 실제 조합이다 |
| 색 | 조치 필요(발송 기한 초과 · 집화 확인 필요) = **경고** / 반송 중 · 추적 정지 = **위험** / 정상 진행 = 정보 / 배송완료 · 구매확정 = 성공 / 취소·환불 = **중립**(원칙 ②) |
| 직권 취소 버튼 | 흰 배경 + 중립 테두리 + **위험색 글자** |
| 행 확장 | 하위주문 — 브랜드 · 대표 상품 외 N종 · 금액 · 상태 · 송장(없으면 `송장 미등록`). **하위주문 합 = 주문 금액** |
| 빈 상태 2종 | **조건 결과 없음**(칩 삭제 안내 · `조회 조건 초기화`) / **검색 결과 없음**(`전체 기간에서 다시 찾기` — 주문번호가 맞는데 결과가 없으면 기간이 좁은 경우가 대부분) · 검색어는 지우지 않는다 |
| ⚠️ 상태명 | 파트너 「신규(준비 대기)」 = 어드민 **「결제완료」** · 파트너는 **반송중이 이행 상태 값**이고 어드민은 **배송 이상 열**이다(§37-8 A-3) |

### 37-4. 주문 상세 모달 — `FE`·`BE`

**모달 1040px · 좌 5블록 + 우 레일 320px**(디자인시스템 §9 `1fr 320px`). 헤더에 주문번호 · **문의 N건 배지** · `‹ 이전` `다음 ›`.

| 블록 | 내용 |
| --- | --- |
| ① 결제 정보 | PG 거래번호 · 결제수단 · 결제금액 · 결제일시 · **취소 가능 잔액** · 결제 상태. 추가 결제가 있으면 **원래 결제 / 추가 결제 두 줄** — PG 거래가 따로라 취소도 따로다 |
| ② 하위주문 · 항목 | 공구 · 인플루언서 → 브랜드별 하위주문 → 항목(상품·옵션 · 수량 · 상태 · 금액) |
| ③ 배송 | 하위주문별 택배사 · 송장(마스킹) · 추적 최신 · **송장 출처** · 발송 기한 · 배송완료일시 + **출처** |
| ④ 정산 반영 | 구매확정 진행 · 정산 편입 · 정산 확정일 · **클로백** |
| ⑤ 이력 | 최신순 · 주체(시스템 / 브랜드 / 소비자 / 운영자) |
| 우 레일 | 현재 상태 → 운영자 조치(인라인 폼) → 그 외 조치 → `연결·소통 스레드 열기 ↗` |

| 항목 | 규칙 |
| --- | --- |
| **④를 남기는 이유** | 직권 취소 · 사유 환불이 **클로백을 만드는지**가 판단에 직결된다 — 레일 버튼 밑에도 한 줄로 적는다 |
| 레일 액션 | 조건 미충족이면 **숨긴다**(비활성 아님) |
| 인라인 폼 | 조치는 **레일 안에서** 펼친다 |
| 필수 미입력 | **버튼 비활성만** — 에러 문구는 형식 오류 · 중복 송장에만. 비활성 버튼에 인라인 opacity를 덧씌우지 않는다 |
| **발송 기한 표기** | **그 주문에 적용된 N과 계산된 기한을 함께** — `마감 MM.DD + N영업일 → MM.DD` · 「주문 시점 값」 병기 |
| **출처 3종** | `(자동 확인)` / `(운영자 정정)` / 송장 `(운영자 대행)` — 배송완료일이 **구매확정 D+7과 반품·교환 기간의 기산점**이라 누가 무슨 근거로 찍었는지가 이의의 쟁점이다. **정정 전 값은 이력에 남긴다** |
| 송장 3종(교환) | 출고 = 브랜드 · 회수 = 소비자 · 재발송 = 브랜드 — **출처별로** 적는다 |
| 반송 사유 | **적지 않는다** — 플랫폼이 단정할 수 없다 |

### 37-5. 운영자 조치 — 5종 — `FE`·`BE`

| **직권 취소** | **배송 전 하위주문만** | ⚠️ 폼 미제작(§37-9 #9) | **PG 자동 환불** — 운영자 집행 없음 |
| **운영자 사유 환불** | 반려 이의 인용 · 위해성 리콜 · 기타 | **대상 항목**(체크 + 수량) · **사유 카테고리** 3종 · **근거** | **환불 대기 편입까지** — 집행은 환불 관리의 재확인 다이얼로그 |
| **반품 대신 열기** | 구매확정 후 하자 · 법정 기한 내 | 대상 항목 · **하자 유형** 3종 · **증빙**(1:1 문의) · **하자 인지일** | 반품 클레임 생성 → 소비자 회수 송장 입력 → 검수 → 자동 환불(일반 반품과 동일 · §35) |

| 항목 | 규칙 |
| --- | --- |
| **대행 등록을 빼지 않는다** | 없으면 브랜드 무응답 시 남는 조치가 **직권 취소뿐**이고, 공구는 한정 수량이라 소비자가 재구매할 수 없다 |
| **브랜드는 날짜를 못 고친다** | 자기 정산을 당기는 날짜를 자기가 정하지 않는다(약관 제19조② — 회사가 중재 후 직권 정정) |
| **운영자가 실행하는 유일한 환불** | 취소 · 반품 승인 · 반송 완료가 모두 PG 자동이 되면서 사유 환불만 남았다 |
| 위해성 중단 | **발송분 = 사유 환불 · 미발송분 = 직권 취소.** 다른 브랜드의 하위주문은 중단 범위가 아니다 |
| **구매확정 후 하자 ≠ 환불** | **물건이 돌아와야 하므로 반품을 연다.** 하자 유형은 불량·파손 / 표시·광고와 다름 / 오배송 — **단순 변심이 없다** |
| 법정 기한 | **공급일 + 3개월**과 **하자 인지일 + 30일** 중 **이른 날**(전자상거래법 제17조③) — 레일에 계산해 보여주고 지난 건은 버튼 비활성 |
| 귀책 | 반품 대신 열기는 **브랜드 귀책**(착불 · 차감 없음)으로 열린다 — 검수에서 달라질 때의 처리는 §37-8 B-16 |
| **클로백 고지** | 정산 확정 항목이면 「환불되면 다음 정산에서 차감」을 **버튼 위에** 적는다 `[자문대기-법률 J]` |

### 37-6. 조치가 없는 상태 — `FE`·`BE`

| 상태 | 화면 | 규칙 |
| --- | --- | --- |
| **반송 완료** | 배너 「반송이 완료되어 PG 자동 환불이 실행됐습니다(금액 · 시각)」 · 반송 감지/완료 시각 | 택배사 코드 감지 → **즉시 PG 환불** · 구매확정 타이머 취소 · 정산 제외 · **재발송 없음** · 환불 실패 시 환불 관리 실패 탭 |
| **취소 요청** | 요청 일시 · 사유 · **응답 마감** · 자동 승인 시 환불액 · 남은 시간 | 브랜드 **1영업일** 응답 · 미응답 **자동 승인 + PG 즉시 환불** · 운영자는 대신 승인·거부하지 않는다 · **처리 지연 항목이 아니다** |
| **교환 진행** | 원래 결제 / 추가 결제 · 송장 3종 · 타이머 정지와 남은 일수 | 처리는 06b · 레일에 `반품·교환 상세 보기 ↗`만 |

| 항목 | 규칙 |
| --- | --- |
| 취소 요청 범위 | 항목 하나만 요청해도 **주문 전체가 취소 요청으로** 가고 **송장 잠금은 하위주문 전체**다(2026.10.05) — 같은 박스로 나가므로 한 항목만 잠그면 분리 발송이 생긴다 |
| **송장 잠금** | 요청이 걸린 하위주문은 **브랜드 송장 등록이 잠긴다** — 거부 사유를 고르지 않고 송장부터 넣어 요청을 무력화하는 경로를 막는다 |
| 거부 사유 4종 | 이미 포장·출고 완료 / 택배사 집화 완료 / 주문 제작·맞춤 상품 / 기타(상세 필수) — **소비자에게 그대로 전달** |
| 교환 타이머 | 요청 시 **구매확정 타이머 정지**(남은 일수 보존 표기) · 교환 완료 시 **7일 새로 시작** |
| 재발송비 | **별도 PG 결제** · **브랜드 수취액에 가산 · 리워드 기준 제외** · 같은 가격 옵션끼리라 차액 없음 |

## 18. 어드민 상품 문의 모니터링 — [v0.26 신설]

대상 화면: `ui-admin-07-product-qna.html` (**rev.1**), 상태 6종(목록 1 · 상세 3 · 모달 2). 셸·테이블·모달·배지는 §16 컴포넌트를 그대로 재사용했다. 근거 와이어는 `wf-admin-08-CS콘텐츠관리` **F3~F4**(F1·F2는 §17).

**성격 — 운영자는 답변하지 않는다.** 상품 문의의 **답변 주체는 브랜드**다(도메인모델 §12 비즈니스 규칙). 운영자는 답변에 개입하지 않고 **부적절 게시물을 걸러내는 역할만** 한다. §17(1:1 문의)이 "답변 작성" 화면인 것과 정반대이며, 그래서 이 화면에는 **운영자 입력란이 없다.**

### 18-1. 상태 정의 — 4종 — `FE`·`BE`

| 상태 | 의미 | 배지 색 | 조치 주체 |
| --- | --- | --- | --- |
| 답변대기 | 소비자 문의 등록, 브랜드 답변 없음 | **정보** | 브랜드 |
| 답변완료 | 브랜드 답변 등록됨 | **중립** | — |
| 삭제 요청 | 브랜드가 삭제를 요청함 | **경고** | **운영자** |
| 삭제 | 운영자가 삭제 집행 — 소비자·브랜드 화면 비노출 | **위험** | — |

| 항목 | 규칙 |
| --- | --- |
| 와이어 대비 | 와이어는 `숨김` 1종이었고 `숨김`과 `게시`에 **같은 검정 배지**를 썼다. 하나의 색이 "차단"과 "정상 노출"을 동시에 뜻해 **상태색 원칙 ③ 위반**이라 4종으로 분리했다 |
| 답변대기가 정보색인 이유 | 브랜드가 조치할 건이라 **운영자에게는 정상 진행 중**이다. 운영자를 재촉하는 색을 쓰면 안 된다 |
| 삭제 요청이 경고색인 이유 | 이 화면에서 **유일하게 운영자 조치가 필요한 상태** — 원칙 ① |
| **삭제가 위험색인 이유** | 원칙 ②(종료=중립)의 **의도적 예외**다. `ui-admin-04`의 미진열 선례를 따랐다 — **소비자 노출이 실제로 막힌 상태**는 목록에서 즉시 눈에 띄어야 한다 |
| 상태 전이 | 답변대기 → 답변완료(브랜드 답변) / 답변완료 → 삭제 요청(브랜드 요청) → **삭제**(집행) 또는 **답변완료**(반려) / 어느 상태에서든 → **삭제**(운영자 직접) |
| 삭제 복구 | **경로 없음.** 원문은 보관하되 되살리는 액션은 제공하지 않는다 |

**작성자·공개 여부를 목록에서 뺀 이유** — 컬럼 7개로 이미 포화다. 목록의 판별 기준은 **"어떤 상품의 어떤 질문인가"**이지 누가 썼는지가 아니다.

### 18-2-1. 문의 유형 — 4종 — `FE`·`BE`

| 유형 | 포괄 범위 |
| --- | --- |
| 옵션 | 용량·색상·구성 선택 |
| 성분·사용법 | 성분·사용 대상·사용 방법 |
| 재입고 | 품절·재입고 일정 |
| 기타 | 위에 해당하지 않는 상품 문의 |

> **§17(1:1 문의)의 5종과 의도적으로 다른 목록이다.** 상품 문의는 **상품 상세에서 그 상품에 대해** 묻는 것이고, 1:1은 주문·결제·계정 등 서비스 전반이다. 대상이 달라 분류를 공유할 수 없으며, **FAQ 카테고리와 맞출 대상도 §17 쪽이다.** 이 화면의 `기타`는 §17에서 `기타`를 폐기한 것과 배치되지 않는다 — 상품 문의는 유형이 4종뿐이라 잔여 케이스를 받을 자리가 필요하다.
> 

### 18-3. 상세 — 필요한 정보 — `FE`·`BE`

| 영역 | 필요한 정보 |
| --- | --- |
| 문의 정보 | 문의번호(`QNA-YYYYMMDD-NNN`) · 문의 유형 · 상품(상품 상세 링크) · 브랜드(브랜드 상세 링크) · 작성자(회원 상세 링크) · **공개 여부** · 등록일시 |
| 문의 내용 | 소비자 메시지 + 첨부 사진. 헤더에 작성 제약 병기(`250자 이내 · 사진 최대 3장`) |
| 브랜드 답변 | 브랜드 메시지 + 답변자(브랜드명) + 답변일시. **답변대기면 이 카드가 비어 있다** |
| 삭제 요청 | **요청이 있는 건에만 존재** — 요청 사유 / 상세 설명 / 요청일시 |
| 처리 패널 | 현재 상태 + 메타(등록일시 · 답변일시 · 답변자 / 요청일시 · 요청자 / 삭제일시 · 처리자) + 액션 |
| 처리 이력 | **최신순.** 문의 등록(정보) → 브랜드 답변(중립) → 삭제 요청(경고) → 삭제(위험) |

| 항목 | 규칙 |
| --- | --- |
| 3개 링크 | 상품·브랜드·작성자 모두 다른 메뉴로 나가는 이동이다. 필드 값 옆 인라인 링크로 두고 우상단 이동 버튼군과 섞지 않는다 |
| 소비자 첨부 | **최대 3장**(§17의 1:1 문의는 5장 — 값이 다르다) |
| 이전/다음 이동 | **현재 탭의 목록 순서**를 따른다 |

### 18-4. 운영자 액션 — 삭제 · 반려 — `FE`·`BE`

| 상황 | 노출 액션 |
| --- | --- |
| 삭제 요청 없음 (답변대기·답변완료) | **삭제** 단독 |
| 삭제 요청 있음 | **삭제** + **반려** |
| 삭제됨 | **액션 없음** — 사유·안내문만 표시 |

| 항목 | 규칙 |
| --- | --- |
| 운영자 답변 | **없다.** 상품 문의 답변은 브랜드 책임이다. 운영자가 대신 답하면 브랜드 답변 SLA·품질 관리 근거가 사라진다 |
| **반려 성립 조건** | **삭제 요청이 있을 때만** 성립한다. 요청 없는 건에 반려 버튼을 노출하지 않는다(기각할 대상이 없다) |
| 레이아웃 | 상태와 무관하게 **같은 레이아웃**을 쓰고 버튼만 다르다. 카드가 사라지면 상태 전환 시 레이아웃이 점프한다 |

**반려 경로를 둔 이유** — 브랜드가 **불리한 문의를 삭제 요청으로 지우려 할 수 있다.** 운영자가 기각할 수 있어야 소비자 게시물 보호가 성립하고, 삭제 요청이 자동 승인처럼 동작하지 않는다.

### 18-5. 삭제 처리 — `FE`·`BE`

| 항목 | 규칙 |
| --- | --- |
| 확인 모달 | **필수.** 되돌릴 수 없는 집행 액션 |
| 정형 사유 | 드롭다운 **필수 선택** — 광고·홍보성 게시물 / 비방·욕설 / 개인정보 노출 / 기타(직접 입력) |
| 상세 사유 | 자유 입력 **선택**. **`기타(직접 입력)` 선택 시에만 필수로 전환** |
| 미선택 처리 | 에러 문구 없이 **버튼 비활성만** |
| 주 액션 색 | **위험색** |
| 집행 결과 | 소비자·브랜드 화면에서 **즉시 비노출**. 상태 → 삭제 |
| **원문 보관** | **원문·첨부·처리 내역을 내부 기록으로 보관**한다. 화면에서 지우는 것이지 데이터를 지우는 것이 아니다 |
| 사유 노출 | **내부 기록용** — 작성자에게 통지하지 않는다 |
| 삭제 요청 카드 | **요청을 거쳐 삭제된 건은 카드를 지우지 않고 남긴다**(18-7) |

### 18-6. 반려 처리 — `FE`·`BE`

| 항목 | 규칙 |
| --- | --- |
| 확인 모달 | **필수.** 구조는 삭제 모달과 동일 |
| 정형 사유 | 삭제 기준에 해당하지 않음 / 근거 부족 — 사실관계 확인 불가 / 정상적인 상품 문의 / 기타(직접 입력) |
| 상세 사유 | 삭제와 동일 규칙 |
| 주 액션 색 | **주 액션(파랑)** — 파괴적 액션이 아니다 |
| 안내 박스 | 정보 톤(삭제는 경고 톤) |
| 처리 결과 | 문의는 **게시 유지**, 상태는 **답변완료로 복귀** |
| **사유 전달** | **요청 브랜드에 전달한다** |

**삭제 사유와 반려 사유의 공개 범위가 다른 이유** — 반려는 **요청을 낸 상대가 있는 판단**이다. 요청자는 결과의 근거를 알아야 다음 요청 기준을 잡을 수 있다. 반면 삭제는 요청자가 없는 경우(운영자 직접 삭제)도 있고, 사유를 알리면 삭제 기준을 우회하는 재작성을 유도하게 된다. **§16-5(변경 요청 반려 사유 공개)와 같은 논리**다.

**통지 정책 정리**

| 대상 | 삭제 | 반려 |
| --- | --- | --- |
| 작성자(소비자) | **미통지** | **미통지** |
| 요청 브랜드 | 미통지 | **사유 전달** |

작성자에게 통지하지 않는 이유는 삭제 기준을 우회하는 재작성 유도와 분쟁 창구 신설을 막기 위해서다.

### 18-7. 삭제 요청 카드 존치 — `FE`·`BE`

| 삭제 경로 | 삭제 후 화면 |
| --- | --- |
| 브랜드 삭제 요청 → 운영자 집행 | **삭제 요청 카드를 문의 내용 카드 아래에 남긴다** |
| 운영자 직접 삭제(요청 없음) | 카드 없음 |

**남기는 이유** — 브랜드가 **왜 요청했고** 운영자가 **무엇을 근거로 집행했는지**가 한 화면에서 대조돼야 분쟁 시 소명이 된다. 처리 이력만으로는 요청 사유 원문이 남지 않는다.

### 29-1. 공구의 출생 — 계약에서만 — `FE`·`BE`

| 항목 | 규칙 |
| --- | --- |
| 생성 | **계약 체결 시에만** 생성된다. **계약 1건 = 공구 1건** |
| 생성 진입점 | **세 서피스 어디에도 없다.** 목록에 `+ 공구 생성`을 두지 않고, 빈 상태 CTA는 **계약 관리로** 보낸다 |

### 29-2. 상태 정의 — 7종 · 3서피스 공통 — `FE`·`BE`

```
준비중 → 준비완료 → 진행중 → 종료 → 정산완료
                        ├─ 중단 예정 → 중단
                        └─ 중단 (긴급)
```

| 상태 | 색 | 의미 | 근거 |
| --- | --- | --- | --- |
| **준비중** | 중립 | 게이트 3개 미충족 | 아직 시작하지 않음 |
| **준비완료** | 정보 | 게이트 충족 · 시작 시각 대기 | **정상 대기 — 시간이 열어준다** |
| **진행중** | 성공 | 판매 중 |  |
| **중단 예정** | **경고** | 직권 중단 사전통지 발송 · 소명 대기 | 아직 팔리지만 **종결이 예고**됐고 **소명해야 하는 상태**(원칙 ①) |
| **종료** | 정보 | 기간 종료 · 정산 대기 | **정산 대기이지 실패가 아니다** |
| **정산완료** | 성공 | 이체 완료 |  |
| **중단** | **위험** | 판매 도중 강제 종결 | 이미 팔린 뒤 소비자 주문을 끊었고 **지급된 고정 지급비도 회수되지 않는다** |

**중단이 계약의 「취소」와 층이 다른 이유** — 계약 취소는 **아직 아무 일도 일어나지 않은 상태**의 철회라 중립이지만, 공구 중단은 **이미 판매가 일어난 뒤** 소비자 주문을 강제로 끊는 것이다. 정상 종결(종료·정산완료)과 **한눈에 갈려야** 한다.

**종결 3종을 구분한다**

| 종결 | 결과 상태 | 색 | 접수분 | 환불 |
| --- | --- | --- | --- | --- |
| **종료** | 종료 | 중립 | 그대로 배송·정산 | 없음 |
| **조기 마감** | **종료** | **중립** | 그대로 배송·정산 | **없음** |
| **중단** | 중단 | **위험** | 판매 관리에서 개별 처리 | 발생 가능 |

> **재고 소진은 중단이 아니라 조기 마감이다.** 정상 종결을 앞당기는 것이므로 **위험색을 쓰지 않는다**(승인 버튼도 인디고).
> 

**목록 탭은 6종이다** — 전체 · 준비중 · 준비완료 · 진행중 · 종료 · **중단**. **「중단 예정」은 탭에 없고 진행중 탭에 배지로만** 나타난다 — 아직 팔리고 있고 종결이 확정되지 않았다.

### 29-3. 게시물 상태 — 8종 · 3서피스 공통 — `FE`·`BE`

| 상태 | 색 | 공구 상태 연동 |
| --- | --- | --- |
| 미작성 | 중립 | 준비중 |
| 작성중 | 중립 | 준비중 |
| 승인대기 | 정보 | 준비중 |
| **반려** | **경고** | 준비중에서 **멈춤** |
| 예약 | 정보 | **준비완료** |
| 노출중 | 성공 | 진행중 |
| **숨김** | **경고** | **진행중 그대로** |
| 종료 | 중립 | 종료 · 조기 마감 · **중단** |

| 항목 | 규칙 |
| --- | --- |
| **경고는 반려와 숨김 둘뿐** | 운영자가 개입해 **진행이 멈추거나 노출이 끊긴** 상태이고 **고칠 권한은 인플루언서**에게 있다 |
| **게시물 「중단」 값을 두지 않는다** | 공구가 중단되면 게시물은 **종료**가 된다. 게시물을 내리는 경로는 공구 종결뿐이다 |
| **숨김은 유일한 어긋남** | 공구 = 진행중(성공) / 게시물 = 숨김(경고)이 **두 열에 다른 색으로 나란히** 서는 유일한 조합이다 |
| 미작성 ≠ 작성중 | **미작성은 상대가 착수조차 안 한 상태**라 스레드에서 확인할 일이고, **작성중은 진행 중**이라 기다리면 된다. 둘 다 중립색이지만 **라벨로 구분**한다(원칙 ③) |
| 게시물 열 | 공구와 **별 축**이라 목록에서 **별 열**로 둔다 |

### 29-4. 준비 게이트 — 3개 — `FE`·`BE`

| # | 게이트 | 주체 |
| --- | --- | --- |
| ① | **최소 준비 물량 확보 확인** | 브랜드 |
| ② | **공구 게시물 등록** | 인플루언서 |
| ③ | **오픈 승인** | 운영자 (SLA 영업일 3일 · `[근거 대기]`) |

| 항목 | 규칙 |
| --- | --- |
| 전이 조건 | **셋이 모두 충족**되면 준비완료가 된다 |
| **시작 버튼이 없다** | 시작 시각이 되면 **시스템이 자동으로 연다.** 브랜드도 인플루언서도 누르는 버튼이 없다 |
| **고정 지급비는 게이트가 아니다** | 브랜드 직접 지급이라 플랫폼이 관여하지 않는다(§29-9). 체크리스트에 지급 병기를 두지 않는다 |
| 체크리스트 표기 | 각 줄에 **주체**를 적고 **내 차례인 줄만 경고 톤**(`.ck-i.wait`)으로 띄운다 |

**①의 근거** — 약관 **제25조** 제재표가 「최소 물량 미확보: 공구 개설 승인 후 브랜드의 정당한 사유 없는 물량 공급 차질 → **2단계**(일정 기간 판매 활동 제한)」를 규정한다. 이 확인 기록이 **제재 판정의 증거**가 된다.

> **같은 준비중이라도 화면 온도가 다르다** — 내가 손댈 게 남았을 때와 남의 응답을 기다릴 때. **상태값을 늘리는 대신 체크리스트의 주체 표기와 경고 톤**으로 표현한다.
>

| **조기 마감** | 브랜드 | **운영자** | 진행중 | 정상 종결이지만 소비자 노출이 끊긴다 |
| **공구 중단** | **브랜드·인플루언서 양측** | **운영자 단독** | 진행중 | 제16조① · **소비자 주문을 끊는 일**이라 당사자 합의만으로 처리할 수 없다 |

**기간 연장 세부**

| 항목 | 규칙 |
| --- | --- |
| 방향 | **연장만.** 단축은 어느 시점에도 없다 — 이미 주문한 소비자가 있다 |
| 명칭 | **「기간 연장」**으로 고정한다. 「기간 변경」이 아니다 |
| 준비중·준비완료 | **경로를 두지 않는다** — 시작 전 기간 수정은 **계약 조건을 고치는 일**이고 새 계약의 몫이다 |
| **횟수** | **공구당 1회.** 수락되든 거절되든 기회는 소진되고 **재요청 경로가 없다** |
| 수락 기한 | **현재 종료 시각.** 그 뒤에는 누를 수 없다 — 이미 닫힌 공구를 되살리는 경로를 만들면 **소비자에게 종료를 알린 뒤 다시 열린다** |
| **무응답** | **변경 없이 종결.** 자동 반영이 아니다. 별도 만료 처리·알림 재촉이 없다 |
| 수락 시 | **즉시 반영 · 불가역.** 기간 표기·진행 바·종료 예정·연장 여유를 **전부 새 기준으로 재계산**한다 |
| 수락해도 늘지 않는 것 | **고정 지급비 · 리워드율** — 연장을 보상 증가로 오해하면 수락 판단이 왜곡된다 |
| 거절 경로 2종 | **명시적 거절**(사유·메모 있음) · **기간 만료 자동 거절**(사유 없음). 결과는 같다 |
| 어드민 | **승인 UI가 없다.** 조회 카드만 둔다 — 분쟁 시 경위를 읽어야 하고 **종료일·정산 일정이 바뀐다** |

**공구 중단 세부**

| 항목 | 규칙 | 근거 |
| --- | --- | --- |
| **요청 ≠ 집행** | 요청만으로 판매가 멈추지 않는다. **승인 전까지 배송·반품·소비자 응대 의무는 브랜드가 계속 부담**한다 | 제16조② |
| **재개 불가** | 한 번 중단된 공구는 재개할 수 없다 | 제16조③ |
| 리워드 | **중단 집행 이전 결제 완료 정상 주문의 리워드는 그대로 정산**되고 **잔여 기간 청구권은 소멸**한다 | 제16조④2 |
| 고정 지급비 | **플랫폼이 회수해 주지 않는다** — 돈이 플랫폼을 지나가지 않으므로 되돌릴 대상이 없다. **「환급」을 쓰지 않는다** | §29-9 |
| 접수분 | 배송·취소·반품·환불·CS는 **브랜드가 부담** · 판매 관리에서 개별 처리 | 제16조④3 |
| **요청은 상태가 아니다** | 요청·검토 중·반려는 전부 **진행중 그대로**다. 배지를 바꾸는 것은 **승인 하나뿐** |  |
| 검토 중 추가 요청 | **불가** |  |

### 29-7. 직권 중단 — 3단계 — `FE`·`BE` `[v0.34 신설]`

약관 **제17조②③④**가 사전 통지를 의무화해 **「중단 예정」 상태**가 생겼다.

```
진행중 ──사전 통지(집행 3영업일 전)──▶ 중단 예정
                                        ├─ 소명 제출(3영업일 내)
                                        │     ├─ 타당 → 철회 → 진행중
                                        │     └─ 부당 → 집행 → 중단
                                        └─ 미제출 → 기존 자료로 판정 → 중단

긴급(제17조③) ──즉시 집행──▶ 중단 → 사후 통지
```

| 항목 | 규칙 | 근거 |
| --- | --- | --- |
| **사유 4호** | ① 법령 위반(화장품법·표시광고법·전자상거래법) 또는 위반 우려 명백 ② 지식재산권 침해 또는 상품의 중대한 하자·위해성 ③ **게시물 무단 변경**·공급불능·약관/계약서상 중대 의무 불이행 ④ 분쟁 심화로 거래 이행 불가 또는 플랫폼 신용·명예 훼손 | 제17조① |
| 사전 통지 | 중단 예정일 **최소 3영업일 전** · 중단 사유 · 집행 일시 · **소명 제출기한** 기재 | 제17조② |
| 긴급 예외 | 소비자 위해 방지 · 행정/사법기관 명령 · 피해 급증 우려 — **즉시 집행 후 지체 없이 사후 통지** | 제17조③ |
| 소명 | 통지 수신일부터 **3영업일 이내** · **미제출 시 기존 자료를 기준으로 최종 판정** · **소명이 타당하면 철회 가능** | 제17조④ |
| 집행 확정 시 | 게시물 **즉시 노출 중지·판매 차단** · **재개 불가** | 제17조⑤ |
| 사유별 통계 | **제17조① 1~4호 체계로 고정**한다 — 자유 사유를 쓰면 **제25조 제재 단계 판정에 쓸 수 없다** |  |

> ⚠️ **사유 3호는 브랜드에 물을 수 없다** — 「승인된 공구 게시물의 무단 변경」은 게시물 수정권이 **인플루언서**에게 있어(인플 제14조⑤) 브랜드 귀책이 될 수 없다. **`[약관수정필요]` — §33-2 C-2**
> 
> 
> ⚠️ **인플루언서에게는 소명 조항이 없다** — 제17조②④가 **브랜드에게만** 통지·소명을 보장한다. 인플루언서도 영향을 직접 받는데(게시물이 내려가고 잔여 리워드 청구권이 소멸) 대응 조항이 없어 **스튜디오 화면에 소명 액션을 두지 못했다.** **`[약관보완-2차질의]` — §33-3 D-4**
> 

### 29-8. 게시물 사후 개입 — 숨김 하나 — `FE`·`BE`

| **승인대기 중 수정** | **불가** — 심사 대상이 도중에 바뀌면 안 된다 | 인플 제14조③ |
| 회사의 권한 | **게시물 삭제 · 노출 중지 · 수정 요청** 3종 | 인플 제14조⑤ |
| 책임 | 승인 후 수정한 내용의 법적 책임은 **인플루언서가 전적으로 부담** | 인플 제14조⑤ |

**숨김 규칙 4개**

| # | 규칙 |
| --- | --- |
| ① | **게시물만 내린다** — 공구는 **진행중 그대로**이고 주문·배송이 계속된다 |
| ② | **사유와 설명이 필수**다 — 무엇을 고쳐야 다시 노출되는지 모르면 숨김이 방치로 끝난다 |
| ③ | **해제는 운영자가 한다** — 인플루언서가 고쳤다고 자동 복귀하면 **같은 문구로 되돌려도 다시 열린다** |

### 29-10. 계약 이행 확인 — 정산의 선행 조건 — `FE`·`BE`

공구가 끝나면 정산 전에 **양측이 서로의 이행을 확인**한다.

| 항목 | 규칙 | 근거 |
| --- | --- | --- |
| **확인 대상** | **내 의무가 아니라 상대의 의무**다 — 브랜드는 **인플루언서의 콘텐츠 의무**를, 인플루언서는 **브랜드의 배송·지급 의무**를 확인한다. 자기 이행을 스스로 체크하는 방식은 **검증력이 없다** | 인플 제20조① |
| **판단 단위** | **계약 전체에 1회.** 항목별로 쪼개지 않는다 — 하나라도 문제가 있으면 결국 같은 스레드에서 다루게 되고, 쪼개면 **부분 판정 규칙**이 또 필요해진다 | 인플 제20조② |
| 선택지 | **이행 / 미이행 2지.** 체크박스가 아니다 — **「체크 안 함」과 「미이행」은 뜻이 다르다** |  |
| **불가역** | 되돌릴 수 없다 | 인플 제20조② |
| 미이행 시 | **사유 입력 필수** → **정산 보류** + 연결·소통에 **3자 스레드** 개설 · 제출 글이 **첫 글** | 인플 제20조②③ |
| **스레드 종결** | **양측 모두 동의**해야 종결·보류 해제. **한쪽이라도 반대 사유를 입력하면 보류 유지** | 인플 제20조⑤ |
| **금액 조정** | **회사의 중재 의견에 금액 조정은 포함되지 않는다.** 금액은 당사자 합의 사항이다 | 인플 제20조④ |
| 재이의 | 종결 후 **동일 사안 재이의 제한** · 새 이견은 **새 스레드** | 인플 제20조⑥ |
| 스레드 무응답 | **회사가 정한 답변 기한** 내 무응답 시 **제출된 자료만으로 중재 의견** 제시 가능 · **기한 도래 전 개별 통지** | 인플 제20조⑦ |
| 합의 화면 | **이 화면에 두지 않는다.** 스레드 UI는 **연결·소통 소관**이고 공구 관리는 **판단을 넘기는 지점까지**다 |  |
| **이슈는 상태가 아니다** | 스레드가 열려 있어도 공구 상태는 **종료 그대로**다 |  |
| 이행 확인 ≠ 이슈 스레드 | 이행 확인은 **정산 전 관문**(양측 필수), 이슈 스레드는 **정산과 무관한 이견**을 여는 창구다 |  |

### 29-11. 정산 트리거 · 지연 감시 — `BE`

| 항목 | 규칙 |
| --- | --- |
| **트리거** | 구매확정이 아니라 **공구 종료 + 모든 주문 항목의 종결** |
| 종결 경로 5종 | ① 배송완료 +7일 무사고 ② 반품 승인→환불 ③ **반품 거절 확정 = 즉시 구매확정** ④ 교환 승인→재발송 도착 +7일 ⑤ **교환 거절 확정 = 즉시 구매확정** |
| **거절 확정 = 즉시 구매확정** | 환불이 발생하지 않아 금액이 이미 확정되므로 **상품 위치와 무관하게** 정산 대상이 된다. 이 규칙이 없으면 **거절 보류 1건이 공구 전체 정산을 무기한 붙잡는다** |
| 지급 | 종결 후 **영업일 5일 내 이체** |
| **미종결 0 아니면** | **정산 확인 버튼 비활성** |
| **지연 감시** | 공구 종료 **+30일**에 어드민 알림. **강제 처리 규칙은 없다**(교환 정상 경로가 30일 근처라 강제 컷을 걸지 않는다) |
| 경로별 내역 | **판매 관리 소관.** 공구 화면은 **남은 건수만** 센다 — 같은 표를 다시 그리면 **두 화면의 숫자가 어긋난다** |
| 정산 명세 | **정산 관리 소관.** 수수료·PG·원천징수를 공구 화면에서 다시 계산하지 않는다 |

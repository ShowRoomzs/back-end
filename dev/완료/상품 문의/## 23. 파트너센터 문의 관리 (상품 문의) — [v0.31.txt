## 23. 파트너센터 문의 관리 (상품 문의) — [v0.31 신설]

대상 화면: `ui-partner-07-inquiries.html` (**rev.4**), 상태 11종(목록 3 · 상세 7 · 모달 1). 셸은 `ui-partner-04-product-management`(rev.32), 상태·용어·컬럼 정본은 **`ui-admin-07-product-qna.html` rev.1**. GNB **#8 문의 관리**(배지 = 답변대기 건수).

**성격 — §18(어드민)과 짝을 이루는 브랜드 측 화면이다.**

|  | §18 어드민 | §23 파트너센터 |
| --- | --- | --- |
| 답변 입력란 | **없음** | **있음 — 유일한 답변 작성 창구** |
| 삭제 | **집행** | **요청만** (집행은 운영자) |
| 반려 | **판단** | **결과 수신** |
| 작성자 표기 | 실명 + 회원 상세 링크 | **닉네임 마스킹만**(구****) · 링크 없음 |

문의는 **소비자가 작성**하고 **답변은 브랜드가 작성**한다. 같은 데이터를 두 서피스가 다른 권한으로 다루므로, 상태값·색·컬럼은 §18을 정본으로 따른다.

> **[v0.31] §18 정합 패치 동반** — 이 화면 작업 중 §18과 어긋난 3건을 발견해 `기능요구사항1`을 **v0.28.1**로 패치했다: 문의 유형 4종→5종, 반려 시 복귀 상태, 삭제 시 답변 동반 비노출.
> 

### 23-1. 상태·색 — §18과 3서피스 동일 — `FE`·`BE`

| 상태 | 배지 색 | 조치 주체 |
| --- | --- | --- |
| 답변대기 | **정보** | **브랜드** |
| 답변완료 | **중립** | — |
| 삭제 요청 | **경고** | 운영자 |
| 삭제 | **위험** | — |

| 항목 | 규칙 |
| --- | --- |
| **서피스 간 동일** | 같은 상태값은 **어느 서피스에서나 같은 색**이다(원칙 ③ 우선). 조치 주체가 다르다고 색을 바꾸지 않는다 — 3서피스를 오가는 운영 소통에서 혼선이 생긴다 |
| 브랜드의 시급성 신호 | 색이 아니라 **등록일 표기(날짜+시:분)와 GNB 배지**가 전달한다 |
| 답변완료가 중립인 이유 | 성공색이 아니다 — **정상 종결된 일상 상태**다 |
| 삭제가 위험인 이유 | **소비자 노출이 실제로 막힌 상태**(§18-1과 동일, `ui-admin-04` 미진열 선례) |
| 공개여부·문의 유형 | **상태가 아니라 분류** — 점 없는 중립 배지 |

**두 축의 분리 — 구현 시 핵심**

| 축 | 값 |
| --- | --- |
| **답변 축** | 답변대기 / 답변완료 |
| **노출 축** | (정상) / 삭제 요청 / 삭제 |

한 열에 합쳐 표시하지만 **내부적으로는 별개 값이다.** 삭제 요청 중에도 **답변 축 값이 보존**돼야 반려 시 정확히 되돌아간다(23-5).

### 23-2. 목록 — `FE`·`BE`

| 축 | 컨트롤 | 선택 방식 |
| --- | --- | --- |
| 상태 | **탭** (전체 · 답변대기 · 답변완료 · 삭제 요청 · 삭제) | **배타적 단일선택** |
| 문의 유형 × 공개여부 | **필터 패널** (체크박스, 건수 병기) | **다중선택** |
| 검색 | `상품명 · 질문` 단일 입력 | — |

| 항목 | 규칙 |
| --- | --- |
| **탭 vs 필터 패널** | 상태는 **한 번에 하나만 보는 배타적 축**이라 탭으로 올린다. 필터 패널에는 **겹쳐 걸 수 있는 축**만 남는다 |
| **`전체`의 위치** | 탭에는 **있고** 필터 패널에는 **없다** — 단일선택은 되돌아갈 항목이 필요하지만, 다중선택은 **미선택이 곧 전체**이고 해제는 초기화 버튼이 맡는다 |
| 정렬 | `답변대기 우선`(기본) / `등록일순` |
| 표시 건수 | 20 / 50 / 100건씩 |
| 툴바 좌측 | `총 N건 · 답변대기 N건` |

**컬럼 7종**

| 컬럼 | 비고 |
| --- | --- |
| 문의 유형 | 5종 — 중립 배지(점 없음) |
| 질문 | 말줄임 |
| 상품 | 상품명 |
| 공개여부 | 공개 / 비밀글 — 중립 배지(점 없음) |
| 등록일 | **날짜 + 시:분** |
| 답변일 | 미답변이면 `—` |
| 상태 | **맨 뒷열**(§18과 동일) |

| 항목 | 규칙 |
| --- | --- |
| **상세 진입** | **행 전체 클릭.** 관리 열에 진입 전용 버튼을 두지 않는다. 와이어의 `[답변]`·`[보기]` 열은 삭제했다 |
| **빈 상태** | 브랜드는 문의를 만들 수 없으므로 **CTA 버튼을 두지 않는다** |
| 검색 결과 없음 | 테이블 헤더는 유지하고 **내용 영역만 교체**. 필터 카운트는 전체 기준이라 그대로 둔다 |

**날짜에 시:분까지 넣는 이유** — 답변 기한(SLA)이 운영 정책으로 확정되지 않았다. 근거 없는 잔여 시간 표기를 두면 **시급성 신호가 먼저 굳어버린다.** 대신 실제 소요를 직접 읽게 한다. SLA 확정 시에는 **상태값을 늘리지 말고 등록일 아래 보조 텍스트로만** 얹는다.

### 23-3. 상세 — `FE`·`BE`

**어드민(§18-3)과 동일한 3카드 + 우측 처리·이력** 구조다.

| 카드 | 내용 |
| --- | --- |
| 문의 정보 | 문의번호(`QNA-YYYYMMDD-NNN`) · 문의 유형 · 상품(상품 상세 링크) · **작성자(마스킹)** · 공개 여부 · 등록일시 |
| 문의 내용 | 소비자 메시지 + 첨부 썸네일. 헤더에 `소비자 입력 · 250자 이내 · 사진 최대 3장` |
| 브랜드 답변 | 답변 작성(미답변) 또는 등록된 답변 + `답변 수정` |
| 삭제 요청 / 삭제 요청 결과 | 해당 건에만 |
| 우측 · 처리 | 현재 상태 + 메타(등록·답변·**답변 소요** 등) + 액션 + 안내 |
| 우측 · 처리 이력 | 최신순 |

| 항목 | 규칙 |
| --- | --- |
| **작성자 표기** | **닉네임 마스킹만**(구****). **회원 상세 링크 없음** — 브랜드는 실명·연락처를 볼 수 없다 |
| 비밀글 | 공개 고지 배너를 **비밀글 고지로 교체**(같은 자리·같은 컴포넌트). **답변해도 공개로 전환되지 않는다.** 상품 상세 문의 탭에는 잠금 표시만 노출 |
| 이동 | 목록 / ‹ 이전 / 다음 › |

### 23-4. 답변 작성·수정 — `FE`·`BE`

| 항목 | 규칙 |
| --- | --- |
| 작성 주체 | **브랜드 단독.** 파트너센터가 **유일한 답변 작성 창구**다 |
| 미입력 처리 | **에러 문구 없이 `답변 등록` 비활성** |
| **글자수 상한** | **상한에서 입력이 막힌다**(`maxlength`) → **초과 상태 자체가 존재하지 않으므로 에러 문구도 없다.** 카운터만 상한 색으로 바뀌고 등록은 계속 활성 |
| 상한값 | **2,000자 — 잠정치**(23-7 미결 2번). 소비자 문의 250자는 어드민 확정값 |
| 등록 시 | **공개 콘텐츠로 전환** — 상품 상세 문의 탭에 질문·답변이 함께 노출. 작성자 마스킹 유지 |
| **답변 수정** | **허용한다** |
| 수정 이력 표기 | 답변 카드에 **"등록 시각 · 수정 시각" 병기** + 처리 이력에 **「답변 수정」 기록** |

**수정을 허용하는 이유** — 공개 콘텐츠라 잘못된 안내를 고칠 경로가 없으면 **브랜드가 삭제 요청으로 우회**하게 된다. 대신 **조용한 수정은 막는다** — 시각 병기와 이력이 그 장치다.

> **[근거 대기]** 수정 횟수 제한 · 소비자 화면의 "수정됨" 노출 여부 · 어드민에 수정 전 원문을 보여줄지는 미확정(23-7 미결 1번).
> 

**에러 문구 사용 범위** — 이 화면에는 **에러 문구가 없다.** 형식 오류·중복·파일 형식/용량 오류에만 쓰는데 그 중 어느 것도 발생하지 않는 화면이다.

### 23-5. 삭제 요청 — 브랜드는 요청까지 — `FE`·`BE`

| 항목 | 규칙 |
| --- | --- |
| 진입 | 상세 우측 `문의 삭제 요청` — **답변대기·답변완료 어느 쪽에서도** 가능 |
| 확인 모달 | **필수** |
| 정형 사유 | 비방·욕설 / 개인정보 노출 / 광고·홍보 / 타 브랜드 비교·비방 / 기타(직접 입력) — **[근거 대기] 잠정** |
| 상세 설명 | 선택 — **`기타(직접 입력)` 선택 시에만 필수** |
| 미선택 처리 | 에러 문구 없이 `요청 보내기` **비활성** |
| 주 액션 색 | **위험색** |
| **요청 취소** | **불가.** 요청 후에는 되돌릴 수 없다 |
| 검토 중 노출 | 문의는 **계속 게시된다** |
| 검토 중 액션 | **없다** — 운영자 판단이 나올 때까지 조작 불가 |

**반려 시 복귀 — 요청 직전 상태로**

| 요청 시점 상태 | 반려 후 |
| --- | --- |
| 답변완료 | **답변완료** |
| 답변대기 | **답변대기** |

**"항상 답변완료로 복귀"는 틀렸다.** 답변하지 않은 문의가 답변완료로 바뀌면 **답변 이력이 소실**된다. 23-1의 두 축 분리가 필요한 이유가 이것이다.

| 항목 | 규칙 |
| --- | --- |
| **반려 인지 경로** | **처리 이력에 「삭제 요청 반려 · 결과 알림 수신」으로 기록**하고 알림을 발송한다 |
| 별도 상태값 | **만들지 않는다** — 상태 축을 늘리지 않는다 |
| 반려 사유 | **요청 브랜드에게 전달된다**(삭제 사유는 내부 기록이라 전달되지 않는 것과 대비 — §18-6) |
| **재요청** | **가능하다** — 사유를 보완해 다시 제출할 수 있다 |

**삭제 집행 후 (브랜드 화면)**

| 항목 | 규칙 |
| --- | --- |
| 브랜드 액션 | **없음** — 조회 전용 |
| **삭제 사유** | **브랜드에게 표시하지 않는다** — 운영자 내부 기록. 브랜드 화면에는 **자신의 요청 경위만** 남는다 |
| 원문·답변 | 보관되며 파트너센터·어드민 상세에서만 조회 |
| **답변 동반 비노출** | 문의가 삭제되면 **브랜드 답변도 함께** 내려간다 — 질문 없는 답변은 성립하지 않는다 |

### 23-6. 권한 3분류 — `FE`·`BE`

| 분류 | 대상 |
| --- | --- |
| ① **직접 수정** | 답변 등록 · 답변 수정 |
| ② **변경 요청**(운영자 검토 경유) | 문의 삭제 — 브랜드는 요청까지, 집행은 운영자 |
| ③ **변경 불가** | 공개 ↔ 비밀글 전환 · 문의 내용 수정 |

**③이 불가인 이유** — 소비자가 작성한 콘텐츠다. 브랜드가 공개 범위나 문구를 바꿀 수 있으면 문의 제도 자체의 신뢰가 무너진다.

⑤ 어드민 · 2. 입점 관리 — 변경 요청 ui-admin-05-change-requests · rev.6

근거: 디자인시스템 v1.2 · 셸·테이블·모달·토스트는 ui-admin-02-onboarding-brand.html 컴포넌트 그대로 재사용 · 브랜드측 대응 화면 ui-partner-06-basic-info.html rev.8

[배치 · 신설] GNB 2. 입점 관리 하위 드롭다운 맨 아래에 "변경 요청"을 추가한다(브랜드 · 인플루언서 · 변경 요청). 입점 심사와 행위가 동일(서류 대조 → 승인/반려)하므로 최상위 메뉴를 새로 만들지 않는다. 상위 뱃지 수는 기존 7 → 9(변경 요청 2건 합산).
[본 파일은 입점 관리 디자인 파일과 분리] ui-admin-02-onboarding-brand.html·ui-admin-03-onboarding-influencer.html은 수정하지 않는다. 단, 두 파일의 GNB에도 "변경 요청" 항목이 없어 현재는 정합이 어긋난 상태다 — 이 화면 확정 후 두 파일 GNB에 1행씩 추가하는 패치가 필요하다(미결).
[대응 관계] 브랜드 파트너센터 ui-partner-06-basic-info의 M1(사업자 정보 변경 요청)·M2(정산 계좌 변경 요청) 모달로 접수된 건이 이 화면의 목록으로 들어온다. 여기서 승인·반려하면 브랜드 화면의 1-F/1-G · 2-E/2-F 배너로 결과가 표시된다.
[반려 사유] 정형 사유는 드롭다운 선택(필수), 상세 사유는 선택 입력. "기타" 선택 시에만 상세 사유 필수. 선택한 정형 사유 문구와 상세 사유가 브랜드 화면에 그대로 노출되므로 운영자용 축약어가 아닌 문장형으로 유지한다.
[rev.2 · 브랜드측 rev.7 반영] M1(사업자 정보 변경 요청)이 새 값 입력형으로 바뀌어, 대조표의 "변경 요청 값"은 브랜드가 직접 입력한 값이다(운영자가 서류를 보고 타이핑하지 않는다 — 오타·책임 소재 문제 회피). 변경 항목에서 사업자등록번호는 제외되어 대조표에 변경 요청 불가로 표시된다. 두 유형 모두 증빙 첨부 필수이므로 목록의 증빙 컬럼은 상수값이 되어 삭제했다.
[rev.2 · 목록 정리] CSV 내보내기 버튼 삭제 · 요청 유형 필터 삭제 · 우측 셀렉트를 정렬(경과시간 순) → 표시 건수로 변경. 정렬은 경과시간 내림차순 고정(SLA 초과 최상단).
[rev.3 · 미리보기 대조 패널 신설] 증빙 [미리보기]를 라이트박스로 열고, 우측에 요청 값 대조 패널을 붙였다. 항목별로 현재 값(취소선) → 요청 값(강조)이 표시된다. 패널 하단에는 변경 대상이 아닌 참고 항목(사업자등록번호·상호 등)을 병기해 동일 사업자 여부·예금주 명의 대조를 한 화면에서 끝내도록 했다. 이전에는 서류 이미지와 대조표가 다른 화면에 있어 운영자가 모달을 여닫아야 했다.
[rev.4 · 목록 컬럼 재구성] 변경 항목 컬럼 삭제(상세에서 대조표로 확인) · 승인·반려일시 컬럼 추가 · 요청 유형·요청일시·승인반려일시·경과·상태는 가운데 정렬 · 브랜드 셀의 요청 코드(BRD-…) 제거(상세에서만 노출) · 표시 건수 셀렉트 제거.
[rev.6 · 디자인시스템 폼 규격 정합] 반려 모달의 셀렉트·텍스트영역을 SHOWROOMZ_웹_디자인시스템_v1.2 폼 규격에 맞췄다 — 셀렉트 높이 36 → 32px, 패딩 8px 12px → 6px 10px, 우측 여백 30 → 32px(화살표 위치 right 12 → 10px), 라벨 weight 600 → 500 · 하단 여백 6 → 4px, 포커스 링(accent-50 3px) 누락분 추가. 셀렉트 화살표를 삼각형 → DS 셰브론(stroke #5B5F68, 1.5px, round cap)으로 교체. 목록에서 삭제된 .sel-sm(높이 28px·삼각형 화살표 — DS 미준수) 잔여 CSS도 함께 제거.
[rev.5 · 상세 내비게이션] 우상단 버튼은 목록 · ‹ 이전 · 다음 › 3개로만 두고 성격을 통일했다(이 목록 안에서의 이동). 브랜드 상세는 다른 메뉴(회원 관리)로 나가는 동작이라 성격이 달라, 제목 옆 칩 링크로 옮겼다 — 브랜드명 바로 옆에 붙어 "이 브랜드를 더 보기"라는 뜻이 위치만으로 읽히고, 우상단 이동 버튼군과 섞이지 않는다. 이전/다음은 현재 탭의 목록 순서를 따라 이동하며, 여러 건을 연속 처리할 때 목록으로 되돌아가지 않아도 된다.
[rev.5 · 목록 열 정돈] table-layout:fixed로 열 너비를 고정한다 — 브랜드 23% · 요청 유형 14% · 요청일시 18% · 승인반려일시 18% · 경과 11% · 상태 16%. 일시·경과 셀은 고정폭 숫자(tabular-nums)를 써서 행마다 자릿수가 흔들리지 않게 했다. 좌우 끝 셀에는 여백 20px을 더해 카드 테두리와 붙지 않도록 했다.
[신규제안 · 확인 필요] ⓐ 부분 승인 미지원 — 한 요청에 묶인 항목은 전체 승인 또는 전체 반려 ⓑ SLA 배지 — 입점 심사와 동일 기준 ⓒ 재요청 시 신규 행 생성 — 입점 심사는 동일 건에 이력 누적이지만, 변경 요청은 요청 시점마다 값이 달라 별건으로 취급 ⓓ 정산 계좌 상세에서 계좌번호 전체 노출(통장 사본 대조 목적 — 브랜드용 화면에서는 계속 마스킹).

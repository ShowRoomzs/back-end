### 34-0. 성격 · 단위 · 설계 원리 — `FE`·`BE`

**조회용 대시보드가 아니라 매일 여는 작업 큐다.** 상단 처리 대기 요약 바 고정 · 기본 진입 탭 **신규** · 신규 정렬 **오래된 순** · 목록 관리 열에서 바로 처리 · 다건 일괄 처리.

**단위 3층**

| 층 | 단위 | 이 화면 |
| --- | --- | --- |
| 주문 | 결제 1건 | 주문번호 |
| **하위주문** | 공구·브랜드별 · **배송 단위** | **목록 기본 단위** · 타 브랜드 몫 비노출 |
| 주문 항목 | SKU · **취소·반품·교환 단위** | 행 확장 · 상세 항목 표 |

**택배 연동 = 배송 추적만** — 송장 자동 발번 **없음**(브랜드가 자기 택배사에서 발급) · 배송 추적·**배송완료 자동 전환 있음** · 반품 회수 접수 **없음**. 「송장은 사람이 넣고, 그다음부터는 시스템이 따라간다.」 `ui-partner-06`의 「택배 연동 준비중」(발번·회수)과 어긋나지 않는다.

**설계 원리** — 돈의 **시점**(구매확정 D+7 · 정산)과 **방향**(환불)에 영향을 주는 상태 전환은 **이해당사자가 만지지 않는다 — 자동 아니면 운영자다.** 배송완료 처리 · 반송 후속 · 환불 집행이 전부 이 원칙을 따르고, 그런 판단(취소 요청 승인)은 **근거가 보이는 상세 모달에서만** 한다.

### 34-2. 화면 공통 — 요약 바 · 조회 조건 · 일괄 액션 바 — `FE`

**처리 대기 요약 바 5칸** — `준비 시작`(신규) · `송장 등록`(상품준비중) · `배송 이상`(집화 확인 필요 + 추적 정지 + 반송중 **합산**) · `입고 확인` · `재발송·교환`(뒤 둘은 반품·교환 관리). **「배송완료 처리」 칸은 없다** — 자동 전환이라 상시 대기 항목이 아니다. 요약은 손댈 일이 있는지만 알리고 구분은 목록이 한다. 탭 카운트와 **동시 갱신**.

**조회 조건**

| 항목 | 값 |
| --- | --- |
| 조회 기준 | **결제일**(기본) / 발주확인일 / 발송처리일 / 배송완료일 / 구매확정일 |
| 프리셋 | 오늘 · 7일 · 1개월 · 3개월 · 직접 입력 — **최대 1년**(초과 조회 불가 · 필드 옆 고지) |
| 검색 | **타입 선택 후 입력** — 주문번호 · 수취인명 · 송장번호 · 상품명 |
| 결과 요약 | `총 N건 · 조회기간 ~` — **기간을 함께 적는다** |
| 검색 결과 없음 | 탭·조건 유지 · 결과 영역만 교체 · **요약 바는 전체 기준이라 숫자 유지** |

**조회 기준 명칭이 버튼 라벨과 다른 이유** — `준비 시작`·`송장 등록`은 **지금 할 행동**이고 「발주확인일·발송처리일」은 **이미 기록된 시각의 이름**이다. 정산·CS 업계 명칭과 맞춘다.

**일괄 액션 바** — 표 위 **상시 노출**(하단 플로팅 바 폐기) · 선택 0건에도 **비활성으로 자리 유지** · 좌측 = 그 탭 전용 액션(행·상세와 **같은 라벨**) · 우측 = 선택 무관 **항상 활성** · 선택 건수는 버튼 옆.

### 34-5. 상품준비중 — 송장 등록 — `FE`·`BE`

**송장은 목록 셀에 직접 입력한다**(rev.5) — 발주서·택배사 화면과 **대조하며 옮겨 적는 일**이라 모달이 목록을 가리면 안 된다. 그리드 모달(rev.4 E2b)은 **폐기** — 같은 일을 하는 화면이 둘이면 정본이 흐려진다.

| 항목 | 규칙 |
| --- | --- |
| **입력 ≠ 확정** | 셀 입력은 **클라이언트 임시값** · **`N건 송장 등록`** 클릭으로만 배송중 전환 — 배송중 전환은 **소비자에게 송장이 전달되는** 사건이다 |
| 표시 | 입력 행 **배경 톤** · 버튼에 **유효 행 건수** + 「오류 N건 제외」 |
| 택배사 | **목록에서만 선택** — CJ대한통운 · 롯데택배 · 한진택배 · 우체국택배 · 경동택배 · 대신택배 · 로젠택배 · 합동택배 · 쿠팡택배 · 우리택배 · CU편의점택배(사용 빈도순 · **11종 확정**, rev.4). **자유 입력·「미지원 택배사」 없음** — 연동 지원 택배사만 노출되므로 추적 불가 송장이 애초에 등록되지 않는다. 발주서 모달도 같은 목록 |
| 택배사 일괄 적용 | 헤더 셀렉트 + `전 행에 적용` |
| 확정 결과 | 모달 없이 **상단 결과 배너**(몇 건이 어디로 · `배송중 탭에서 확인`) · 탭 카운트·요약 바 동시 갱신 · 미입력 행 유지 |
| 상세 모달 | 송장 입력은 **우 레일 인라인**(모달 안 모달 금지) · 미입력은 에러 없이 `등록` 비활성 |

**검사 — 시점 4단**

| 시점 | 검사 | 서버 |
| --- | --- | --- |
| ① 입력 중 | **정제만** — 공백·하이픈 자동 제거 · 숫자 외 입력 차단 | 없음 |
| ② 포커스 아웃 | **형식**(자릿수·체크디지트) · **화면 내 중복** | 없음(형식은 연동 업체 규칙) |
| ③ `송장 등록` 클릭 | **전역 중복** · **주문 상태 재확인**(그 사이 취소 가능) | **있음** |
| ④ 등록 후 24시간 | 추적 조회 실패 → **집화 확인 필요**(§34-6) | 배치 |

**강도 — 2단**

| 강도 | 대상 | 표현 |
| --- | --- | --- |
| **하드 차단** | 화면 내·전역 중복 · **형식(자릿수·체크디지트)** · 택배사 미선택 · 주문 상태 변경 | 위험 테두리 + 인라인 문구 · **그 행만 제외하고 나머지는 등록** |
| 표시 없음 | 빈 값 | **조용히 확정 대상에서만 제외**(필수 미입력은 에러 없이 — 전역 규칙) |

| 문구 | 값 |
| --- | --- |
| 전역 중복 | 「**ORD-NNNNN에 이미 등록된 번호입니다**」 — **겹치는 주문을 지목**한다(지목하지 않으면 어느 쪽을 고칠지 모른다) |
| 형식 오류 | 「**송장번호 형식이 올바르지 않습니다. 다시 확인해 주세요.**」 — 자릿수인지 체크디지트인지 **구분하지 않는다** |

**형식을 하드 차단으로 바꾼 이유(rev.4)** — 택배사별 자릿수 표를 **하드코딩하지 않고 연동 업체가 최신 규칙으로 판정**(무과금)한다. 송장번호는 **체크디지트**라 숫자 하나만 틀려도 잡힌다 — 오타를 통과시킬 이유가 없다. 「택배사가 번호 체계를 바꿀 수 있어 경고만」이던 rev.2~3 규칙은 **폐기**.

**엑셀 일괄 업로드**

| 단계 | 규칙 |
| --- | --- |
| 파일 선택(E2) | 툴바에서 **항상 열림** · `송장 업로드 양식 받기` · **xlsx · 최대 1,000행** · 필수 = 주문번호 + 송장번호 |
| 검증(E3) | **부분 성공 허용** — 오류는 **행 번호 · 주문번호 · 사유** + `오류 건만 엑셀로 받기` |
| **`N건 목록에 채우기`** | **상태를 바꾸지 않고 셀만 채운다**(rev.5) — 라벨이 「등록」이 아니라 「채우기」인 이유 |
| 채운 뒤 | 채워진 행 **전부 선택 상태** → 확인 후 **`N건 송장 등록`** — 수기 입력과 **같은 확정 지점** |
| 완료(E4) | 결과 요약 · 오류·신규 건 재업로드 안내 |

**신규 주문은 업로드에서 제외한다(rev.7)** — rev.4의 「송장이 있으면 이미 출고 → 신규도 배송중 전환」을 **철회.** ① 신규는 소비자 단순 취소권이 살아 있는 구간이고 파일 한 번으로 수십 건의 권리가 닫힌다 ② 배송중 → 준비중 복귀 경로가 없다 ③ 신규에 남은 건은 발주서를 거치지 않은 **예외 건**이다. E3에서 **「신규(준비 대기) 주문 · 준비 시작 전이라 송장을 등록할 수 없습니다」**로 분류하고 신규 탭에서 먼저 처리하게 한다.

**E3 제외 사유(시안)** — 이미 배송중인 주문 · 송장번호 중복(겹치는 주문 병기) · 주문번호 없음 · 신규(준비 대기) 주문.

### 34-6. 배송 추적 · 배송 이상 · 반송 — `BE`

**배송 이상 2단(rev.4 확정)**

| 단 | 조건 | 배지 | 브랜드 |
| --- | --- | --- | --- |
| 1 | 송장 등록 후 **24시간** 추적 미조회 | **집화 확인 필요**(경고) | 목록 **송장 셀 편집 가능** + `수정` · 상세 **`송장 수정` 주 액션** |
| 2 | **집화 후 7일** 갱신 없음 | **추적 정지**(위험) | 목록 액션 없음 · 상세 `송장 수정` |

| 항목 | 규칙 |
| --- | --- |
| **24시간인 이유** | 집화 스캔 전에는 데이터가 없는 게 정상이라 등록 직후 경고하면 **전부 경고**가 된다 |
| 3단 → 2단 | 형식 오류가 **등록 시점에 이미 차단**되므로 24시간 미조회는 **픽업이 안 된 것**이다. 「송장 확인 필요(24h)」·「집화 지연(72h)」을 **「집화 확인 필요」 하나**로 합쳤다. 형식은 맞지만 **다른 주문의 송장을 붙여넣은** 경우가 남아 수정은 유지 |
| **경고 배지 = 편집 권한** | 배송중 송장 셀은 **기본 읽기 전용**, 「집화 확인 필요」 행만 편집 |
| 2단 명칭 | **「배송 지연」 금지** — 발송기한(브랜드 의무)과 혼동된다. 추적 정지는 **택배사 데이터가 멈춘 상태** |
| **추적 정지 처리** | **플랫폼은 분실·누락 판정에 관여하지 않는다**(약관 제17조③) — 택배사 조회는 소비자·브랜드가 직접. **누락** = 택배사가 배송완료 처리 · **분실** = 브랜드 재발송 후 `송장 수정` · 분실 보상은 택배사↔브랜드. **분실 신고·증빙 폼 폐기**(rev.6) |
| 송장 수정 | **배송완료 전까지** · **수정 이력 기록** · 반송중은 불가 |
| 발송기한 경과와의 관계 | **별 축** — 한 행에 둘 다 뜰 수 있다(늦게 보낸 데다 픽업도 안 된 건) |

**반송중**

| 항목 | 규칙 |
| --- | --- |
| 감지 | 연동 업체 **반송 코드** → 자동 · **별 탭**(배송중에 섞이면 구분 불가) |
| **구매확정** | **불가** — 타이머 **취소** + **정산 대상 제외**(약관 제17조③) |
| 종결 | **환불로 종결** · 이 주문으로 **재발송하지 않음** · 원하면 소비자가 새로 주문 |
| 반송 완료 | 입고도 **자동 감지** → **운영자 큐 자동 편입** · 환불은 운영자 |
| 브랜드 액션 | **없음** — 임의 재발송은 소비자 의사와 어긋날 수 있다 |
| 송장 수정 | **불가**(목록·상세) |
| **반송 사유** | **표시하지 않는다** — API는 **반송 코드와 시각만** 준다. 화면에는 **반송 사실 · 감지 시각 · 구매확정 불가**만 쓰고 사유는 택배사 직접 조회로 안내 |
| 상세 문구 | 「이 주문은 구매확정되지 않습니다 … 환불로 종결되며, 소비자가 다시 받길 원하면 새로 주문해야 합니다」 · 「환불은 운영자가 실행합니다 — 이 주문으로는 재발송하지 않습니다」 |

### 34-7. 배송완료 · 구매확정 — `BE`

**배송완료 — 브랜드가 관여하지 않는다(rev.8)**

| 경로 | 처리 | 출처 |
| --- | --- | --- |
| 정상 | **추적 API 자동 전환** · 구매확정 카운트 시작 | **(자동 확인)** |
| 예외 | **운영자 직권 처리** — 어드민 · 처리자·입력 시각 기록 | **(운영자 처리)** |
| 브랜드 | **버튼·요청 창구 전부 없음** — `배송완료 처리 요청`·`배송완료 수기 처리`·요청 모달 삭제 | — |

**요청 창구조차 두지 않는 이유** — 브랜드가 날짜를 **제안만 할 수 있어도** 협상 여지가 생기고, 그 날짜가 **구매확정 D+7(청약철회 기간)과 정산 시점**을 움직인다. 앞당기면 브랜드에게 **직접 이익**이다.

| 항목 | 규칙 |
| --- | --- |
| **출처 병기** | 배송완료일시 옆에 **항상** — 상세·이력 양쪽. 구매확정·정산의 **기준값**이라 신뢰도가 보여야 한다 |
| 운영자 처리 건 고지 | 「소비자가 실제 수령일과 다르다고 이의를 제기하면 구매확정일과 정산 시점이 조정될 수 있습니다」 |
| 소비자 이의 | **연결·소통 스레드**에서 운영자 중재 → **배송완료일 직권 정정**(약관 제19조②). 브랜드 정정 경로 없음 |
| 구매확정 | 배송완료 + **7일** 자동(약관 제19조①) · 배송완료 탭 주인공은 **구매확정 예정 D-N** |
| 구매확정 탭 정산 열 | `정산 대상 · 공구 종결 후 일괄` / `구매확정 후 클레임 · 클레임 종결 후 재산정` / `정산 완료 · 이체일` |
| **구매확정 ≠ 정산 완료** | 정산은 공구의 **모든 주문 항목 종결 후 일괄**(정산체계 v1.1 · 약관 제21조①). 확정 후 클레임도 정산 전일 수 있어 **중립 배지** |
| 사후 클레임 | 확정 후에도 **하자·오배송·광고와 다름**은 반품·교환 가능(증빙 필수 · 단순변심 불가 · 약관 제19조③) — 접수 기한 `[근거 대기]` |

### 34-8. 취소 — 3경로 — `FE`·`BE`

| 경로 | 시점 | 처리 | 취소율 | 취소 탭 표기 |
| --- | --- | --- | --- | --- |
| **소비자 취소** | 준비 시작 **전** | **PG 자동 취소** — 브랜드·운영자 개입 없음 · 재고 원복 | 미반영 | 소비자 취소 · 준비 시작 전 |
| **취소 요청 → 승인** | 준비 시작 **후** | 브랜드 승인 → **환불은 운영자** | **미반영** | 취소 요청 승인 · 브랜드 승인 |
| **브랜드 직권 취소** | 상품준비중 | 브랜드(품절·하자) → **환불은 운영자** | **반영** | 브랜드 직권 취소 · {사유} |

**환불은 브랜드가 절대 실행하지 않는다** — 어느 경로든 **운영자 집행**. 세 모달(직권 취소 · 승인 · 거부) 모두 같은 문구.

**직권 취소(E5)**

| 항목 | 규칙 |
| --- | --- |
| 사유(필수) | 품절 · 상품 하자 · 배송 불가 지역 · 기타(직접 입력) |
| 소비자 설명 | 입력 — **사유와 함께 소비자에게 그대로 전달**(약관 제18조②) |
| 고지 | 되돌릴 수 없음 · 환불 운영자 · **취소율 반영 · 반복 시 제재** `[근거 대기]` |
| 버튼 | **진입 버튼은 중립**(목록 `판매 취소` 보조 · 상세 `주문 취소` 텍스트) — 품절 대응은 정상 업무다. 위험색이면 매일 누르는 버튼이 매일 경고가 된다. **E5 실행 버튼만 위험색**(되돌릴 수 없는 확정) |
| ⚠️ 가능 단계 | 약관 = **상품준비중에 한함** ↔ 시안 = **신규 탭 일괄 바에도 `판매 취소`** — §34-13 #1 |

**취소 요청 — 주문 단위 이동 · 상세 판단(rev.5)**

| 항목 | 규칙 |
| --- | --- |
| 사유 | **소비자 앱 4택 그대로** — 단순 변심 · 주문 실수 · 다른 결제 수단으로 변경 · 기타(**기타만 자유 입력**, 사유 아래 보조 줄). 브랜드 화면이 선택지를 따로 만들지 않는다 |
| **들어올 때** | 항목 **하나만** 요청돼도 **주문 전체가 취소 요청 탭으로** — 항목별로 갈리면 한 주문이 두 탭에 걸려 **남은 항목을 발송하면서 요청을 놓친다** |
| 목록 | 상품 열에 「**3건 중 1건 요청 · 남은 2건 발송 대기**」 · **경과** 열 · 관리 `요청 확인` 하나 |
| **목록 처리 폐기** | 체크박스 · 일괄 바 · 처리 드롭다운 · 거부 사유 열 **삭제**(rev.7 목록 처리 → rev.5 상세 이관) — 송장은 판단 없는 **옮겨 적기**라 목록에 두지만, 취소 승인은 **돈이 나가는 판단**이다 |
| **일괄 처리** | **없다** — 건별 근거가 다른 판단을 묶으면 검토가 형식이 된다 |
| 상세(C11) | 요청 블록 최상단(요청자 · 사유 · 일시 · **준비 시작 후 경과**) · **요청 대상 항목만 경고 톤 + 「취소 요청」 배지** · 금액 요약에 **취소 요청분 별 행** · 우 레일에 **처리 후 이동 탭** · 「어느 쪽도 기본값이 아니니 출고 상황을 보고 판단하세요」 |
| **승인(E6)** | 주 액션 · 확인 모달 경유(즉시 실행 안 함) · **요청 항목만 취소 · 남은 항목 발송** · 환불 예정액(요청분/총액) · 취소율 미반영 · 「이미 출고했다면 거부하고 반품 안내」 |
| **거부(E7)** | **사유 필수**(소비자에게 그대로 전달 — 약관 제18조①) · 전 항목 배송 진행 · 소비자는 **수령 후 반품으로만**(반품비 발생) 고지 |
| **나갈 때** | 승인·거부 모두 **원래 탭 복귀**(준비 시작 전 = 신규 · 후 = 상품준비중). **전 항목 승인일 때만 취소 탭** |

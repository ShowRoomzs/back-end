주문 내역으로

요청 → 확인 모달 → 접수 화면 — 모든 항목을 채우고 CTA를 누르면 확인 모달("반품을 요청할까요?" · [닫기] / [반품 요청하기])이 뜨고, 확정하면 접수 화면으로 바뀝니다(눌러 보세요). 접수 화면은 반품 방법 박스(직접 발송 · 송장 입력 완료 / 나중에 입력) → 안내 → 반품 신청 정보 → 환불 정보 → 반품 상품 → [반품 상세] [주문 내역으로] 순입니다. 제목은 "완료"가 아니라 "접수" — 검수 전이라 환불이 확정되지 않았기 때문입니다. 나중에 입력을 골랐다면 "7일 안에 송장을 등록하지 않으면 요청이 자동 취소돼요"를 굵게 덧붙입니다. 무신사의 [계속 쇼핑하기] 대신 [주문 내역으로]를 둔 것은 주문 취소 접수 화면과 같은 규칙입니다.

직접 발송만 둡니다 — 배송 API가 추적 전용이라 수거 예약이 불가능합니다. "수거 요청"을 선택지로 남겨 두면 사용자는 기사님을 기다리는데 아무도 오지 않는 사고가 납니다. 방법이 하나라 라디오를 누를 필요는 없지만, 선택된 상태로 보여 "이게 유일한 방법"이라는 점을 분명히 합니다.

송장 입력 = 추적 시작 — 택배사 + 송장 번호를 넣으면 추적 API가 회수 상황(집하 → 이동 → 브랜드 도착)을 받아 C10-1 상태에 반영합니다. 아직 부치지 않았으면 [나중에 입력하기]로 요청만 먼저 접수하고, 7일 안에 입력이 없으면 자동 취소됩니다(입력 칸이 회색으로 잠김). 요청 후 입력은 C10-1 반품 상세의 [송장 입력]에서 합니다.

귀책에 따라 달라지는 것 — 사유를 고르는 순간 아래 세 곳이 함께 바뀝니다: 상세 내용(브랜드 귀책일 때만, 필수) · 사진(선택) · 택배비 안내(고객 귀책 = 선불 직접 결제 / 브랜드 귀책 = 착불) · 배송비 차감(3,000원 / 없음). 결과가 CTA 라벨에 그대로 들어가 결제 전에 금액을 한 번 더 확인합니다.

CTA — 빠진 항목을 버튼 라벨이 순서대로 알려주고, 다 채우면 "반품 요청하기 (1개 · 3,000원 차감)" 형태가 됩니다. 상품을 모두 해제하면 "반품할 상품을 선택해 주세요".

남은 결정 — ① 반송 택배비 착불 수락 여부는 브랜드별로 달라 브랜드 설정값으로 받을지 ② 부분 반품 시 무료배송 조건 재계산 규칙 ③ 차감 문구·청약철회 제한 법무 확정.

재발송 배송비 결제 — 주문 실수처럼 고객 귀책일 때만 금액 아래에 결제 수단(C9와 같은 신용·체크카드 / 간편결제 두 갈래 — 카드는 카드사 시트, 간편결제는 3종)이 생기고, 고르기 전에는 CTA가 "결제 수단을 선택해 주세요"입니다. 확인 모달 → 선택한 간편결제의 외부 결제창 → 성공 시 접수 화면, 취소·실패 시 요청 화면으로 돌아와 §07 토스트("결제가 완료되지 않았어요")를 띄우고 입력 내용은 유지합니다. 외부 결제창은 우리가 그리지 않으므로 회색 자리표시와 두 결과 버튼으로만 표현했습니다(눌러 보세요). 주문 결제 수단으로 자동 결제하려면 빌링키가 필요해 쓰지 않습니다. 브랜드 귀책이면 0원이라 결제 수단·결제창 없이 바로 접수됩니다.

받을 곳 [배송지 변경] → C13-2 배송지 선택 페이지(시트 아님)로 이동하고, 고르면 이 화면으로 돌아옵니다.

요청 → 확인 모달 → 접수 화면 — 1a와 같은 흐름입니다. 접수 화면의 금액 섹션은 환불이 아니라 결제 정보(재발송 배송비)이고, 교환 상품 행에 받은 옵션(취소선) → 새 옵션을 두 줄로 보여줍니다. 버튼은 [교환 상세] [주문 내역으로].

옵션은 상품 행 아래에서 고릅니다 — 선택한 상품마다 [교환할 옵션] 드롭다운이 붙고, 누르면 시트가 열립니다. 시트는 C7 옵션 시트와 같은 규격(묶인 목록 · 품절 회색 + "품절" 텍스트)이고, 지금 받은 옵션도 고를 수 있습니다("받은 옵션 · 같은 옵션으로 다시 받기") — 파손·불량·오배송이면 같은 상품을 새로 받아야 하기 때문입니다. 단순 변심·주문 실수인데 같은 옵션을 고르면 교환할 이유가 없으므로 CTA가 "같은 옵션은 불량 · 오배송일 때만 교환돼요"로 막힙니다. 고른 뒤 [변경하기]를 눌러야 반영돼, 목록을 스크롤하다 잘못 누른 것이 바로 적용되지 않습니다.

반품과 같은 문법 — 사유 → 방법(직접 발송) → 신청 정보 → 금액 → CTA 순서와 모든 컴포넌트를 1a와 공유합니다. 다른 점은 두 가지입니다: 신청 정보에 받을 곳(새 상품 배송지, 변경 가능)이 추가되고, 금액 섹션이 환불이 아니라 결제입니다.

재발송 배송비 — 주문 실수면 새 상품을 보내는 3,000원을 요청 시점에 결제합니다(주문 결제 수단으로). 나중에 받으면 검수 후 재발송이 결제 대기로 멈추기 때문입니다(C10-1의 "재발송 배송비 결제 대기" 상태가 그 경우). 이때 CTA는 "3,000원 결제하고 교환 요청하기"가 됩니다. 브랜드 귀책이면 0원 · 착불 안내로 바뀝니다.

남은 결정 — ① 교환 옵션 간 가격이 다를 때(차액 결제/환불) 허용 여부 — 현재는 같은 가격 옵션만 노출 가정 ② 교환 재고 확보 시점(요청 시 선점 vs 검수 후 확인) ③ 반송 착불 수락 여부 브랜드별 설정.

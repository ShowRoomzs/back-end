## 19. 어드민 FAQ 관리 — [v0.27 신설]

대상 화면: `ui-admin-08-faq.html` (**rev.2**), 상태 3종(목록 1 · 모달 2). 셸·테이블·모달·배지는 §16 컴포넌트를 재사용했다. 근거 와이어는 `wf-admin-08-CS콘텐츠관리` F5~F10 중 FAQ 부분.

> **[v0.27] 파일 분리** — 기존 계획의 `ui-admin-08-cs-content.html`(FAQ·공지·약관 통합) 대신 **`ui-admin-08-faq` / `ui-admin-09-notice` / `ui-admin-10-terms` 3개 파일**로 나눴다. 세 화면은 데이터 구조·액션·법적 성격이 모두 달라(FAQ=순서 있는 목록 / 공지=게시 기간 / 약관=버전 이력) 한 파일로 묶을 이유가 없다. §17·§18의 상호참조도 이 기준으로 읽는다.
> 

**성격 — 심사도 답변도 없는 운영자 정적 콘텐츠.** §17·§18이 **소비자가 만든 데이터를 운영자가 처리**하는 화면인 반면, FAQ는 **운영자가 직접 만드는 콘텐츠**다. 그래서 상태·심사·통지·SLA가 전부 없고 액션은 등록·수정·삭제·순서 조정 4가지뿐이다. 도메인모델 §12의 비즈니스 규칙도 **"FAQ·공지는 별도 정적 콘텐츠(문의와 무관)"**로 이미 분리해 두었다.

### 19-3. 상세 페이지를 두지 않는다 — `FE`

| 액션 | 처리 방식 |
| --- | --- |
| 등록 | **모달** |
| 수정 | **모달** — 등록 모달과 같은 폼, 초기값만 다름 |
| 삭제 | **확인 모달** |

**근거** — FAQ 항목당 필드는 **카테고리·질문·답변 3개뿐**이다. 상세 페이지를 만들면 목록 → 상세 → 수정으로 3단계가 되어 운영 비용만 늘어난다. 처리 이력·상태 전이가 없어 상세 페이지에 채울 정보도 없다.

> 다른 어드민 화면의 **"행 클릭 → 상세" 패턴을 이 화면에 적용하지 않는다.**
> 

### 19-4. 순서 조정 — 드래그 핸들 — `FE`·`BE`

| 항목 | 규칙 |
| --- | --- |
| 조작 방식 | 행 맨 앞 **핸들을 잡고 끌어 놓는다**. 핸들 위에서 커서가 grab으로 바뀐다 |
| 드롭 위치 표시 | 행 경계에 **인디고 선** |
| **저장 시점** | **놓는 즉시 저장.** 별도 저장 버튼을 두지 않는다 |
| **적용 범위** | **카테고리 내에서만 유효.** 전체 통합 순서를 두지 않는다 |
| 신규 등록 시 | 해당 카테고리 **맨 위**에 배치 |
| 삭제 시 | 같은 카테고리 남은 항목의 순서가 **자동으로 당겨진다** |
| 실패 처리 | 순서 갱신 요청이 실패하면 **원위치로 되돌린다**(`FE`) |

**드래그로 정한 이유** — 상하 버튼은 한 칸씩만 움직여 6번째를 1번으로 올리는 데 5번 클릭이 필요하다. 순번 직접 입력은 중복·누락 검증이 붙는다. 즉시 저장으로 둔 이유는 **"옮기고 저장 안 함" 상태**를 만들지 않기 위해서다 — FAQ 순서는 되돌릴 위험이 낮은 조작이다.

**카테고리 내로 한정한 이유** — 전체 통합 순서를 두면 카테고리 탭을 옮길 때마다 순서가 뒤섞여 보인다.

### 19-5. 등록·수정 — `FE`·`BE`

| 필드 | 필수 | 형식 |
| --- | --- | --- |
| 카테고리 | **필수** | 셀렉트(초기값 `선택`) · 5종 |
| 질문 | **필수** | 단일 인풋 |
| 답변 | **필수** | 텍스트에어리어 |

| 항목 | 규칙 |
| --- | --- |
| 미입력 처리 | **에러 문구 없이 저장 버튼 비활성만** — §17·§18과 동일 원칙 |
| 노출 시점 | **등록 = 즉시 노출.** 게시/미게시 상태를 두지 않는다 |
| 노출 대상 | 답변 본문이 **소비자 앱 고객센터에 그대로** 실린다 |
| 질문 작성 원칙 | **소비자가 검색할 표현으로 작성한다** — 운영자 내부 용어로 쓰면 검색에 걸리지 않아 FAQ가 있어도 1:1 문의로 유입된다 |
| 수정 이력 | **수정일만 갱신.** 변경 전 내용을 이력으로 남기지 않는다(약관과 다른 점 — 19-7) |

**게시/미게시 상태를 두지 않는 이유** — 초안 보관 수요가 확인되지 않았다. 필요해지면 그때 추가한다.

### 19-6. 삭제 — `FE`·`BE`

| 항목 | 규칙 |
| --- | --- |
| 확인 모달 | **필수** · 소형(입력 필드 없음) |
| 모달 본문 | **대상 질문 원문을 문장에 넣는다** |
| **사유 입력** | **없다** |
| 집행 결과 | 소비자 앱 고객센터에서 **즉시 사라진다** |
| 복구 | **불가** |
| 순서 | 같은 카테고리 남은 항목이 자동으로 당겨진다 |

**질문 원문을 모달에 넣는 이유** — 행이 6개 이상이면 어느 행의 삭제 버튼을 눌렀는지 헷갈린다. 대상이 문장에 박혀 있으면 오삭제를 막는다.

**사유를 받지 않는 이유** — **운영자가 만든 정적 콘텐츠**다. 소비자 게시물 삭제(§18-5)와 달리 소명할 상대가 없다.

**이 섹션이 §36-8의 「20b 수령 후 이어 붙인다」를 대신한다.** 이슈 스레드는 정산 금액을 바꾸는 **유일한 경로**라 소통 스레드(§36)가 아니라 정산 옆에 둔다 — 1:1 운영팀 채널은 §36, 결과가 반영되는 정산 화면은 §41 · §43~§45다.

**개정 이력** — 2026.10.06 **전면 개정**(「계약 이행 확인 · 미이행 → 운영자 중재 의견 → 동의/반대」 구조 폐기) · 2026.10.07 **근거 첨부 삭제**. 파트너 rev.1~4 · 스튜디오 rev.1의 중재 구조(중재 의견 카드 · 「중재」 태그 · 운영자 말풍선 · 반대 사유 필수 모달)는 폐기된 이력이다.

### 42-1. 입구 — 정산 조정 요청 — `FE`·`BE`

| 항목 | 규칙 |
| --- | --- |
| 누가 | **브랜드 · 인플루언서 누구나** — 운영자는 요청하지 않는다 |
| 언제 | **정산 확인 기간**(§41-3)에만 — 정산 관리 상세의 `[정산 조정 요청]`(파트너 13 D2 · 스튜디오 12 D1) |
| 입력 | **조정할 리워드 금액(필수) · 사유(필수)** 둘뿐 — 바꿀 수 있는 것은 **인플루언서 리워드 하나**다 |
| 자동 계산 | 금액을 넣으면 바로 보인다 — 파트너: 인플루언서 실지급(원천징수 후) · 브랜드 수취액 원래 → 변경 / 스튜디오: 원천징수 · **실지급액(요청 시)** · 원래 실지급액 대비 ± |
| **범위** | 0 이상 ~ **조정 후 브랜드 수취액이 0 미만이 되지 않는 값** — 상한 = (확정 거래액 − PG 수수료 − 플랫폼 수수료) ÷ 1.1(리워드 부가세 포함) · 10원 미만 절사(파트너 13 C1) — 산식·절사 최종 확인 필요(§46 B-1 · X-02) |
| 비활성 | 범위 밖이거나 사유가 비면 **에러 문구 없이 버튼 비활성** |
| 보낸 뒤 | 정산 **전액 보류**(조정 협의) + **이슈 스레드 자동 개설** · 첫 글 = 조정 요청 카드 · **차액 선지급 없음** |
| 요청이 없으면 | **원래 금액으로 정산**한다 — 간주 규칙이 필요 없다 |
| 계약 위반 기록 | **남지 않는다** — 조정 요청은 금액 이야기다. 제재(파트너 제25조)는 운영자가 직접 확인한 사유로만 한다 |
| 횟수 | 정산 1건에 협의 1건 — 종결 후 **같은 사안 재요청 불가**(정산이 공구당 1건이라 「다음 확인 기간」도 없다) |

**입구가 「미이행」이 아니라 「조정 요청」인 이유** — 미이행은 **상대가 계약을 어겼다는 판정**이라 협의 전에 감정을 상하게 하고, 금액은 나중에 따로 정해야 했다. 조정 요청은 **처음부터 금액 이야기**라 상대가 바로 동의할 수 있다.

**근거 첨부를 뺀 이유(2026.10.07)** — ① 근거를 받아 판정하는 주체가 없다(운영팀은 열람만 · 양측 직접 합의) ② 말풍선에 이미 첨부가 있어 요청에도 두면 **파일 올리는 곳이 두 군데**가 되고 무엇이 근거인지 흐려진다 ③ 파일 저장 · 형식/용량 검사 · 에러 문구가 요청 데이터에 붙고, 다른 금액 제안에도 같은 칸을 둘지 매번 갈린다. **근거 자료는 요청 직후 요청자의 일반 말풍선 첨부**로 올린다(첨부 규칙은 (1) §13-7~§13-11). 운영팀도 근거는 스레드 대화에서 열람한다.

### 42-2. 응답 3종 · 차례 — `FE`·`BE`

| 응답 | 입력 | 결과 | 버튼 |
| --- | --- | --- | --- |
| **동의** | 없음 · **불가역** | **금액 변경 + 보류 해제 + 이슈 종결**이 시스템에서 동시에 — 운영자 승인 없음 | 주 액션(인디고) |
| **다른 금액 제안** | 금액(필수 · 같은 범위) · 사유(선택) | **새 요청**이 된다 — 처음 요청한 쪽이 답할 차례 · 합의 기한은 **늘어나지 않는다** | 보조 |
| **반대** | **사유 없음** — 확인 모달만 · 의견은 대화로 | 요청 금액 미반영 · **보류 계속** · 협의는 합의 기한까지 이어진다 | 보조 — **위험색을 쓰지 않는다**(종결이 아니다) |

| 항목 | 규칙 |
| --- | --- |
| **버튼은 최신 요청 카드에만** | 이전 요청 카드는 **응답 결과로 굳는다**(「다른 금액 제안으로 응답됨」) · 내가 보낸 요청 카드에는 처음부터 버튼이 없다 |
| 차례 | 받은 쪽 = **내 응답 필요(경고)** · 보낸 쪽 = **상대 응답 대기(정보)** |
| 동의 모달(C2) | **바뀔 금액을 숫자로 먼저** 보인다 · 「동의하면 되돌릴 수 없습니다」 · 종결 후 같은 사안 재요청 불가 · 감액에 동의하는 경우 **내 리워드가 줄어든다는 사실을 숨기지 않는다**(스튜디오) |
| 반대 모달(C3) | **결과를 먼저 말한다** — 요청 금액 미반영 · 보류 계속 · 기한까지 협의 · **기한까지 합의가 없으면 원래 금액 확정** · 「반대 이유는 스레드 대화로 남겨 주세요」 · 모달 확정 버튼도 **인디고**(세 모달 공통 · 위험색 없음) |
| 반대가 확인을 받는 이유 | 반대는 **보류를 계속시키는 응답**이라 결과를 누르기 전에 알아야 한다 — 스튜디오 rev.1의 「반대 사유 필수 모달」은 폐기 |
| 반대 뒤 | 종결이 아니다 — 응답자는 나중에 동의·다른 금액 제안으로 바꿀 수 있고(파트너 C3), 요청자는 다시 제안할 수 있다(스튜디오 C3). **반대 이후의 차례·버튼 화면은 시안에 없다** → §46 A-9 |
| 제안 모달(C1) | 원래 리워드 · 상대 요청 · 합의 기한을 상단에 · 「0원 ~ {상한}원 안에서 입력할 수 있습니다」 · 「제안하면 {상대}가 응답할 차례가 됩니다. 합의 기한은 늘어나지 않습니다.」 |

### 42-3. 합의 기한 · 종결 2종 — `BE`

| 항목 | 규칙 |
| --- | --- |
| **합의 기한** | **개설 + 10영업일**(주말·공휴일 제외) · 마감 23:59(어드민 — 파트너·스튜디오 시안은 18:00 · §46 B-4) |
| 연장 | **없다** — 몇 번을 주고받아도 기한은 그대로다 |
| D-N | **영업일 기준 남은 일수**(예: 09.04 기준 09.17 마감 = D-9) |
| D-1 통지 | 시스템 카드 + 양측 통지 「{기한}까지 합의가 없으면 원래 금액으로 확정됩니다」 — 역일·영업일 기준 미정(§46 B-4) |
| **종결 ① 합의 완료** | 동의 순간 금액 변경 · 보류 해제 · 종결 → 정산 **지급 예정** · 배지 **성공** |
| **종결 ② 기한 만료** | 기한까지 합의 없음 → **원래 계약 금액으로 확정** · 보류 해제 · 종결 · 배지 **중립**(누가 이긴 결과가 아니라 아무도 동의하지 않은 결과) · 반대가 있었어도 같다 |
| 원래 금액이 기본값인 이유 | 계약서가 정한 금액이고, 바꾸려면 **양측 합의**가 필요하다. 더 다투려는 쪽은 **플랫폼 밖 절차**로 간다 |
| **간주 없음** | 「무응답 = 동의」·「무응답 = 반대」 같은 간주 규칙이 없다 — §33-3 D-2 · §36-9 B-10 해소 |
| 종결 후 | 입력창 **잠금**(「종결된 이슈에는 메시지를 보낼 수 없습니다」) · 기록 **삭제하지 않음**(종결 후에도 법령이 정한 기간 보존 — 파트너 제26조④) · 같은 사안 재요청 불가 · 일반 대화는 **1:1 스레드**에서 |
| 정산 반영 | 종결 즉시 정산 관리에 반영 — 운영자 처리 없음(「남은 처리가 없습니다」) |

### 42-4. 운영자 — 열람만 — `FE`·`BE`

| 항목 | 규칙 |
| --- | --- |
| 하는 일 | **없다** — 조정안을 내지도 승인하지도 않는다. 금액을 정하는 주체는 **당사자뿐**이다 |
| 삭제된 것 | 구 M1 조정안 제시 · 구 M2 답변 기한 설정 · 구 M3 이슈 직접 개설 · 중재 의견 카드 · 「중재」 태그 · 이슈 스레드 안의 운영자 말풍선 |
| 어드민 입력창 | 없음 — 자리에 안내 바 「운영팀은 열람만 합니다 — 금액은 양측 합의로만 바뀌고, 합의가 되면 시스템이 즉시 반영합니다.」 |
| 열람 목적 | **CS 문의에 상황을 답하는 용도** — 운영자는 결론을 내지 않고 정산이 멈춘 건을 한눈에 본다 |
| 탭 · GNB 배지 | 이슈 스레드 탭 = **항상 0**(운영자 차례가 없다) · 게시물·소통 GNB 배지는 **1:1 미답만** 센다 |
| 양측 상단 고지 | 파트너 「이슈 스레드입니다 · 금액은 양측 합의로만 바뀌며 SHOWROOMZ 운영팀은 열람만 합니다 · 대화 내용은 분쟁 기록으로 보관됩니다」 / 스튜디오 「금액은 양측 합의로만 바뀌어요. 운영팀은 열람만 해요. · 대화 내용은 분쟁 기록으로 보관돼요.」(어드민 기준 확정 문구) |
| 그 밖의 분쟁 | 게시물 문구 · 일정 · 재발송 · **고정 지급비** 이견은 양측 **1:1 스레드**에서 당사자끼리 풀고 운영자는 관여하지 않는다 · 숨김 해제 · 수정 요청은 **운영팀 1:1 채널**(§36) |
| 약관과의 관계 | 회사가 금액을 정하지 않으므로 인플 제20조④ 「중재 의견에 금액 조정은 포함되지 않는다」의 **취지와는 맞는다** — 그러나 제20조 전체와 파트너 제26조가 **운영자 중재 구조**라 개정이 필요하다(§46 C-1 · C-2) |

### 42-5. 화면 요소 — 고정 카드 · 시스템 카드 · 말풍선 — `FE`

**절차는 시스템 카드, 대화는 말풍선** — 절차가 말풍선에 섞이면 이후 대화에 묻히고, 분쟁 때 「그 안내를 받았는가」가 흐려진다.

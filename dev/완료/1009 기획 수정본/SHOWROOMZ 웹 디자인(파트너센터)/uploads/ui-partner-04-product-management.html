근거: wf-partner-02-상품관리 · 기존 ui-partner-04(rev.24, 인터랙티브 버전) 내용 참고 · 어드민(ui-admin-04) 방식으로 상태별 정적 화면 전환

[재제작 사유] 기존 파일은 실제 동작하는 JS 프로토타입(등록·수정·삭제 로직 연결)이라 작은 수정 하나에도 전체 로직을 다시 이해해야 해서 수정 비용이 컸음. 어드민(ui-admin-04)과 동일하게 상태별 정적 화면으로 전환 — 각 상태는 독립된 스냅샷이며 서로 연결되지 않음(클릭해도 동작 안 함).
[단순화] 상품 설명은 Quill 에디터 대신 정적 미리보기 텍스트로 표현(실제 리치텍스트 편집 로직은 프로덕션 구현 시 김태호 확인). 이미지 업로드·옵션 그룹 추가/삭제 등 인터랙션도 정적 스냅샷으로만 표현.
[신규 규칙 반영] 진행중 공구에 연결된 상품이라도 진열 상태가 "미진열"이면 잠금 해제(B4) — 미진열은 소비자에게 노출되지 않아 계약·공구 내용과 어긋날 위험이 없다는 판단. 기존 규칙(진행중 연결 시 재고만 수정)은 진열 중인 상품에만 적용됨. [확인필요] 재검토대기·미진열(요청)도 동일하게 잠금 해제 대상인지 확인 필요 — 우선 미진열만 반영.
[유지] 상품 삭제 차단 범위(공구 상태 준비중·준비완료·진행중·종료)는 이전 확정대로 유지 — 진열 상태와 무관하게 공구 상태만으로 판단.
[rev.26] 입력 필드 포커스 색상 누락 수정(디자인시스템 v1.2 border-color:accent-500 · box-shadow 0 0 0 3px accent-50 반영 — 이전엔 focus 스타일 자체가 정의되지 않아 브라우저 기본값이 뜨고 있었음). 검색 입력·버튼 높이 36px로 통일(버튼만 32px 기본값이라 입력필드보다 작아 보였음). 상품명 100자 제한 + 우측 글자수 카운터 + 이모지 입력 불가 안내 + 특수문자 자제 플레이스홀더, 전 폼 상태에 적용. 정가 필드에 3자리 콤마·최대 9,999,999원 안내 통일. 카테고리 대→중→소 단계적 활성화(상위 미선택 시 하위 select 비활성화, 등록 폼 기준).
[rev.27] B2·B3·B4·B5 수정 폼이 재제작 과정에서 기본정보·가격만 남고 나머지 섹션(카테고리·이미지 전체·옵션 그룹 토글·상품 설명·상품정보제공고시 11필드)이 누락돼 있던 것을 전부 복원 — B1(등록)과 동일한 완전한 섹션 구성으로 통일. 목록 · 검색 결과 없음(A2)에 테이블 헤더가 안 보이던 것 수정(헤더는 유지, 내용 영역만 빈 상태로 교체). 상품 설명을 정적 문단 대신 에디터 목업(툴바+본문 영역)으로 표현 — 실제 리치텍스트 동작은 프로덕션 구현 시 별도. B3(잠금) 카드 전체에 걸려있던 opacity:.7 제거 — 재고 입력필드·취소 버튼 등 잠기지 않은 요소까지 흐려 보이던 문제, 이제 실제로 잠긴 필드만 disabled 스타일로 흐려짐.
[rev.28] 텍스트 범례(list-legend)를 어드민(ui-admin-04)과 동일한 필터 영역(다중선택) 컴포넌트로 교체 — 진열 상태 행(진열/미진열/재검토대기/미진열(요청)) · 공구 상태 행(준비중/준비완료/진행중/연결없음), 우상단 초기화 버튼, 하단 검색 필드+버튼. 목록 상단에 툴바 신설(총 건수+정렬순 좌측, 페이지당 건수 20/50/100건 우측). 정가 다음 열에 재고 열 추가(가운데 정렬, 0이면 회색 "품절" 배지). 등록일·수정일 2열을 1열로 통합해 최신 날짜 + (등록)/(수정) 표시. 목록 행에 마우스 오버 시 하이라이트(배경 인디고 틴트, 상품명 강조) 추가.
[rev.29] 필터 영역 검색 행이 초기화 버튼과 다른 우측 지점에서 끝나던 문제(패널 전체 padding-right:100px)와 검색 입력·버튼 간격 문제(둘이 .search로 묶이지 않아 부모 .fp-row의 14px gap이 적용됨)가 재발해 있던 것을 재수정 — 이전 어드민 작업에서 확인했던 원인과 동일. .tbar-l에 걸려있던 display:flex;gap:8px 제거 — "총 N건" 텍스트가 "총"/숫자/"건" 사이마다 강제로 8px씩 벌어져 있던 근본 원인(플렉스가 텍스트 노드까지 개별 아이템으로 취급). 정렬순 드롭다운을 페이지당 건수 옆(우측)으로 이동. 커버 이미지 예시 색상을 연한 파스텔(#f4b3c5 등)에서 채도 높은 색으로 교체 — 흐려 보이던 원인은 CSS 문제가 아니라 색상 선택 자체였음. B2·B3·B4·B5 수정 폼 우측에 상태 관리·처리 이력 카드 신설(어드민과 동일한 구성이나 액션 버튼은 없는 조회 전용). B3(진행중 잠금)에는 과거 미진열 이력을, B4(미진열 잠금해제)에는 현재 미진열 사유를 우측 패널로 추가 — B5와 함께 미진열 관련 모든 수정 상태에 사유 패널이 노출되도록 통일.
[rev.30] 검색 입력·버튼 높이 재정렬(.search .btn 36px 명시 — 버튼 기본값 32px과 입력필드 36px이 다시 어긋나 있었음). 수정·삭제 버튼에 hover/focus 상태 추가(이전엔 정적이라 마우스 올려도 아무 반응 없었음). 목록 하단 페이지네이션 신설. 옵션 영역을 인터랙티브 버전(업로드해주신 rev.23 파일 기준)으로 복원 — 등록 폼(B1)에 한해 옵션 그룹 추가/삭제, 항목 추가/삭제/드래그 재정렬, 대표 옵션 라디오, 재고·옵션가 콤마 입력, 이미지 업로드(클릭 시 파일 선택) 전부 실제 동작. 수정 폼(B2~B6)은 기존처럼 정적 스냅샷 유지 — 상태별 예시 화면이라는 문서 성격상 5곳 모두에 독립 상태를 두면 관리 비용이 커져, 실제 동작 데모는 등록 폼 하나로 집중. B5의 "사용기한" 필드에 걸려있던 빨간 테두리(border-color:danger-text) 제거 — 기술적 신호 대신 평범한 안내 문구로 대체. 목록 행 클릭(관리 버튼 제외) 시 수정 폼 데모 위치로 스크롤 이동하는 JS 추가. B6 "수정 폼 · 재검토 대기" 상태 신설 — 브랜드 수정 직후 운영자 재검토 대기 배너, 필드는 계속 수정 가능, 미진열 사유 패널은 미노출(미진열 처리가 아니라 정보 수정이 트리거이므로).
[rev.31 · 규칙 명확화] 미진열 = 미진열(요청): 둘 다 진열 상태값은 동일한 "미진열"이며 차이는 미진열 사유뿐(브랜드 요청이면 회색 배지 + 이후 수정해도 재검토 대기로 전환 안 됨, 나머지 3개 사유면 빨강 배지 + 수정 시 재검토 대기 전환). 그 외 소비자 비노출·삭제 차단 조건(공구 상태 기준)·수정 권한은 완전히 동일. 진행중 공구 잠금 해제 범위 명확화: "진열 상태가 미진열이면"이 아니라 "진열 상태가 '진열'이 아니면"이 정확한 조건 — 미진열·미진열(요청)·재검토 대기 3종 전부 공구 진행중과 무관하게 잠금 해제 대상. B4 라벨·안내 문구를 이 기준으로 수정했고, B6(재검토 대기)의 공구 상태를 준비중→진행중으로 바꿔 재검토 대기도 동일하게 잠금 해제됨을 실제로 보여줌. B6 삭제 버튼 비활성 사유도 "재검토 대기라서"가 아니라 "공구 상태(진행중)라서"로 정정 — 삭제 차단은 진열 상태와 무관하게 공구 상태만으로 판단.
[rev.32 · 수정 폼 전면 재구성] 수정 폼을 진열 상태 × 공구 진행 여부 7경우 × 옵션 그룹 사용/미사용 2가지 = 14개 상태(B2~B15)로 재구성. 기존 B2~B8(7개)을 대체한다. 경우 구분은 ①진열·공구 아님 ②진열·공구 진행중 ③미진열·공구 아님 ④미진열·공구 진행중 ⑤미진열(요청)·공구 아님 ⑥미진열(요청)·공구 진행중 ⑦재검토 대기(공구 상태 무관). 각 상태는 .grp-chip으로 옵션 그룹 사용 여부를 표기한다.
[rev.32 · 재고 입력 상시 활성] 이전 버전은 B2·B4·B5·B6의 옵션 표에서 재고 수량이 정적 텍스트로만 표시돼 입력필드가 없었음(잠금 상태인 B3에만 입력필드 존재). 모든 상태에서 재고 수량은 입력필드로 노출되며 항상 활성이다 — 잠금 여부와 무관. 잠금 상태(B4·B5)에서는 표 헤더를 "재고 수량(수정 가능)"으로 액센트 표기해 유일하게 열린 필드임을 드러낸다.
[rev.32 · 진열+진행중 잠금 범위 확정] "재고 수량만 수정 가능"으로 확정(대표 확인 2026.08, 기능요구사항 §11-8과 동일). 옵션 그룹명·항목·옵션가·대표 옵션 라디오까지 전부 잠기고 재고 입력만 열린다 — 진행중 공구에서 SKU가 변경·삭제되면 이미 발생한 주문·정산 데이터가 깨지기 때문. 재논의 금지. 옵션 그룹 추가/삭제·항목 추가/삭제·드래그는 <div> 기반 클릭 컨트롤이라 disabled가 먹지 않으므로 pointer-events:none으로 차단했다(§11-8 구현 유의사항과 동일).
[rev.32 · 옵션 그룹 미사용 UI] 토글 OFF 시 그룹 에디터를 감추고 "구성 / 재고 수량 / 진열 여부" 3열 1행 표(기본 조합(옵션 없음))만 노출한다. 대표 옵션·옵션가 열은 존재하지 않는다(기능요구사항 §11-6 근거). 토글 OFF 시각 상태가 없어 꺼진 토글도 켜진 것처럼 보이던 CSS 버그도 함께 수정.

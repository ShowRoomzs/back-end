[파일 분할 · 2026.10.04] 소통 스레드는 한 화면(좌측 목록 탭 이슈 스레드 / 브랜드 / 인플루언서)이지만 기획은 두 파일로 나눈다 — ui-admin-20a-channels(운영팀 1:1 채널) · ui-admin-20b-issues(3자 이슈 스레드). 셸·목록·말풍선·입력창은 두 파일이 같은 마크업이고, 이 파일은 이슈 스레드 탭과 중재 모달만 담는다.
[이 화면 = 운영자의 두 채널] ① 1:1 운영팀 채널 — 파트너센터·쇼룸 스튜디오 목록 최상단에 고정된 SHOWROOMZ 운영팀의 반대편. 모든 브랜드·인플루언서와 채널이 하나씩 미리 있어 “새 대화”가 없고 검색으로 찾는다. ② 이슈 스레드 — 브랜드 · 인플루언서 · 운영팀 3자 채널. 정산액 조정이 필요한 경우에만 열린다(2026.09.28 확정) — 계약 이행 확인에서 미이행이 제출돼 정산이 보류될 때 시스템이 자동으로 연다. 그 밖의 분쟁(게시물 문구 · 일정 · 재발송 · 고정 지급비 등)은 양측이 1:1 스레드에서 직접 해결하고 운영자는 관여하지 않는다(2026.10.06 재확인) — 금액이 바뀌지 않는 분쟁에는 운영자가 낼 결론이 없다. 그래서 운영자가 이슈 스레드를 직접 여는 경로(구 M3)가 없다. 좌측 목록 탭이 이슈 스레드 / 브랜드 / 인플루언서이고 기본 진입은 이슈 스레드다 — 운영자가 결론을 내야 끝나는 건이 여기 있다.
[3단 구성 · 판단 근거 패널 — 이슈 스레드 전용] 파트너·스튜디오의 2패널(목록 · 스레드)에 우측 300px 패널을 더했다. 이 패널은 이슈 스레드에만 있고 이슈 정보 · 정산 영향 · 진행 단계 · 양측 응답 · 조치를 보인다. 1:1 채널은 우측 패널 없이 2단이며 상대 정보는 위의 상단 접이식 바로 본다. 대화는 길어지고 운영자는 여러 스레드를 오가므로, 스크롤하지 않고도 어디까지 왔고 무엇을 눌러야 하는지가 옆에 있어야 한다. 조치 버튼은 패널에만 두고 스레드 안에는 두지 않는다(대화와 판정을 섞지 않는다).
[이슈 진행 · 2026.10.06 개정] 개설(미이행 제출 → 정산 보류 → 자동 개설) → 자료 제출(운영자가 답변 기한 설정 · M2) → 정산 조정안 제시(운영자 · 조정 금액 · 근거 · 응답 기한) → 양측 응답(동의 / 반대·사유 필수) → 양측 동의 = 정산 금액 변경 + 보류 해제 + 이슈 종결(시스템 · 동시). 한쪽이라도 반대하면 금액 그대로 · 보류 유지 · 운영자가 2차 조정안을 낸다. 종결 후 같은 사안은 재이의 불가, 새 이견은 새 스레드.
[응답 기한 경과 · 2026.10.06] 기한은 영업일 수 숫자 입력(답변 기한 기본 2 · 응답 기한 기본 3 · 1~10). 응답 기한까지 한쪽만 무응답 = 동의 간주 → 조정안대로 자동 확정(A5) · 양측 무응답 = 원래 금액 확정 → 조정안 철회 · 보류 전 금액으로 자동 확정(A6). 간주의 조건은 사전 통지 2회(조정안 카드 문구 + 기한 D-1 통지 카드) · 응답 배지에 「동의 간주 · 무응답」을 실제 동의와 구분해 남긴다. 어떤 경우에도 보류는 응답 기한에서 끝난다.
[⚠ 약관수정필요 · 간주 조항] 무응답을 동의로 보려면 약관에 의사표시 간주 조항 · 상당한 기한 · 사전 개별 고지가 있어야 한다(약관규제법 제12조). 양측 무응답 시 원래 금액 확정도 같은 조항에 넣는다.
[운영자는 금액을 제안할 뿐 확정하지 않는다] 조정안은 운영자 판정이 아니라 스레드에 나온 양측 의견을 반영한 제안이고 확정은 양측 동의다 — 단독 확정·종결 버튼이 없다. 운영자가 누르는 것은 조정안 제시 · 답변 기한 설정 둘뿐이다. 귀책 판단·후속 조치 지시(재발송 등)는 하지 않는다 — 당사자의 일이다. 동의가 모이면 정산 관리에서 다시 누를 것 없이 바로 반영된다(공구 관리 B5a · 정산 관리 보류 탭은 결과만 조회).
[⚠ 약관수정필요] 인플 이용약관 제20조④는 “판단·근거·후속 조치·이의 기한을 포함한 중재 의견을 제시할 수 있으며, 금액 조정 내용은 직접 포함되지 않는다”이다 — 이번 개정은 회사가 금액 조정안을 제시하고 양측 동의로 정산 내용을 변경하는 구조라 정반대다. 「중재 의견」→「정산 조정안」, ④ 단서 삭제, “양측 동의 시 회사는 조정안대로 정산 내용을 변경하고 보류를 해제한다” 신설이 필요하다. 파트너 약관에도 같은 조항이 있어야 브랜드 수취액 변경의 근거가 된다.
[목록 배지 = 누구 차례인가] 조정안 필요 · 재조정 필요 = 운영자 차례(경고) / 자료 제출 중 · 응답 대기 = 당사자 차례(정보) / 종결 = 중립. 상태색 원칙 ①②를 그대로 따르고, GNB 배지는 운영자 차례인 이슈 + 1:1 미답만 센다 — 당사자 차례를 세면 운영자가 0으로 만들 수 없는 숫자가 된다(공구 관리 조치 필요 큐와 같은 판단).
[시스템 카드와 말풍선을 나눈다] 미이행 사유 · 답변 기한 · 정산 조정안 · 동의/반대 · 계약 처리 결과 같은 절차의 기록은 시스템 카드로, 사람의 대화는 말풍선으로 둔다. 절차가 말풍선에 섞이면 이후 대화에 묻히고, 분쟁 때 “그 안내를 받았는가”가 흐려진다. 반대 사유도 말풍선이 아니라 카드로 고정된다.
[운영자 이름은 어드민에서만] 운영자 말풍선은 어드민에 운영팀 · 김운영으로 보이고 양측에는 SHOWROOMZ 운영팀으로만 나간다 — 운영자 개인이 아니라 회사의 판단이라는 뜻이고, 담당이 바뀌어도 대화가 이어진다. 누가 썼는지는 내부 감사용으로 남긴다.
[1:1 브랜드–인플루언서 스레드는 열람만] 파트너·스튜디오의 스레드 상단 고지(“분쟁 발생 시 운영자가 열람할 수 있습니다”)의 실제 경로는 이슈 패널의 [브랜드–인플루언서 1:1 스레드 열람] 하나다 — 이슈가 없는 쌍의 대화를 목록으로 훑는 기능은 두지 않았다(고지의 범위가 “분쟁 발생 시”이기 때문).
[컴포넌트 재사용] 목록 아이템 · 말풍선 · 첨부 칩 · 입력창은 ui-partner-05-connections와 같은 마크업이다. 첨부 규칙(20개 · 500MB · 종류별 클릭 동작)도 그대로 따르며 이 초안에서는 첨부 상태 화면을 다시 그리지 않았다.
[약관보완-2차질의] D-2 정산 보류의 출구 없음 — 반대가 반복되면 A3이 끝나지 않는다. 재중재 횟수 · 최종 판정 주체가 약관에 없다. D-4 인플루언서 측 직권 중단 소명 조항 부재 — 이 스레드가 그 소명의 자리가 될 수 있는지도 함께 묻는다.
[확인 필요] ⓑ 응답 기한 무응답 처리 → 해소(한쪽 = 동의 간주 · 양측 = 원래 금액) 기한 내 무응답의 효과 — 동의 간주인지 반대 간주인지 약관에 없다 ⓒ 1:1 채널의 응답 SLA와 미답 기준 ⓓ 운영자 여럿이 같은 이슈를 볼 때 담당자 지정이 필요한지 ⓔ 휴면 회원(탈퇴·정지)의 운영팀 채널 처리 — 파트너 규칙의 “휴면(열람만)”을 그대로 쓸지.
[금칙어] 프로젝트 지침 §4 확정 용어 대조표를 따른다.
[규격 정합] 사이드바 240 · 탑바 56 · 본문 패딩 24 · 좌 목록 300 · 우 패널 300 · 스레드 헤더 60 · 입력창 높이 60 · 액센트 인디고 #3B5BDB 단일 · 밀도 Compact · 설계 근거는 이 박스와 .state-spec에만 둔다.
A1이슈 스레드 · 조정안 필요 (기본 진입)기본 진입은 이슈 스레드 탭 — 운영자가 정산 조정안을 내야 다음으로 가는 건이 여기 있다 · 이슈 스레드는 정산 금액이 바뀌어야 할 때만 열린다(이행 확인 미이행 제출 → 정산 보류 → 시스템 자동 개설). 그 밖의 분쟁(게시물 문구 · 일정 · 재발송 · 고정 지급비)은 양측이 1:1 스레드에서 해결하고 운영자는 관여하지 않는다 · 3단 구성: 목록 300 · 스레드 · 이슈 정보 300 — 정산 회차·보류 금액·진행 단계를 대화 옆에 둔다 · 첫 글은 미이행 사유 시스템 카드 · 자료 제출 기한이 지나 조정안 필요(경고)로 올라왔다

근거: 계약 작성 스펙 §10 발송 순서 · 디자인시스템 v1.3 · 셸·토큰 출처 ui-partner-08-contracts.html · GNB #4

[이 파일의 범위] 브랜드가 [서명 후 발송]을 누른 뒤 서명대기에 도달하기까지의 모달 8종만 담는다. 작성·서명대기·체결·종결 상태는 ui-partner-08-contracts.html에 있다 — 한 파일에 30장이 넘어가면 리뷰가 불가능해 발송 구간만 떼어냈다. 셸·토큰·상태색·폼 행 규격은 두 파일이 동일하다.
[확정 시퀀스 · 서명이 결제보다 먼저] ① 하드 검증 → ② 발송 확인 모달 → ③ 계약서 문서 생성(M2) → ④ 브랜드 서명(M3) → ⑤ 고정 지급비 선결제(M5) → ⑥ 인플루언서에게 서명 요청 발송 → ⑦ 서명대기(M7)
[자금 경계선] ④까지는 브랜드 자금이 움직이지 않는다. 결제만 되고 계약은 없는 상태를 막기 위한 순서이므로 바꾸지 않는다. 각 실패 지점의 결과가 다르며, 그 차이를 화면 문구가 반드시 말해야 한다 —
  · M1(발송 전 재검증 실패) · M4(서명 미완료) → 문서 폐기 · 결제 없음 · 작성중 유지
  · M6(결제 실패) → 서명한 문서 폐기 · 결제 미승인 · 작성중 복귀 · 재발송 시 다시 서명
  · M8(발송 실패) → 결제는 완료됨 · 자동 환불 · 작성중 복귀 — 돈이 나간 유일한 실패 경로다
[디자인시스템에 없어 새로 정의한 것] ① 진행 마대(.pbar) — 로더가 없어 신설했다. 인디고 면 + 중립 트랙, 높이 5px, 회전 애니메이션 없이 정적 스냅샷으로도 읽히는 형태다. ② 결과 아이콘(.rico) — 상태색 배경 + 같은 계열 글리프, 38px 원형. ③ 결과 체크리스트(.ck) — 어느 단계까지 됐는지 보여주는 목록. 세 컴포넌트 모두 기존 토큰만 조합했고 새 색을 만들지 않았다.
[외부 시스템은 그리지 않는다] 전자계약 솔루션·PG 업체가 미확정이라 실제 UI를 그리지 않고 점선 placeholder + 주석으로만 둔다([전자계약 솔루션 렌더 영역] · [PG 인증 영역]). 우리가 쓰는 건 그 위의 안내 문구뿐이다.
[닫기 버튼 규칙] 진행 중 모달(M2·M5)에는 닫기가 없다 — 중단하면 문서가 반쯤 생기거나 결제 상태가 불분명해진다. 결과 모달(M4·M6·M7·M8)에는 다음 행동 버튼을 두고, M3은 사용자가 스스로 그만둘 수 있어야 하므로 닫기를 둔다(닫으면 M4로 이어진다).
[상태색] M4 서명 미완료 = 경고(되돌아온 것이지 부정 결과가 아니다) · M6 결제 실패 · M8 발송 실패 = 위험(자금·문서가 실제로 폐기·이동된 확정 결과) · M7 = 성공. 아이콘에만 상태색을 쓰고 버튼은 인디고 단일이다.
[근거 대기] ① 전자계약 업체·자체구축 여부 ② 서명 시 본인확인 수준 ③ PG 업체·3DS 절차 ④ 환불 소요(영업일 3일은 잠정) ⑤ 오류코드 체계(SEND-503은 예시).

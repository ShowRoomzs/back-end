# 어드민 반영 요청 — 파트너센터 변경 사항 (2026.10.05)

> 파트너센터 시안을 2026.10.05 「거래 관리 결정 사항」에 맞춰 고쳤다. 아래는 **어드민 화면이 같은 기준을 따라야 하는 항목**이다.
> 근거 파일: ui-partner-03-onboarding · 06-basic-info · 10a~10e-orders · 11-claims (2026.10.05 반영본)

---

## 1. 발송 기한 — 고정 3영업일 → 브랜드가 정하는 N영업일 【가장 큰 변경】

**바뀐 내용**
- 발송 기한 = **공구 마감 시각 + 브랜드가 정한 N영업일**
- N은 브랜드가 **온보딩**과 **기본정보 관리 › 배송·반품 정책 › 「발송 기한」**에서 정한다. 기본값 3, 입력 범위 1~7
- 이 값은 소비자 상품 상세에 **「공구 마감 후 N영업일 이내 발송」으로 자동 표시**된다. 전자상거래법 제15조①의 「공급 시기 별도 약정」 근거가 된다
- 공구 진행 중에 결제된 주문은 **마감 전까지 발송 기한이 생기지 않는다**
- 값을 바꾸면 **이후 접수되는 주문에만 적용**된다. 이미 접수된 주문은 접수 당시 값으로 고정된다
- 기존 「출고 소요일」(결제완료 + N일) 개념은 **폐기**한다

**어드민에서 맞출 것**
- 주문 조회·처리 지연 모니터의 발송 기한 계산식을 **마감 + 주문 시점의 N**으로 바꾼다
- 주문 상세에 **그 주문에 적용된 N값**을 표시한다. 브랜드가 나중에 값을 바꿔도 주문별로 기한이 다를 수 있어서다
- 「발송기한 경과」 판정 기준 시각은 **송장 등록 시각**(기존과 같음)
- `[근거 대기]` 상한 7영업일(운영정책) · 마감일부터 세는 방식이 약정으로 인정되는 요건(변호사 2차 질의)

## 2. 환불 실행 주체 — PG 자동이 기본

| 경로 | 처리 |
|---|---|
| 결제완료 상태에서 소비자 취소 · 취소 요청 승인 · 브랜드 직권 취소 · 반품 검수 승인 · 반송 완료 | **PG 즉시 자동 환불** |
| 운영자 사유 환불(중재 인용 · 구매확정 후 하자 · 위해성 리콜) | **운영자 실행** — 이것만 |

- 브랜드는 **어떤 경로로도 환불을 실행하지 않는다**
- 어드민 「환불 집행」 페이지가 다루는 범위는 **운영자 사유 환불뿐**이다. 나머지는 이력에 「PG 자동 환불」로만 남긴다

## 3. 취소 요청 — 응답 기한 1영업일 · 넘기면 자동 승인

- 브랜드가 **1영업일 안에** 승인·거부하지 않으면 **자동 승인**되고 PG가 즉시 환불한다
- 취소 요청이 걸린 항목은 브랜드 쪽에서 **송장 등록이 잠긴다**
- 거부 사유는 드롭다운으로 고른다: 이미 포장·출고가 완료됨 / 택배사 집화가 완료됨 / 주문 제작·맞춤 상품 / 기타(상세 사유 필수). 소비자에게 그대로 전달된다
- 일부 항목만 취소 요청된 경우 **주문 전체가 취소 요청 탭으로 이동**한다. 처리 후에는 원래 탭으로 돌아간다. 전 항목이 승인되면 취소 탭으로 간다

## 4. 발주서 다운로드 = 준비 시작 (선택 없음)

- 발주서를 내려받으면 주문이 **무조건 상품준비중으로 넘어간다**. 「다운로드만 하기」 체크박스는 없앴다
- 이유: 결제완료 상태에서는 소비자가 배송지를 바꿀 수 있어, 발주서 주소와 실제 배송지가 달라질 수 있다
- 어드민 이력에서 **준비 시작 사유 = 「발주서 다운로드」**를 구분해 기록한다

## 5. 배송 이상 감시

- **집화 확인 필요 = 송장 등록 후 24시간 미조회**. 72시간 「집화 지연」 단계는 **폐기**
- **추적 정지**(집화 후 7일 갱신 없음)는 **플랫폼이 개입하지 않는다**. 소비자나 브랜드가 택배사에 직접 조회한다
  - 누락(이미 수령) → **택배사가 배송완료로 처리**
  - 분실 → **브랜드가 재발송한 뒤 송장 수정**
  - 분실 보상은 택배사와 브랜드 사이에서 처리하며 플랫폼은 관여하지 않는다
- **반송 중 → 반송 완료**: 구매확정이 불가하다. **환불로 종결**하고 **이 주문으로 재발송하지 않는다**. 소비자가 다시 받길 원하면 새로 주문한다. 반송 사유는 택배사가 주지 않으므로 화면에 사유를 단정해 적지 않는다

## 6. 택배사 목록

- **추적 연동 업체 목록 하나를 출고·회수·재발송 공통으로** 쓴다. 자유 입력과 수기 송장은 없다

## 7. 직권 취소 가능 단계

- **신규 · 상품준비중**에서 가능하다. 송장 등록 후에는 불가

## 8. 구매확정 후 하자

- 소비자는 **직접 반품을 신청하지 못한다**. 1:1 문의 → **운영자가 반품 클레임을 대신 개설**한다
- 법정 기간(공급일 3개월 · 안 날부터 30일), 증빙 필수, 단순 변심 불가
- 개설 후에는 일반 반품과 같은 흐름이다. 브랜드는 검수만 하고, 정산이 끝난 건은 다음 정산에서 차감한다

## 9. 반품·교환 검수 (11-claims)

- **[검수 승인]은 되돌릴 수 없다** → 확인 모달을 거치고, 승인 즉시 **PG가 자동 환불**한다
- **검수 반려 입력 항목** — 소비자 화면 C10-5와 1:1로 맞춘다
  1. 반려 사유
  2. 법적 근거(전자상거래법 제17조② 각 호에서 선택)
  3. 증빙 사진(필수)
  4. 소비자에게 보낼 메시지(필수)
  5. 전체 / 일부 반려(일부면 수량 지정)
  6. 귀책 변경(변경 없음 / 브랜드 귀책 인정)
- 반품 사유 「기타」는 **소비자 귀책이 기본**이고 상세 내용이 필수다. 검수 단계에서 브랜드 귀책으로 바꿀 수 있다
- 교환은 **같은 가격 옵션끼리만** 가능하다. 가격이 다르면 반품 후 다시 주문한다
- 재발송비(교환·반려)는 브랜드가 부담한다. 정산 때 **브랜드 수취액에 더해진다**
- 반품·교환을 요청하면 그 항목의 **구매확정 타이머가 멈춘다**. 철회되거나 자동 취소되면 남은 일수부터 다시 센다. 교환이 완료되면 7일을 새로 센다
- 반려 상품은 약관에 반영되기 전까지 **폐기하지 않는다**. 보관 기한만 표시한다
- 회수는 **소비자가 직접 발송**한다. 회수 송장은 소비자가 입력하고, 브랜드 화면에는 회수 목록 다운로드가 없다. 엑셀 다운로드는 **재발송 탭**에만 있다

## 어드민이 새로 표시해야 하는 값 (요약)

- 주문별 **적용된 발송 기한 N값**과 그 값으로 계산한 **발송 기한 일시**
- 취소 요청의 **응답 마감 일시**와 **자동 승인 여부**
- 준비 시작 사유(**발주서 다운로드 / 개별 준비 시작 / 일괄**)
- 환불 출처(**PG 자동 / 운영자 사유**)
- 검수 반려 6개 항목(소비자 C10-5와 같은 값)

## 바꾸지 않는 것

- 운영정책에 맡긴 값은 `[근거 대기]` 그대로 둔다(오픈 승인 SLA · 반려 재등록 횟수 · 연장 상한 · 발송 기한 상한 7 등)
- 상태 배지 색 원칙(v1.3) — 경고=조치 필요 · 위험=부정 결과 확정 · 중립=종결
- 금칙어 — 크리에이터 · 마켓 · 판매자 · 구매자 금지

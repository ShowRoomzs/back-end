⑤ 어드민 · 3. 회원 관리 — 인플루언서 상세 ui-admin-18-influencer-detail · rev.1

인플루언서 회원 상세 · 근거: SHOWROOMZ_웹_디자인시스템_v1_2.html · 목록은 ui-admin-16-influencers.html · 대칭 화면은 ui-admin-15-brand-detail.html · 마스킹 동선은 ui-admin-13-consumer-detail.html

[브랜드 상세와 대칭] 좌측은 사실 조회, 우측은 판단과 조치(sticky 레일)이며 좌측 카드가 많아 모든 상태를 상단·하단 2장으로 낸다 — 셸·카드·필드행·모달·배지는 ui-admin-15-brand-detail.html에서 그대로 가져왔다. 상단: 기본·본인확인·사업자·정산 / 하단: 운영 현황·연결 브랜드·쇼룸 활동·관리자 메모. 처리 이력은 레일 맨 아래다 — 이력은 지금 내리는 조치의 근거라 정지 버튼과 같은 열에서 읽혀야 한다(상태 → 조치 → 과거에 무엇을 했는지). 관리자 메모만 좌측에 남긴다 — 300자를 쓰고 읽는 카드라 320px 레일에서는 접힌다.
[본인확인 카드를 브랜드가 아니라 소비자 쪽에서 가져왔다] 인플루언서는 개인이 계약 당사자다 — 고정 지급비가 개인에게 지급되고 비사업자면 3.3% 원천징수가 걸린다. 그래서 브랜드 상세에 없는 본인확인 정보 카드 + 마스킹 해제 동선(소비자 상세 §13 패턴)을 그대로 이식했다: 기본 마스킹 · 정형 사유 4종 · 이 회원 1건·이 세션 한정 · 무조작 10분 자동 재잠금 · 처리 이력 즉시 기록 · 최고관리자 한정. 사유 목록만 인플루언서 맥락으로 바꿨다(정산·원천징수 확인 · 계약·분쟁 대응).
[사업자 여부가 카드 하나를 갈라놓는다] 사업자면 상호·등록번호·주소가 있고, 비사업자면 그 자리가 전부 빈다. 빈 카드를 두거나 카드를 없애는 대신 비사업자 + 3.3% 원천징수를 그 자리에 쓴다(C1) — 목록의 사업자 여부 열을 둔 이유(정산 원천징수 방식이 갈리는 지점)와 같은 판단이다.
[운영 현황 4-KPI는 브랜드와 거울] 브랜드가 연결 인플루언서 / 진행중 공구 / 누적 정산액 / 미정산액이면 인플루언서는 연결 브랜드 / 진행중 공구 / 누적 지급액 / 미지급액이다 — 인플루언서에게 지급되는 것은 판매 정산이 아니라 고정 지급비라 이름을 바꿨다. 미지급액만 경고색으로 올린다(유일하게 돈이 걸린 수치).
[쇼룸 활동은 앱 내 지표만] 공구 게시물·일반 게시물·쇼룸 팔로워·소통 스레드 — 모두 우리 데이터다. 목록에서 외부 채널 팔로워를 뺀 이유(갱신 시점이 제각각이라 판단 근거가 못 된다)는 상세에서도 같으므로, 여기 팔로워는 인스타 팔로워가 아니라 앱 내 쇼룸 팔로우 수이며 카드 헤더에 그렇게 못박았다. 게시물 신고 행은 그리지 않았다 — 신고 기능이 [자문대기-법률 · 쟁점J]라 없는 데이터를 UI에 올리지 않는다.
[탈퇴 = 승인 심사 · 조건 검증 블록 없음] 인플루언서 탈퇴도 셀프서비스가 아니다. 다만 진행중 공구·미지급액이 0이어야 인플루언서 화면에서 신청 버튼이 열리므로 어드민에 체크리스트를 두지 않는다(늘 ✓만 뜨는 블록은 자리만 차지한다) — 대신 승인 모달에서 0건·0원을 한 번 더 보여 준다. 반려 사유는 조건과 같은 축으로 남긴다.
[레일 처리 이력은 최신 3건 + 전체 N건 보기] 320px 레일에 이력을 전부 쌓으면 카드가 화면 밖으로 잘린다 — 레일 이력은 조치 직전에 최근 이력을 확인하는 자리라 최신 몇 건으로 충분하고 나머지는 전체 N건 보기로 펼친다. 심사 카드가 붙는 B1-b는 최신 2건으로 더 줄였다.
[상태와 제재를 한 카드로] 계정 상태 관리 카드를 없애고 정지·정지 해제를 현재 상태 카드 맨 아래(구분선 아래)로 넣었다 — 상태와 그것을 바꾸는 버튼이 떨어져 있으면 두 카드를 왕복해야 하고, 활성일 때 제재 카드는 버튼 하나만 든 빈 카드였다. 남은 축은 현재 상태(활성·정지·탈퇴 + 제재 버튼)와 탈퇴 신청 심사(승인 대기) 둘이다 — 신청은 상태가 아니라 처리해야 할 건이고, 승인 전까지 회원은 실제로 활성이다(쇼룸이 열려 있다). 심사 카드는 신청이 있을 때만 그려지므로 A1·C1·D1 레일에는 없다. 정지는 회원 상태에 그대로 올린다 — 목록의 상태 열과 어긋나면 안 된다.
[상태 색 매핑] 활성=성공 / 탈퇴 승인 대기=경고(원칙 ①) / 정지=위험 / 탈퇴=중립(원칙 ②). 정지 버튼은 흰 배경 + 중립 테두리 + 위험색 글자이며 꽉 찬 위험색은 모달의 최종 실행 버튼에만 쓴다.
[정지의 범위] 공구 개설·게시물 등록·정산 신청은 막고 진행 중 공구와 미배송 주문은 유지한다 — 인플루언서 제재로 소비자·브랜드 피해를 만들지 않기 위함이다. 고정 지급비는 보류, 소명은 1:1 문의로만 받는다.
[계좌번호 마스킹] 정산 정보의 계좌번호는 가운데를 가리고 전체 값은 정산 관리에서만 조회한다 — 본인확인 카드의 마스킹 해제 대상에 계좌는 포함하지 않는다(회원 관리의 목적은 신원 확인, 송금은 다른 화면의 일).
[메모 규칙] 조치하지 않은 판단의 기록 · 누적 기입(작성자·일시 표기) · 항목당 300자 · 작성자 본인 24시간 내 수정·삭제 — F4·F5 동일 적용 결정을 그대로 따랐고 좌측 맨 아래에 둔다(처리 이력은 레일).
[금칙어] 크리에이터 → 인플루언서 · 앱 내 인플루언서 페이지 → 쇼룸 · 크리에이터 스튜디오 → 쇼룸 스튜디오.
[확인 필요] ⓐ 연결 브랜드 “연결 종료” 행을 상세에 남길 기간(브랜드 상세 ⓒ와 동일 쟁점) ⓑ 인스타를 운영하지 않는 인플루언서의 인스타 행 표기(빈칸 vs 미등록) ⓒ 비사업자 → 사업자 전환 시 원천징수 방식 변경 이력을 이 화면에서 볼지 ⓓ 쇼룸 팔로워가 정지·탈퇴 판단에 실제로 쓰이는 수치인지(안 쓰이면 카드에서 뺀다) ⓔ 탈퇴 승인 시 쇼룸 게시물의 처리(비공개 vs 삭제) — 소비자가 구매한 공구 게시물이 사라지면 주문 상세의 참조가 끊긴다.
[⚠ 법률 자문 대기] 탈퇴 시 보존·파기 범위는 쟁점 G 종속 — 시안에는 지급·정산 기록 보존 / 본인확인·사업자·정산 정보 파기로 그렸고 CI/DI는 미확정 표기다.
[규격 정합] 상세 필드 행 9px · 라벨 140px, 테이블 본문 셀 14px 16px · 행높이 50px. 설계 근거는 이 박스와 .state-spec에만 둔다.
A1활성 인플루언서 · 상단기본 진입 — 좌측 상단 4카드(기본·본인확인·사업자·정산)와 우측 sticky 레일 현재 상태 1카드(맨 아래에 정지 버튼) — 탈퇴 신청 심사 카드는 B1에만 나타나고 계정 상태 관리 카드는 없다 · 본인확인 정보는 기본 마스킹이며 카드 헤더의 마스킹 해제로만 열린다(소비자 상세와 동일 동선) · 사업자 회원이라 원천징수 방식이 세금계산서다 · 액션은 정지 단독 · 하단 카드(운영 현황·연결 브랜드·쇼룸 활동·관리자 메모)와 레일의 처리 이력은 A1-b에서 본다

[스코프 · 역할] GNB #3 계약 관리 — 스튜디오는 수신 측이다. 브랜드가 작성 · 발송하고 인플루언서는 확인 · 서명 · 거절만 한다. 발송 · 작성 · 수정 액션은 이 화면에 존재하지 않는다.
브랜드 작성 → 운영자 검토 → 양측 동시 서명 요청 → 브랜드 · 나 각각 서명 → 운영자 체결 완료 처리 → 체결완료 · 공구 생성 (└ 내 거절 / 만료 / 브랜드 취소)
[상태값 · 파트너센터와 동일] 상태 이름 · 색은 거래플로우 상태정의서와 파트너센터를 그대로 따른다 — 서명 진행중 · 체결 처리 대기=정보 · 체결완료=성공 · 거절=위험 · 만료 · 취소=중립(원칙②). 같은 상태값에 서피스별로 다른 색을 쓰지 않는다(원칙③).
[파트너센터와 다른 점 · 근거] 컴포넌트(카드 · 폼 행 · 배지 · 스텝퍼 · 서명 박스 · 목록 · 모달 · 이력)는 완전 동일 마크업으로 재사용하고, 아래 5가지만 다르다.
  · 작성중 탭이 없다 — 브랜드가 작성 중인 계약은 발송 전이므로 인플루언서에게 도착하지 않는다. 탭은 전체 · 서명 진행중 · 체결 처리 대기 · 체결완료 · 종료 5종이고, 스튜디오가 볼 수 있는 최초 상태는 서명 진행중이다 — 작성중 · 검토 대기 · 검토 반려는 브랜드 전용이라 인플루언서에게 도착하지 않는다(운영자 검토를 통과해야 서명 요청이 온다).
  · 주 CTA가 없다 — 파트너센터 목록의 [+ 계약 작성]과 빈 상태 CTA를 삭제했다. 인플루언서는 계약을 만들 수 없다. 빈 상태는 "브랜드가 보내면 도착한다"는 사실 + 연결·소통 · 연결코드 안내로 대신한다.
  · 목록 열 교체 — 「생성일」 → 「내 서명 기한」. 수신 측에서 유효한 날짜는 내가 조치해야 하는 기한 하나뿐이고, 생성일은 브랜드의 사정이다.
  · 「내가 받는 금액」 카드 신설 — 같은 값(고정 지급비 · 리워드율)이 파트너센터에서는 내는 돈, 스튜디오에서는 받는 돈이다. 관점이 반대라 라벨과 배치가 같을 수 없다. 이 카드와 「내가 해야 할 일」(콘텐츠 의무)을 상품 항목보다 위에 둔다 — 인플루언서가 서명 여부를 판단하는 근거가 그 둘이기 때문이다.
  · [이 조건으로 새 계약 작성]이 없다 — 종결 3종의 파트너센터 액션이다. 스튜디오의 회복 경로는 [스레드에서 협의하기] 하나이며, 새 계약을 보내는 쪽은 항상 브랜드다.
[서명 진행중이 「내 몫이 남은 것」인데 색을 바꾸지 않는 이유] 파트너센터에서 서명 진행중은 "기다리는 중", 스튜디오에서는 "내 서명이 남았다"일 수 있다. 그러나 상태값이 같으면 색도 같다(원칙③)는 규칙이 우선하고, 원칙①의 경고 · 위험은 운영자 조치가 필요한 상태에 쓰는 색이다. 그래서 배지는 정보색 그대로 두고, 내 차례라는 사실은 색이 아니라 ①GNB 배지 숫자 ②목록의 「내 서명이 필요한 계약 1건」 ③기한 날짜의 경고색 ④서명 카드의 내 칸 강조(.sbox.mine) ⑤주 버튼으로 표현한다.
[남은 기간 표기] 기한이 임박한 건은 날짜 텍스트 자체를 경고색으로 칠한다 — 칩이나 "N일 남음" 같은 보조 요소를 덧붙이지 않는다(요소가 늘면 상태 배지와 경쟁하고 행 높이도 흔들린다). 칩 · 배지 형태를 쓰지 않는 이유는 같은 행의 상태 배지와 형태가 겹쳐 무엇이 상태값인지 흐려지기 때문이다 — 배지는 상태값 전용이고, 기한은 텍스트다. 색은 경고다 — 기한이 지나면 만료(중립 종결)이지 부정 결과 확정이 아니므로 위험색을 쓰지 않는다(원칙①③).
[수정 요청 경로] 인플루언서는 조건을 고칠 수 없다. 조정이 필요하면 ①서명 전 스레드 협의 또는 ②거절 + 사유 전달 뿐이며, 두 경로 모두 결과적으로 브랜드의 재발송을 기다린다. 화면 어디에도 조건 입력 필드를 두지 않는다.
[rev.5 · 서명 순서가 사라졌다 — 이 개정의 근간] 파트너센터 rev.5에서 전자서명 솔루션이 기안자 선서명을 지원하지 않는 것이 확인돼, 「발송 = 브랜드 서명 완료 → 내가 2순위」 전제가 폐기됐다. 확정 절차는 브랜드 작성 → 운영자 검토 → 양측 동시 서명 요청 → 각자 서명 → 운영자 체결 완료 처리다. 그래서 이 파일에서 「1순위 · 2순위」 표기를 전부 걷어냈다 — 서명은 순서가 아니라 각자의 몫이고, 계약서가 도착한 시점에 브랜드도 아직 서명하지 않았을 수 있다(S3).
  · 서명은 이 화면 밖에서 한다 — 검토를 통과하면 전자서명 솔루션이 양측에 메일 · 문자를 각각 발송하고 서명은 그 링크에서 이뤄진다. 그래서 업체 미확정을 전제로 그렸던 임베드 서명 모달(구 S4)을 삭제했다.
  · 「내가 서명하면 즉시 체결」도 폐기했다 — 양측 서명만으로 계약이 성립하지 않고 운영자가 체결 완료를 눌러야 한다. 그 구간을 체결 처리 대기(S3c)로 세웠고, 이유는 파트너센터와 같다: 서명을 끝낸 사람이 「끝났다」고 보고 준비 일정을 당겨 잡는 것을 막기 위해서다. 그래서 S3c와 서명 완료 모달(S11)에 「아직 공구는 만들어지지 않았습니다」를 명시하고, PDF · 인증서도 체결 처리 시 발급됨을 밝힌다.
  · 내가 먼저 서명하는 경우가 생겼다(S3b) — 스튜디오에 없던 상태다. 이때는 내 할 일이 없고 되돌릴 수도 없어(서명 후 거절 불가) 액션을 [스레드에서 협의하기] 하나로 줄였다.
  · 파트너센터는 이를 「어드민」으로 쓰지만 스튜디오 화면 문구는 「운영자」로 통일한다 — 인플루언서가 보는 화면에 사내 용어를 쓰지 않는다.
[MVP · 서명 현황은 수동 갱신이다 · 확정] 모두싸인 API 연동을 도입하지 않기로 확정됐다(API 요금제 비용). 이 결정이 화면에 남기는 제약은 세 가지다 — ①서명 링크를 우리가 갖지 못한다(모두싸인이 메일 · 문자로 직접 보낸다) ②서명 완료를 실시간으로 통지받지 못한다(웹훅이 없다) ③PDF · 인증서도 자동 수신되지 않는다.
  · 그래서 이 화면에 서명 버튼을 두지 않는다 — 누를 대상(링크)이 없다. 대신 [서명 안내 다시 받기]로 운영자에게 재발송을 요청한다. 있지도 않은 버튼을 그리면 "눌러도 아무 일이 없는" 화면이 된다.
  · 참여자별 서명 상태는 운영자가 모두싸인에서 확인해 입력한 값이다. 실시간이 아니므로 서명 카드에 기준 시각("운영자 확인 · 08.14 12:00 기준")을 박고, 방금 서명한 사람이 "내 서명이 왜 반영 안 됐지"로 오해하지 않게 한다. 이것이 MVP에서 참여자별 상태를 그대로 유지한 이유다 — 값이 늦을 뿐 틀리지는 않고, 늦는다는 사실을 화면이 밝히면 읽을 수 있는 정보가 된다.
  · 만료도 자동 판정이 아니다 — 기한이 지나도 시스템이 스스로 닫지 않고 운영자가 확인해 만료 처리한다. 그래서 종결 스텝의 주체를 「시스템」에서 「운영자」로 바꿨다.
  · [다음 단계] API 도입 시 이 화면은 그대로 두고 기준 시각 문구와 [서명 안내 다시 받기]만 제거하면 된다 — 상태 구조를 수동 운영에 맞춰 바꾸지 않은 것은 나중에 되돌리는 비용을 만들지 않기 위해서다.
[rev.6 · 고정 지급비에서 선결제를 걷어냈다] 파트너센터 rev.6에서 플랫폼이 고정 지급비를 중개하지 않기로 확정됐다 — 브랜드가 직접 지급하고 계약서에는 금액과 지급 시점만 기재되며, 지급 시점도 고정이 아니라 브랜드가 공구 게시물 등록 후 / 공구 종료 후 / 정산 완료 후 중에서 고른 값이다. 그래서 이 파일 전체의 「브랜드가 이미 선결제했습니다」를 삭제했다.
  · 받는 쪽에는 이 변화가 더 크다 — 선결제라면 「플랫폼에 돈이 있으니 받는다」지만, 직접 지급이면 브랜드가 안 주면 못 받는다. 그래서 「내가 받는 금액」 카드에 플랫폼이 지급을 보증하지 않는다는 사실과 미지급 시 이슈 스레드 · 운영자 중재 · 계약서가 근거라는 경로를 명시했다. 서명 전에 알아야 할 사실이라 서명 진행중 화면부터 나온다.
  · 체결완료 상태에서도 지급 전임을 상태 카드에 못박는다 — 체결을 입금으로 오해하면 분쟁이 된다. 종결 3종에서는 지급 없음으로만 표기하고, 브랜드 쪽 환불 이력은 표시하지 않는다(내 자금이 아니다).
[금액 표기] 화면의 금액은 공제 전 기준이며 실지급액은 정산 관리(#7) 소관으로 넘긴다. [근거 대기] 비사업자 원천징수 3.3% 적용 방식이 세무 확정 전이라 이 화면에서 실지급액을 계산해 보여주지 않는다.
[서명 플로우] 서명 진행중(S3 · S3a · S3b) → 내 서명 완료 모달(S11) → 체결 처리 대기(S3c) → 체결완료 상세(S6). 파트너센터 08b의 발송 시퀀스와 달리 중간 실패 모달을 그리지 않는다 — 인플루언서 서명에는 결제 · 문서 생성이 얽혀 있지 않아, 서명을 마치지 않고 이탈하면 아무 일도 일어나지 않고 서명 진행중이 유지된다.
[진입 · 라우팅] 목록은 행 전체 클릭으로 진입하고 관리 열을 두지 않는다. 상세는 상태가 바뀌어도 같은 화면에서 액션 영역과 종결 안내만 교체된다(파트너센터 rev.2와 동일).
[용어] 목록 · 상세의 상대 라벨은 브랜드다. 공구명은 브랜드 내부 관리용 이름이며, 소비자에게 보이는 게시물 제목은 인플루언서가 공구 게시물에서 따로 쓴다.
[확인 필요] ① 서명 기한 임박 알림 발송 시점(D-3 · D-1 등)이 미정 — 만료는 인플루언서에게 기회 손실이므로 알림 규칙이 필요하다. ② 서명 위치 — 스튜디오 내부 임베드인지 전자계약 업체 외부 링크인지 미확정(S4는 placeholder). ③ 거절 사유 구분 값은 이 시안의 제안이며 확정 목록이 필요하다. ④ 체결 후 해지 값이 없다(파트너센터 rev.2의 미해결 지적 그대로) — 공구 진행 중 중단을 표현할 상태가 없다. ⑤ 사전 검수 있음 계약에서 초안 확인이 스레드 대화로만 남는데, 이행 판정의 조건이므로 별도 기록 구조가 필요한지 결정 필요.
[스냅샷 높이] 프레임은 1440×1024 기준이며, 세로로 잘리는 내용을 확인할 수 있도록 .stage는 콘텐츠 높이만큼 늘어난다.

교환 · 반려 재발송도 이 화면 — 교환 새 상품과 반려 상품 재발송은 둘 다 브랜드 → 고객 방향의 새 송장이라 같은 화면을 씁니다(회수 조회 C10-4만 방향이 반대). 위 [배송 종류]로 확인하세요. 다른 점은 두 가지 — 주문 날짜 앞의 회색 라벨("교환 상품 발송" / "반려 상품 재발송")로 같은 주문의 여러 송장 중 어느 배송인지 가르고, 상품 아래 회색 안내 한 줄로 배송완료 뒤 할 수 있는 일을 알립니다. 반려 상품은 이미 반려된 상품이라 반품·교환 버튼이 다시 생기지 않습니다.

진입 경로 — 교환 상세 · 재발송 상태 [배송 조회], 반려 후 결제·차감 완료 → 재발송 상태 [배송 조회], 주문 내역 상품 행 [배송 조회].

왜 별도 화면인가 — 배송 추적은 주문이 아니라 송장 하나에 붙습니다. 공동구매는 브랜드가 다르면 따로 발송되므로 한 주문에 송장이 여러 개 생기고, 주문 상세 안에 이력을 다 펼치면 어느 상품의 이력인지 알 수 없게 됩니다. 그래서 주문 상세는 항목별 상태만 보여주고, 이력은 이 화면이 송장 단위로 책임집니다. 상단에 대상 상품 한 건을 다시 보여주는 이유도 같습니다 — 목적지가 분명해야 합니다.

결론을 제목으로 — "9.16(수) 상품 배송이 완료되었어요"처럼 날짜 + 결과를 19px 제목으로 답합니다. 사용자가 이 화면에 들어오는 이유가 그 한 문장이고, 스캔 이력은 근거입니다. 날짜만 로즈로 칠해 시선이 먼저 닿게 했습니다.

3구간 바(배송 시작 · 배송중 · 배송 완료)는 택배사 스캔을 사용자 언어로 접은 것입니다 — 집하·구간발송·셔틀도착 같은 택배사 내부 용어를 단계로 쓰지 않습니다. 이력 원문은 아래에 그대로 두되, 큰 흐름은 세 칸으로 읽히게 합니다.

이력은 최근 4건만 펼치고 접습니다 — 전체는 10건이 넘어 화면을 다 먹는데, 대부분은 최신 상태만 봅니다. 첫 건만 잉크·채운 점이고 나머지는 회색·빈 점이라, 어디까지가 "지금"인지 한눈에 갈립니다. 하단 면책 한 줄은 택배사 API 지연 문의를 줄이는 장치입니다.

FAQ를 이 화면에 붙였습니다 — "배송완료인데 못 받았어요" 같은 질문은 바로 이 화면에서 생깁니다. 고객센터로 보내는 대신 §05 아코디언 규격으로 4건을 두고, 해결되지 않으면 문의로 이어집니다.

남은 결정 — ① 배송 기사 직통 전화 제공 여부(택배사 API 지원 범위) ② 미연동 브랜드(수기 송장)의 이력 미제공 처리 ③ FAQ 항목 확정(C16과 동기) ④ 합배송 시 송장 1개에 상품 여러 건을 묶어 보여줄지.

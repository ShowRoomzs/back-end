브랜드(판매자) 회원 상세 · 근거: SHOWROOMZ_웹_디자인시스템_v1_2.html · 목록은 ui-admin-14-brands.html · 소비자 상세는 ui-admin-13-consumer-detail.html · 셸·카드·필드행·모달·배지는 ui-admin-05-change-requests.html rev.6 재사용

[좌우 분업] 좌측은 사실 조회(기본·사업자·정산·배송반품·운영현황·연결 인플루언서 6카드), 우측은 판단과 조치이며 sticky 레일이라 좌측을 길게 내려도 조치 버튼이 따라온다 — 브랜드 상세는 좌측 카드가 7개라 스크롤이 길고, 배송 정책을 보다가 정지를 누르는 동선이 실제로 생긴다.
[스냅샷 2단 구성] 좌측 7카드는 1440×1024 한 화면에 들어오지 않는다(단일 열 실측 약 2,000px). 그래서 모든 회원 상태를 상단·하단 2장으로 낸다 — 상단: 기본·사업자·정산·배송반품(필드가 많은 카드는 2열 필드 그리드) / 하단: 운영 현황·연결 인플루언서·관리자 메모(처리 이력은 레일). 내용을 생략해 억지로 한 장에 담지 않는다 — 배송·반품 9필드, 연결 종료 행, 탈퇴 신청 접수·정지 이력 행이 모두 스펙 항목이므로 어느 하나도 빠지면 핸드오프가 성립하지 않는다. sticky 레일은 두 장 모두에 동일하게 들어간다. 레일은 상태 + 계정 상태 관리 2카드이며, 탈퇴 상태(A4·A4-b)는 조치가 없어 상태 카드 1개만 남는다.
[레일 처리 이력은 최신 3건 + 전체 N건 보기] 320px 레일에 이력을 전부 쌓으면 카드가 1,000px을 넘어 화면 밖으로 잘린다(A2-b 실측 1,040px). 레일 이력은 조치 직전에 최근에 무슨 일이 있었나를 보는 자리라 최신 몇 건이면 충분하고, 나머지는 전체 N건 보기로 펼친다 — 심사 카드가 붙는 A2-b는 최신 2건으로 더 줄였다(승인 근거인 이력이 잘리는 것이 가장 나쁘다).
[처리 이력은 레일 · 메모는 좌측] 처리 이력을 레일 맨 아래로 돌렸다 — 이력은 지금 내리는 조치의 근거다(“지난달에 이미 정지 한 번 했나”를 정지 버튼 옆에서 확인해야 한다). 레일에서 상태 → 조치 → 과거에 무엇을 했는지가 위에서 아래로 한 줄기로 읽힌다. 반면 관리자 메모는 좌측 맨 아래에 남긴다 — 300자 본문을 쓰고 읽는 카드라 320px 레일에서 다섯 줄로 접히면 읽히지 않는다. 즉 짧고 조치에 붙는 것은 레일 · 길게 읽는 것은 좌측이며, 둘 다 하단 스냅샷에서 확인한다(레일은 sticky라 이력도 상단에서 함께 따라온다).
[탈퇴 승인 · 소비자와 다른 점] 브랜드 탈퇴는 셀프서비스가 아니다 — 미배송 주문·진행중 공구·미정산액이 남으면 해지가 성립하지 않는다. 다만 그 조건은 브랜드 화면에서 신청 시점에 이미 강제되므로 — 셋 다 0이어야 신청 버튼이 열린다 — 어드민에 조건 검증 체크리스트를 두지 않는다. 늘 ✓만 뜨는 블록은 판단을 돕지 못하고 자리만 차지한다. 어드민이 하는 일은 사유와 경과를 보고 승인 또는 반려하는 것이고, 반려 사유 선택지는 조건 4항목과 같은 축으로 남긴다(신청 이후에 상황이 바뀐 건을 되돌릴 수 있어야 하므로).
[상태와 제재를 한 카드로] 계정 상태 관리 카드를 없애고 정지·정지 해제 버튼을 현재 상태 카드 맨 아래(구분선 아래)로 넣었다 — 상태와 그 상태를 바꾸는 버튼이 떨어져 있으면 운영자가 두 카드를 왕복해야 하고, 활성일 때 제재 카드는 버튼 하나만 든 빈 카드였다. 정지 상태에서는 사유·처리자·일시와 해제 버튼이 배지 바로 아래 같은 카드에 모인다. 남은 축은 현재 상태(활성·정지·탈퇴 + 제재 버튼)와 탈퇴 신청 심사(승인 대기 건) 둘이다 — 신청은 상태가 아니라 처리해야 할 건이다. 승인 전까지 브랜드는 실제로 활성이고(공구가 돌고 주문이 들어온다) 승인된 순간에만 회원 상태가 탈퇴로 내려가므로, 대기를 회원 상태 배지에 올리면 영업 중인 브랜드를 이미 나간 것처럼 보이게 한다. 심사 카드는 신청이 접수된 A2에만 그려지고, 정지는 회원 상태에 그대로 올린다(목록의 상태 열과 어긋나면 안 된다). 심사 중에도 정지는 실행될 수 있다 — 현재 상태 카드의 정지 버튼이 계속 살아 있는 이유다.
[상태 색 매핑] 활성=성공 / 심사 카드의 탈퇴 승인 대기=경고(운영자 조치 필요 · 원칙 ①) / 정지=위험 / 탈퇴=중립(원칙 ② 해지). 정지 버튼은 흰 배경 + 중립 테두리 + 위험색 글자이며 꽉 찬 위험색은 모달의 최종 실행 버튼에만 쓴다(소비자 상세와 동일).
[정지의 범위] 상품 등록·공구 개설·정산 신청은 막고 진행 중 공구와 미배송 주문은 유지한다 — 브랜드 제재로 소비자 피해를 만들지 않기 위함이다. 정산은 보류이며 소명은 1:1 문의로만 받는다(소비자 상세와 같은 원칙).
[미정산액 강조] 4-KPI 중 미정산액만 0원이 아니면 경고색으로 올린다 — 탈퇴 승인·정지 판단에서 유일하게 “돈이 걸린” 수치다.
[계좌번호 마스킹] 정산 정보의 계좌번호는 가운데를 가리고 전체 값은 정산 관리에서만 조회한다 — 회원 관리 화면의 목적은 신원 확인이고 송금은 다른 화면의 일이다. 소비자 상세처럼 이 화면에 해제 버튼을 두지 않았다.
[배송·반품 정책은 조회 전용] 브랜드가 입력한 값이며 운영자가 고치지 않는다 — 정책은 소비자 고지 대상이라 운영자가 임의로 바꾸면 고지 이력과 어긋난다.
[메모 규칙 충돌 → 누적 기입 채택] 지시서에는 “500자 · 저장 버튼”으로 적혀 있으나, 직전 확정된 메모 규칙(조치하지 않은 판단의 기록 · 누적 기입 · 항목당 300자 · 작성자 본인 24시간 내 수정·삭제)을 F4·F5에도 동일 적용하기로 한 결정이 있어 그쪽을 따랐다. 덮어쓰기 500자로 돌릴지 확인이 필요하다. 고지 문구는 브랜드 맥락에 맞춰 정산·분쟁 시 증빙 인용 가능성으로 바꿨다.
[금칙어] 마켓·판매자 → 브랜드. 예외는 “브랜드(판매자) 약관” 등 법정·계약 표기뿐이다.
[확인 필요] ⓐ 탈퇴 승인 SLA(현재 “경과 6일”만 표기) ⓑ 승인 후 남은 반품의 운영자 대행 처리 화면 소관 ⓒ 연결 인플루언서 연결 종료 행을 목록에 남길 기간 ⓓ 택배사 연동 해제 시 배송 정책 카드 표기 ⓔ 사업자 정보 변경 이력을 이 화면에서 볼지(현재는 변경 요청 화면 소관).
[⚠ 법률 자문 대기] 탈퇴 승인 시 보존·파기 범위는 소비자와 동일하게 쟁점 G 종속이다 — 시안에는 주문·정산 기록 보존 / 사업자·정산 정보 파기로 그렸다.
[규격 정합] 상세 필드 행 9px · 라벨 140px, 테이블 본문 셀 14px 16px · 행높이 50px. 설계 근거는 이 박스와 .state-spec에만 둔다.
A1활성 브랜드 · 상단기본 진입 — 좌측 상단 4카드(기본·사업자·정산·배송반품)와 우측 sticky 레일 현재 상태 1카드(맨 아래에 정지 버튼) — 탈퇴 신청 심사 카드는 신청이 접수된 A2에만 나타난다 · 필드가 많은 카드는 2열 필드 그리드로 접어 한 화면에 담았다 — 값이 열 폭을 넘으면 잘리지 않고 두 줄로 흐른다(주소처럼 긴 값 대비 · 라벨은 상단 정렬) · 액션은 정지 단독이며 탈퇴 관련 버튼은 없다(신청이 없으면 심사할 것도 없다) · 사이트 링크는 외부 이동이라 ↗ 아이콘을 붙인다 · 하단 카드(운영 현황·연결 인플루언서·관리자 메모)와 레일의 처리 이력은 A1-b에서 본다

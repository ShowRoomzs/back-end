[리워드 지급자 = 플랫폼 · 부가세 별도 · 2026.10.07] 리워드는 플랫폼이 인플루언서에게 지급하는 구조로 확정했다(PG 3자 분배는 그대로 · 리워드 몫이 플랫폼 명의로 지급대행). 그래서 ① 비사업자 3.3%는 플랫폼이 원천징수 의무자 — 영수증 자동 발행 · 스튜디오에서 다운로드 ② 사업자 인플루언서는 플랫폼 앞으로 역발행(승인 전 지급 보류) ③ 브랜드는 리워드를 플랫폼에서 산 마케팅 서비스로 보고 플랫폼이 세금계산서 1장(공급가 = 리워드 · 부가세 10% 별도)을 발행 — 금액 분해에 리워드 부가세 줄이 생기고 그만큼 브랜드 수취액이 줄어든다(일반과세 브랜드는 매입세액으로 공제). 인플루언서 리워드는 계약서 숫자 그대로다. 차감(클로백)은 플랫폼이 브랜드에 마이너스 수정세금계산서, 인플루언서는 다음 지급분 차감 후 금액으로 원천징수. 세율(3.3%)은 백엔드 변수 — 플랫폼 종사자 세율 개정 가능성 때문에 문구에 고정하지 않는다. 원천징수 의무자 [자문대기-세무]는 해소, 구조 점검만 세무사 확인.
[좌우 분업] 좌측은 돈의 사실(개요·분해·3자 분배·증빙·고정 지급비·명세), 우측 sticky 레일은 상태와 조치(현재 상태 + 액션 · 처리 이력)다 — 회원·브랜드 상세와 같은 골격이며 셸·카드·필드행·모달을 ui-admin-15-brand-detail.html에서 그대로 가져왔다. 좌측 카드가 많아 상단·하단 2장으로 낸다.
[두 축을 한 표에 쌓는다] 파트너센터는 브랜드 수취액까지, 쇼룸 스튜디오는 내 실지급액까지만 분해한다. 어드민은 브랜드 축(확정 거래액 − PG − 플랫폼 − 리워드)과 인플루언서 축(리워드 − 원천징수)을 위아래로 쌓았다 — 두 축이 만나는 지점이 판매 리워드이고, 표를 나누면 그 연결이 끊겨 검산이 안 된다. 스튜디오가 “플랫폼·PG 수수료 행을 넣지 않은” 이유(내 리워드에서 차감되지 않는데 차감되는 것처럼 읽힌다)는 어드민에서 성립하지 않는다 — 운영자는 전체 흐름을 봐야 한다.
[3자 분배 — 플랫폼이 나눠주는 게 아니다] 소비자 결제금은 PG에서 브랜드·인플루언서·플랫폼에게 각각 직접 지급된다. 합계가 확정 거래액 − 원천징수와 맞는지 tfoot에서 확인되고, 차액은 플랫폼이 납세 대리로 보유하는 원천징수분이다. 이 블록이 있어야 “돈이 안 들어왔다”는 문의에 누구에게 물어야 하는지를 답할 수 있다.
[분배 실패 = 어드민 전용 · 유일한 위험색] 3자 분배라 한쪽 계좌가 막히면 그 몫만 반환되고 나머지는 정상 지급된다(D5에서 브랜드=지급 완료 / 인플루언서=분배 실패로 갈린다). 수취자 화면에는 「지급 완료」로 보이는데 돈이 없으므로 운영자가 먼저 알아야 한다. 보류와의 차이 — 보류는 금액이 바뀔 수 있는 상태(경고), 실패는 금액은 맞고 전달만 실패한 상태(위험)다. 조치는 재분배이고 금액을 재계산하지 않는다.
[정산은 주문 종결 후 생긴다 · 2026.10.06] 정산이 생기는 시점에 금액은 이미 확정 거래액이라 회색·예정 표시를 없앴다(D2). 상단 단계 줄(주문 종결 › 정산 확인 3영업일 › 조정 협의 › 자동 확정 › 지급)이 위치를 보여주고, 조정 요청이 없던 회차는 「조정 협의」에 취소선을 긋는다. 명세 다운로드만 확정 전 비활성이다.
[돈은 이 화면에서도 나가지 않는다] 지급은 예정일에 PG가 자동 실행하고, 확정도 확인 기간 경과 시 자동이다. 운영자 액션은 재분배 하나다(분배 실패 · M3). 확정 · 보류 · 보류 해제 버튼과 구 M1 확정 모달 · 구 M2 보류 해제 모달은 모두 삭제했다. 지급일을 앞당기는 버튼도 없다.
[상태별 액션] 정산 확인 중 · 조정 협의 · 지급 예정 · 지급 완료 → 조치 없음 · 분배 실패 → 재분배. 직권 보류는 두지 않는다 — 확정 후 환불(리콜 · 확정 후 하자)은 다음 정산에서 차감한다(D3 차감 반영 블록 · 07a 차감 탭).
[보류 해제는 자동 · 2026.10.06] 한쪽이 정산 확인 기간에 정산 조정 요청을 내면 정산이 전액 보류되고 이슈 스레드가 열린다. 양측이 금액에 합의하면 시스템이 금액을 바꾸고 · 보류를 풀고 · 이슈를 닫는다. 합의 기한(개설 + 10영업일)이 지나면 원래 금액으로 확정한다. 운영자는 조정안을 내지 않고 승인하지도 않는다 — 그래서 구 M2 보류 해제 모달을 삭제했다. 보류 중에는 브랜드 몫도 함께 정지한다(합의 금액이 브랜드 수취액도 옮기므로 · 차액 선지급 없음).
[고정 지급비 = 계약 조건만] 모델 B — 브랜드가 인플루언서에게 직접 지급해 플랫폼을 지나지 않는다. 지급 여부 · 원천징수 · 실지급을 표시하지 않고 계약 금액 · 지급 시점만 읽기 전용으로 둔다. 「공구 총 수령액」 합산도 없앴다.
[같은 값을 두 곳에 쓰지 않는다] 정산 확정일·지급(예정)일은 우측 레일의 상태 메타에 있으므로 좌측 개요에서 뺐고, 분해 표의 행별 주석(“PG사가 먼저 차감한다”·“인플루언서 몫으로 분배”)은 축 헤더가 이미 말하는 문장이라 걷어냈다 — 중복은 읽는 시간만 늘리지 않고 프레임 하나에 6블록이 들어가지 못하게 만든다(1440×1024 고정 아트보드에서 세로는 예산이다).
[한 줄짜리 표는 표로 두지 않는다] 증빙·고정 지급비는 공구당 한 건이라 헤더 + 1행짜리 표가 되어 전폭에 빈 칸만 늘어선다 — 비교할 다른 행이 없으면 표의 일(열 정렬로 행을 견주기)이 없다. 인라인 요약 바로 바꿨고 관리 버튼은 바 우측 끝에 둔다(쇼룸 스튜디오 규칙 승계).
[원천징수는 사업자 여부로 갈린다] 비사업자는 리워드에서 3.3%(소득세 3% + 지방세 0.3%) 차감 + 원천징수영수증(D1), 사업자는 차감 없이 전액 + 세금계산서 수취(D6). 발행 주체는 인플루언서이고 플랫폼이 대행하지 않는다 — 쇼룸 스튜디오에서 “내 조치”였던 항목이고 어드민은 방치 건을 보는 쪽이다.
[상태 색 매핑] 정산 확인 중=정보 · 조정 협의=경고(진행이 멈춤 · 원칙 ①) · 지급 예정=중립 · 지급 완료=성공 · 분배 실패=위험(유일).
[필수 미입력 = 버튼 비활성만] 에러 문구는 형식 오류·중복에만 뜬다. 비활성 버튼에 인라인 opacity를 덧씌우지 않는다.

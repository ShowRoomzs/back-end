[상태 색 매핑] 시행중=성공 / 시행 예정=정보 / 구버전·과거 버전=중립.
[용어 2단] 상태어는 층이 다르다 — 문서 목록에서는 후속 문서로 대체돼 더는 시행되지 않는 문서를 구버전, 버전 이력에서는 같은 문서 안에서 교체된 지난 버전을 과거 버전이라 부른다. 색은 둘 다 중립이다.
[개편 · 목록 구조] 카드 나열 + 하단 이력 → 문서 목록(표) + 문서 상세로 바꿨다. 약관·정책·개인정보 문서가 늘어나면 카드 나열은 세로로 무한히 길어지고 검색·필터를 붙일 자리가 없다. 문서 1건 = 1행, 버전 이력은 상세로 내렸다.
[와이어 수정] ⓐ 관리 열의 [상세] 버튼은 두지 않았다 — 디자인시스템 규칙(“행 클릭으로 상세 이동, 별도 상세 버튼 금지”)과 충돌해 행 클릭으로 대체하고, 관리 열에는 실제 액션인 새 버전 등록을 넣었다. ⓑ 유형 탭에 전체를 더해 4탭으로 했다 — 문서명 검색은 유형을 넘나든다. ⓒ 대상·상태 셀렉트는 두지 않았다 — 문서가 10건 안팎이라 유형 탭 + 문서명 검색으로 충분하고, 대상은 목록 열에서 바로 읽힌다.
[와이어 수정] ⓐ 약관은 카드와 이력 표의 연결이 없어 선택 카드 강조 + 하단 이력 갱신 구조로 바꿨다. ⓑ 새 버전 등록의 체크리스트는 와이어에서도 라벨만 있고 컨트롤이 없어 삭제했다 — 운영 절차 확인은 화면 밖 업무다.
[법률 대기] 개정 고지 방법·의무·사전 고지 기간은 변호사 확인 대기 — “사전 고지 21일”은 임시 표기다. 문서 범위는 현재 8종(이용 약관 3 · 개인정보처리방침 2 · 마케팅 목적 개인정보 수집·이용 동의 3)이며 운영정책 편입 여부는 미정이다(약관후속패치리스트 #4·#5).
[규격 정합] 테이블 본문 셀은 어드민 공통 규격대로 14px 16px · 행높이 50px(ui-admin-05 실측 13px과 1px 차이 — 디자인시스템 파일의 미결 항목). 상세 필드 행은 9px · 라벨 140px(.frow).
[주석 분리] 설계 근거는 이 박스와 각 상태의 .state-spec에만 둔다 — .stage 안에는 규칙 메모를 넣지 않았다.

[브랜드 큐와 같은 탭 · 같은 건수] 탭 7개와 건수가 파트너 11-claims와 같다(전체 12 = 3+2+2+1+1+3). CS 통화에서 운영자와 브랜드가 같은 단계 이름을 써야 한다. 어드민 전용 열은 브랜드 · 귀책 둘. 반품·교환은 탭으로 나누지 않고 유형 열로 구분한다(색 없음).
[운영자가 실행하는 일은 하나] 반려에 대한 소비자 이의를 인용하는 운영자 사유 환불(B2)뿐이다. 회수·입고·검수·재발송은 소비자와 브랜드의 일이고, 신청 단계 반려는 없다. 기각은 버튼이 아니라 스레드 답변이다(반려가 그대로 유지되므로). 구매확정 후 하자는 06a B6에서 대신 열고 이후는 일반 반품과 같다(B4).
[기한 2종 · 2영업일] 회수 대기 방치(신청 → 소비자 송장 입력)와 검수 완료(입고 확인 → 판정). 넘기면 시스템 자동 알림 · 06d 처리 지연이 센다 · 독촉 버튼 없음. 회수 송장 7일 미입력은 자동 취소. 영업일 = 주말·공휴일 제외.
[환불 계산식] 상품 금액 − 최초 배송비(무료배송 + 소비자 귀책일 때 3,000원) − 재발송비(일부 반려일 때 3,000원). 전체 반려는 재발송비를 소비자가 따로 결제하고, 일부 반려는 통과분 환불에서 뺀다(B3). 귀책은 항목 단위로 적는다 — 일부 반려에서 갈리기 때문이다.
[구매확정 타이머] 신청 시 정지 → 철회·자동 취소 시 남은 일수부터 재개 · 교환 완료 시 7일 새로 시작. 상세 금액 블록에 남은 일수를 적는다.
[상태색] 단계는 정보(정상 진행) · 검수 지연만 경고 · 환불·교환 완료 = 성공 · 반려 종결 = 중립. 소비자 이의는 보조줄 경고(운영자 조치 필요).
[확인 필요] ⓐ 반려 고지 간격(2회 고지 사이 일수) ⓑ 보관 기한 경과 후 처리(약관 반영 대기) ⓒ 교환 반려 시 이의 경로 — 시안은 반품과 같은 운영자 사유 환불로 그렸으나 교환은 환불이 아니라 원래 상품 반송이 기본이다 ⓓ 운영자 개설 클레임의 개설 취소 권한 ⓔ 사이드바 「반품·교환」 배지 = 소비자 이의 건수(1)로 잡았다 — 검수 지연까지 셀지.

카드가 아니라 행 — 배송지는 글자만으로 판별되는 정보라 테두리 카드로 감싸지 않고 0.5px 구분선 행으로 두었습니다. 받는 분 → 연락처 → 주소 → 배송 메모 순으로, 받는 분 이름이 가장 크고 굵게입니다 — 별칭(집·회사)을 없앴으므로 배송지를 구별하는 첫 단서는 누구에게 가는가입니다.

기본 배송지 — 로즈 틴트 배지로 표시하고, 기본이 아닌 항목에만 [기본으로 설정]이 붙습니다(눌러 보세요). 기본 배송지 행에는 그 버튼이 없어 이미 기본이라는 사실이 버튼 부재로도 읽힙니다.

액션 배치 — [기본으로 설정]은 이름 줄 우측에 작은 외곽선 버튼(높이 30 · 라벨 11.5)으로 두었습니다 — 아래 편집 버튼(34)보다 한 단계 작아 같은 줄의 배지와 무게가 맞습니다. 기본 배송지 배지와 같은 줄이라 상태와 그 상태를 바꾸는 버튼이 나란히 놓이고, 아래 줄은 편집 계열([수정]·[삭제])만 남아 성격이 갈립니다. 기본 배송지 행에는 배지만 있고 버튼이 없습니다. 우측 끝 아이콘(⋯)으로 숨기면 탭 수가 늘고, 배송지는 자주 손대는 데이터가 아니라 발견성이 더 중요합니다. 삭제도 중립 외곽선이며 로즈는 쓰지 않습니다(파괴적 액션에 강조색 금지 규칙).

삭제 확인 — 받는 분과 주소를 모달 문구에 넣어 어느 것을 지우는지 명시합니다. 좌 [취소](중립 외곽선) / 우 [삭제하기](로즈 채움) 배치입니다 — 확인 모달은 이미 한 번 걸러진 단계라, 여기서는 이 모달에서 하려던 일을 주 버튼으로 둡니다.

남은 결정 — ① 배송지 개수 상한(보통 10~20개) ② 기본 배송지 삭제 시 다음 기본을 자동 지정할지 ③ 최근 배송지 자동 저장 여부 ④ 결제 화면에서의 배송지 선택 시트를 이 목록과 공유할지.

순서 — 받는 분 → 연락처 → 주소 → 배송 메모 → 기본 설정.

주소 — 우편번호 + [주소 검색](잉크 채움) → 도로명 주소(자동 입력) → 상세 주소. 도로명은 검색 결과로만 채워지는 필드라 직접 타이핑하지 않게 두었고(입력 전에는 회색 배경 + "주소 검색으로 입력돼요"로 스스로 못 쓰는 칸임을 알림), 상세 주소만 사용자가 씁니다. 우측 Tweaks의 form으로 입력 전·후를 확인해 보세요.

저장 활성 조건 — 필수 항목(받는 분 · 연락처 · 우편번호 · 도로명 · 상세 주소)이 모두 채워져야 [저장]이 로즈로 켜집니다. 입력 전에는 회색 비활성이고, 버튼을 숨기지는 않습니다 — 무엇을 향해 입력하는지가 보여야 끝이 예측됩니다. 배송 메모는 선택이라 활성 조건에서 제외했습니다. 주소 검색 버튼은 중립 외곽선입니다 — 이 화면의 주 액션은 하단 [저장]이고, 폼 안의 보조 액션이 색으로 앞서면 안 됩니다.

배송 메모 — 자유 입력 대신 시트 선택이 기본입니다(문 앞에 두세요 · 경비실에 맡겨주세요 · 배송 전 연락 주세요 · 부재 시 전화 · 직접 입력). 자유 입력만 두면 기사에게 전달되지 않는 문장이 쌓입니다. [직접 입력]을 고르면 그 아래 입력 필드가 펼쳐지고 50자 제한이 붙습니다(시트에서 골라 확인해 보세요) — 송장에 실리는 문구라 길면 잘리므로, 글자 수를 필드 우측에 상시 노출합니다.

주소 검색 — 카카오 우편번호 서비스(Daum Postcode)를 연동합니다. SDK가 자체 검색 UI를 오버레이로 제공하므로 앞단에서 검색 화면을 따로 그리지 않습니다 — 직접 만들면 검색어 처리·지번 병기·건물명 매칭을 중복 구현하게 되고 도로명 개정도 직접 따라가야 합니다. 선택 결과(우편번호·도로명)를 받아 이 화면의 두 필드를 채우고 상세 주소 칸으로 포커스를 이동시킵니다.

남은 결정 — ① 카카오 SDK 오버레이의 테마 커스터마이징 범위 ② 공동현관 비밀번호 필드 필요 여부 ③ 연락처 인증(본인 명의 외 수취인) 정책 ④ 배송 메모 직접 입력 시 글자 수 상한.

## 17. 어드민 1:1 문의 (CS) — [v0.25 신설]

대상 화면: `ui-admin-06-inquiry.html` (**rev.2**), 상태 6종(목록 2 · 상세 3 · 모달 1). 셸·테이블·모달·배지는 §16(`ui-admin-05-change-requests.html`) 컴포넌트를 그대로 재사용하고 도메인만 교체했다. 근거 와이어는 `wf-admin-08-CS콘텐츠관리` **F1~F2**(F3·F4는 상품 문의 모니터링 — §18 예정, 이 섹션 범위 아님).

**성격** — 심사(§5·§9·§16)와 다르다. 승인/반려 **판정**이 아니라 **답변 작성 1회**로 끝나는 단일 액션 화면이다. 대신 **응답 속도(SLA)**가 유일한 관리 지표다.

> **[정합 경고]** 도메인모델 §12(CS 문의)와 이 섹션은 **3곳이 어긋나 있다.** 시안이 문서보다 앞서 있는 상태이며 김화창님 확인 후 도메인모델 쪽을 패치해야 한다 — 17-8 미결 1·2·3번.
> 

### 17-1. 상태 정의 — 2단계 — `FE`·`BE`

| 상태 | 의미 | 배지 색 |
| --- | --- | --- |
| 접수 | 소비자 문의가 들어왔고 아직 답변이 없음 | **정보(파랑)** |
| 답변완료 | 운영자 답변이 등록됨 — 종료 상태 | **중립(회색)** |

| 항목 | 규칙 |
| --- | --- |
| 처리중·종료 | **두지 않는다**(운영 확정). 답변이 1회 등록·수정 불가 구조라 "처리중"에 머무는 실제 구간이 없고, 상태를 늘리면 운영자가 수동으로 바꿔줘야 하는 관리 부담만 생긴다 |
| 상태 전이 | 접수 → 답변완료 **단방향 1회.** 되돌리는 경로 없음 |
| 전이 트리거 | **답변 등록 성공** 단 하나. 운영자가 상태만 따로 바꾸는 조작은 제공하지 않는다 |
| 접수를 경고색으로 하지 않는 이유 | 접수는 정상 유입이지 이상 상태가 아니다(§9 상태색 4원칙 ①의 "운영자 조치 필요"에 해당하나 **운영 판단으로 정보색 확정**). 목록 전체가 경고색으로 물드는 것을 피했고, 미답변 압박은 17-6의 경과·SLA가 대신한다 |
| 답변완료가 중립인 이유 | 운영자 손을 떠난 종료 상태 — 원칙 ② |

> **도메인모델 충돌** — `SHOWROOMZ_도메인모델_규칙` §12-1의 상태는 **접수 / 처리중 / 답변완료 / 종료 4종**이다. 본 섹션은 상태 값을 재정의하는 것이 아니라 **1:1 문의(기타 유형)에 한해 2종만 사용**함을 확정한 것이며, 도메인모델 enum 자체를 2종으로 줄일지는 상품 문의(§18)까지 확정한 뒤 함께 판단한다(17-8 미결 1번).

**의도적으로 두지 않는 것** — 참조 주문 컬럼(상세에서 확인, 목록에서는 폭만 먹고 판별에 쓰이지 않음) · 담당자 배정 · CSV 내보내기 · 사용자 정렬 셀렉트.

### 17-2-1. 문의 유형 — FAQ 카테고리와 동일 5종 — `FE`·`BE`

| 유형 | 포괄 범위 |
| --- | --- |
| 배송 | 배송 조회·지연·송장 |
| 취소/교환/반품 | 취소·교환·반품·환불금 미입금 (구 `환불` 대체) |
| 주문·결제 | 결제 수단·쿠폰 적용·주문 변경 (구 `주문` 대체) |
| 서비스 | 공구·쇼룸 등 서비스 이용 문의 |
| 계정 | 가입·탈퇴·로그인 |

| 항목 | 규칙 |
| --- | --- |
| **단일 소스 원칙** | 이 목록은 **FAQ 카테고리와 동일해야 한다.** 한쪽만 바뀌면 대조가 깨지므로 **enum 하나를 두 화면이 공유**한다 |
| 폐기 값 | `환불` · `주문` · `기타` — 재사용하지 않는다 |
| **`기타` 미운영** | `기타`가 있으면 소비자가 고민 없이 거기로 몰려 유형별 집계가 무의미해진다. 5종이 실제 문의를 대부분 포괄한다 |
| 선택 주체 | 소비자가 앱 문의 작성 시 선택. **운영자가 나중에 바꾸는 경로는 두지 않는다** |

**FAQ와 맞추는 이유** — 같은 문의를 소비자는 **FAQ에서 먼저 찾고, 못 찾으면 1:1로 넘어온다.** 두 곳의 분류 체계가 다르면 "어떤 유형의 문의가 많은가"를 "어떤 FAQ를 보강해야 하는가"로 연결할 수 없다. **CS 데이터가 콘텐츠 개선으로 이어지는 경로**가 이 통일에 걸려 있다.

| 처리 패널 | 현재 상태 + 메타 — **접수: 접수일시·미답변 경과 / 답변완료: 접수일시·답변일시·응답 소요·처리자** |
| 처리 이력 | 문의 접수(정보) → 답변 등록(중립) 타임라인, 시간 역순 |
| 이동 | `[목록]` · `[‹ 이전]` · `[다음 ›]` — **현재 탭의 목록 순서**를 따른다 |

| 항목 | 규칙 |
| --- | --- |
| 참조 주문 | **선택값이다.** 앱에서 주문 없이도 문의할 수 있으므로 `—` 케이스를 반드시 처리한다 |
| 처리자 | 답변을 등록한 운영자 계정. 답변완료 상태에서만 값이 있다 |
| 답변완료 시 패널 | 카드를 **없애지 않고 유지**한다 — 상태별로 카드가 사라지면 레이아웃이 점프한다. 액션 버튼 자리만 비운다 |

### 17-4. 답변 등록 — `FE`·`BE`

| 항목 | 규칙 |
| --- | --- |
| 입력 | 답변 본문 **필수**, 단일 textarea. 소비자에게 **가공 없이 그대로** 노출된다 |
| 미입력 처리 | **에러 문구 없이 버튼 비활성만** — 다른 화면의 필수값 처리 원칙(§8-1·§10)과 동일 |
| 확인 모달 | **필수.** 본문에 **발송될 답변 원문을 그대로 미리보기**로 넣는다 |
| 모달 버튼 | 취소 / **등록** — 파괴적 액션이 아니므로 주 액션(파랑). 반려처럼 사유 입력을 받지 않는다 |
| 등록 후 | 소비자에게 **즉시 발송** → 상태 답변완료 전환 → 접수 대기열·GNB 배지에서 제외 |
| 수정·삭제 | **불가.** 등록은 1회뿐이다 |
| 알림 | 답변 등록 시 소비자에게 알림 발송(도메인모델 #11) |

**확인 모달을 두는 이유** — 등록 후 수정·삭제가 불가능하고 문구가 소비자에게 그대로 간다. 잘못된 스레드에 답변하거나 오타가 난 채로 나가면 **회수 경로가 없다.** 모달에 원문을 다시 보여주는 것이 유일한 방어선이다.

> **도메인모델 충돌** — §12-2는 문의 1 : N 답변(**게시판형 주고받기**)이다. 이 화면은 **운영자 답변 1회로 종료**이며 소비자 재질문 경로가 없다. 재질문은 신규 문의로 접수된다. 어느 쪽으로 확정할지 판단 필요(17-8 미결 2번).
> 

### 17-5. 첨부 사진 — `FE`·`BE`

| 항목 | 규칙 |
| --- | --- |
| 소비자 첨부 | 문의 1건당 **최대 5장** |
| 표시 | 스레드 메시지 하단에 `첨부 사진 N장` + 72px 썸네일 한 줄(5장이 한 줄에 들어간다) |
| 확대 | 썸네일 클릭 시 라이트박스(모달 1080px 변형) |
| **운영자 답변 첨부** | **미지원** — 요건에 없다. 캡처 안내가 필요하면 FAQ·공지 링크로 유도하는 편이 CS 이력 관리에 유리하다 |

환불·배송 문의는 소비자가 **상품 상태 사진을 근거로 붙이는 경우가 대부분**이라 첨부가 CS 판단의 핵심 자료다. 도메인모델 §12-1에는 첨부 속성이 없어 추가가 필요하다(17-8 미결 3번).

### 17-6. 경과 · SLA — `FE`·`BE`

**경과는 모든 행에 값이 있다.** 미답변이면 "아직 안 된 시간", 답변된 건이면 "걸린 시간"이다 — 컬럼이 비는 케이스가 없다는 점이 구현 시 놓치기 쉽다.

| 구분 | 계산 | 상세 화면 라벨 |
| --- | --- | --- |
| 접수(미답변) | 접수일시 → **현재 시각** | `미답변 경과` |
| 답변완료 | 접수일시 → 답변일시 | `응답 소요` |

**SLA 초과 기준 — 경과 3일**

| 경과 | 상태 컬럼 | 경과 값 |
| --- | --- | --- |
| 3일 이하 | `접수`(정보) 또는 `답변완료`(중립) | 기본 |
| **3일 초과** | **`SLA 초과`(경고색)로 교체** — 접수 배지와 **병기하지 않는다** | 굵은 경고색 |

| 항목 | 규칙 |
| --- | --- |
| 표기 단위 | `3일 2h` · `19h 42m` · `2h 15m` — 24시간 미만이면 일 단위 생략 |
| 계산 주체 | **서버 계산값을 내려준다.** 클라이언트 시각 기준으로 계산하면 사용자 PC 시각이 틀어졌을 때 SLA 표시가 어긋난다 |
| 병기하지 않는 이유 | 한 칸에 배지 2개가 들어가면 컬럼 폭이 무너지고, 초과 건은 어차피 전부 접수 상태라 정보 손실이 없다 |

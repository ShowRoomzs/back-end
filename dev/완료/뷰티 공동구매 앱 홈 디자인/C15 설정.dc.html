회원정보 변경 — 값 자체를 편집하는 폼이 아니라 재인증으로 갱신하는 구조입니다(통신사 원장 값이라 직접 입력은 오히려 신뢰를 떨어뜨립니다). 동의 체크박스와 버튼은 하단 고정 영역에 함께 두어(스크롤과 무관하게 항상 보임) 체크 → 실행이 한 시선에 들어옵니다. 체크해야 버튼이 로즈로 활성화되고(체크를 눌러 확인해 보세요), 누르면 PASS 인증창으로 넘어갑니다(자체 대기 모달은 제거 — 인증 사업자 SDK의 로딩 화면과 중복). 인증 완료 후 이름·생년월일·성별·휴대폰번호가 자동 업데이트되고 이 화면으로 복귀합니다.

동의를 매번 다시 받는 이유는 가입 시 동의와 별개의 새 수집 행위이기 때문입니다 — 동의 일시는 기록해 회원정보 이력에 남깁니다. 로그인 수단 행은 제거했습니다(소셜 단일이라 정보 가치가 없고, 변경 수단도 없음).

남은 결정 — ① 재인증 결과가 기존 명의와 다를 때(타인 명의 확인) 처리 정책 ② 갱신 이력 보관 기간 ③ 동의 문구 법무 검토.

조회 전용 — 수정 가능한 값이 없으므로 셰브런을 붙이지 않았습니다(탭해도 아무 일 없는 행을 만들지 않기 위해). 라벨은 회색·값은 굵게 두어 왼쪽에서 라벨, 오른쪽에서 값을 훑을 수 있게 했습니다. 본인인증 정보(이름·생년월일·휴대폰번호)는 PASS 결과이므로 마스킹해 표기했습니다.

2단계 · 확인 — 차단 사유(있을 때) → 결과 고지 3가지 → 1단계에서 고른 이유 확인 → 하단 고정 동의 + [탈퇴하기]. 진행 중 주문이 있으면 탈퇴를 막고 이유와 확인 경로를 함께 보여줍니다(우측 Tweaks의 blockers로 두 상태 전환 — 차단 상태에서는 동의·버튼이 계속 비활성입니다).

고지 — 삭제되는 것과 법정 기간 보관되는 것을 나눠 적었습니다. 전자상거래법상 거래 기록은 즉시 파기할 수 없으므로 "모두 삭제된다"고만 쓰면 사실과 다릅니다. 재가입 가능 여부도 미리 알려 문의를 줄입니다.

파괴적 액션 처리 — 하단에 [탈퇴하기](좌 · 중립 외곽선 — 로즈를 쓰지 않습니다)와 [계속 사용하기](우 · 로즈 채움)를 나란히 두어, 오른손 엄지가 닿는 쪽이 항상 머무는 선택이 되게 했습니다. [탈퇴하기] → 최종 확인 모달 → 확정 시 완료 모달(탈퇴가 완료되었습니다 + 법정 보관 안내) 순으로 이어지고, 확인을 누르면 비로그인 홈으로 나갑니다. 모달 문구에 잃게 되는 것의 실제 개수를 넣어 마지막으로 한 번 더 실감하게 했습니다.

남은 결정 — ① 법정 보관 항목·기간의 정확한 문구(법무) ② 재가입 제한 기간을 둘지(어뷰징 방지 목적의 30일 제한 등) ③ 탈퇴 이유 항목 확정 ④ 진행 중 주문의 정의(배송 완료 후 교환·환불 기간까지 포함할지).

취소 반려 이력 — 반려되면 주문은 일반 배송 흐름으로 돌아가므로 상태 라벨은 실제 상태(배송중)를 그대로 쓰고, 그 아래에 회색 한 줄 "취소 요청 반려 · 사유 보기 ›"를 붙입니다(09.12 주문의 배송중 상품). 누르면 1d 취소 상세의 반려 상태로 갑니다. 반려 화면으로 들어오는 주 경로는 푸시·앱 내 알림이고, 이 줄은 나중에 다시 찾을 때를 위한 것입니다. 배송완료 후 반품 기간이 끝나면 사라집니다 — 반려 사실은 "받은 뒤 반품할 수 있다"로 이어질 때만 의미가 있기 때문입니다. 주문 상태를 "취소 반려"로 바꾸거나 모달로 알리지 않습니다.

[반품 · 교환] → 주문 상세 — 목록 카드는 버튼 하나만 둡니다. 누르면 C10-1 주문 상세로 이동하고, 거기서 해당 상품 행의 [반품 요청] / [교환 요청] 중 하나를 고릅니다. 반품·교환은 수량·환불 금액·배송지를 확인한 뒤 결정하는 행동이라 상세를 거치는 한 단계가 헛걸음이 아니고, 목록 카드는 버튼 2개로 가볍게 유지됩니다.

항목 단위 행 — 같은 주문·같은 브랜드라도 옵션(SKU)마다 행을 분리합니다. 취소·반품·교환이 항목 단위로 일어나므로 한 행에 두 항목을 묶으면 "어느 것을 반품하는지"가 목록에서 사라집니다. 주문일은 그룹 머리로 한 번만 적고, 그룹 사이는 5px 밴드 — C8 장바구니의 쇼룸 그룹과 같은 문법입니다(카드 테두리를 쓰지 않는 이유도 같습니다).

그룹 머리 = 날짜 + 주문번호 + [주문 상세]로, C10-1 주문 상세의 상단과 같은 형식(26.09.12 (금) / 주문번호 20260912030201)을 씁니다. 목록에서 주문번호를 자주 읽지는 않지만, 상세·배송 조회·1:1 문의가 모두 이 번호로 대화하므로 목록과 상세의 표기가 어긋나면 같은 주문인지 확인하는 단계가 생깁니다. 11.5px 회색 보조 줄로 낮춰 날짜가 먼저 읽히게 했습니다.

상태는 칩이 아니라 글씨 — 배지로 감싸지 않고 굵기·색만 다르게 둡니다. 한 화면에 상태 표기가 6~7개 반복되는 목록에서 칩을 쓰면 알약이 줄줄이 늘어서 상품보다 배지가 먼저 읽히고, 칩은 누를 수 있어 보여 오해도 생깁니다. 굵기는 13/700로 통일하고 색으로만 층을 나눕니다 — 로즈: 지금 볼·할 것이 있는 상태(결제완료 = 취소 가능 / 배송중 = 추적 가능 / 배송완료 = 반품·교환 기한), #737373: 개입할 수 없는 상태(상품준비중 · 구매확정 · 취소 · 반품 · 교환 진행). 상품준비중이 회색인 이유는 취소는 이미 불가하고 반품은 아직 불가한 유일한 무액션 구간이기 때문입니다. C10-1 주문 상세의 항목 상태 라벨과 같은 규칙·같은 13/700을 씁니다.

상태 우측 보조 텍스트에는 그 상태에서 궁금한 날짜 하나를 답으로 붙입니다 — 배송중 = 도착 예정, 상품준비중 = 발송 예정, 배송완료 = 구매확정 예정, 구매확정 = 확정일, 반품·교환 = 세부 단계. 환불은 배지가 아니라 결과이므로 금액으로 표기합니다(취소 행의 "환불 18,900원").

취소·반품 행은 탈색 — 썸네일 불투명도와 상품명·금액 색을 낮춰(#9E9E9E) 살아 있는 주문과 한눈에 갈립니다. §02의 "품절·마감 텍스트" 예외와 같은 규칙입니다. 다만 탈색된 행에도 [취소 상세]·[반품 상세]·[교환 상세] 버튼은 남깁니다 — 상태만 죽었을 뿐 환불액·회수 일정·재발송 송장은 사용자가 가장 자주 확인하는 정보이고, 이 행이 유일한 진입 경로입니다(C10-3). 그룹 머리의 [주문 상세]는 주문 전체를, 행의 [○○ 상세]는 그 항목의 처리 흐름을 엽니다 — 목적지가 달라 두 경로가 함께 있습니다.

결제완료(맨 위 주문)는 [주문 취소]가 열려 있는 유일한 구간입니다 — 브랜드가 상품 준비에 들어가기 전이라 즉시 전액 취소가 가능하고, 준비중으로 넘어가면 버튼이 사라집니다. 상태 라벨이 로즈인 이유도 사용자가 지금 개입할 수 있는 상태이기 때문입니다. 공구는 마감 후 일괄 발송이라 부제에 발송 예정일을 적었습니다.

인라인 액션은 두 개까지 — 결제완료에 [배송 조회]·[주문 취소], 상품준비중·배송중·구매확정에 [배송 조회], 배송완료에 [배송 조회]·[반품 · 교환]입니다. 송장이 없는 상품준비중에도 [배송 조회]를 둡니다 — 그 화면이 발송 예정일과 "공구 마감 후 일괄 발송" 안내를 담고 있어, 이 구간에서 가장 궁금한 것에 답하는 경로입니다. 상세에서는 [반품 요청]·[교환 요청]으로 갈라지지만 목록에서는 한 버튼으로 묶었습니다 — 목록의 역할은 어느 상품을 처리할지 고르는 것이고, 반품이냐 교환이냐는 상세에서 대상이 확정된 뒤 결정하면 충분합니다(버튼 3개는 목록을 버튼 벽으로 만듭니다). 중립 외곽선만 쓰고, 로즈 채움 버튼은 목록에 두지 않습니다.

[구매확정] 버튼은 뺐습니다 — 되돌릴 수 없는 확정을 목록에서 한 번의 탭으로 처리하게 하면 오조작 위험이 큽니다. 조기 확정 기능을 도입할 경우 상세에서 확인 모달과 함께 두는 편이 맞습니다.

필터를 두지 않았습니다 — 상태 필터 칩을 얹으면 화면 위 46px을 상시 차지하는데, 개인 주문 내역은 목록 자체가 짧아(최근 6개월) 스크롤로 다 훑는 편이 빠릅니다. 상태는 각 행에서 이미 읽히고, 특정 상태만 보고 싶은 수요는 마이 탭의 배송 상태 카운터가 이미 받고 있습니다.

빈 상태는 주문이 아예 없을 때 하나뿐입니다(Tweaks의 listState) — 홈으로 보내는 [공구 구경하기]를 함께 둡니다.

남은 결정 — ① 6개월 이전 주문 조회 방식(기간 선택 or 더 불러오기) ② 구매확정 자동 처리 기한(배송완료 후 N일) ③ 조기 구매확정 기능을 상세에 둘지 ④ 부분 취소된 주문의 금액 표기 규칙 ⑤ 마이 탭 배송 상태 카운터를 탭했을 때의 동작(전체 목록 진입 / 해당 상태만 걸러 보여주기).

취소 완료 화면 — 결제완료 단계는 브랜드가 아직 준비를 시작하지 않아 즉시 취소됩니다. 그래서 버튼은 "취소하기", 완료 화면 제목은 "주문이 취소되었어요"입니다. 환불 정보 → 취소 상품 → [취소 상세] [주문 내역으로] → 안내 순이고, 장바구니에 다시 담았으면 제목 아래 한 줄로 알립니다. 닫기는 우상단 X — 뒤로가기를 두면 방금 끝난 취소 폼으로 돌아가게 됩니다. 브랜드 승인이 필요한 상품준비중은 1c에서 따로 다룹니다.

반품·교환 요청과 같은 페이지 문법 — 대상 상품 → 사유 → 금액 → 하단 고정 CTA. 같은 종류의 요청을 같은 방식으로 열어, 사용자가 한 번 배운 흐름을 그대로 씁니다.

부분 취소 — 주문에 상품이 여러 개면 체크로 고르고, 선택한 상품이 2개 이상 수량이면 취소 수량 스테퍼가 붙습니다(체크를 풀었다 켜 보세요). 진입한 항목은 미리 체크됩니다. 체크를 푼 상품은 흐리게 낮춰, 무엇이 취소 대상인지 한눈에 갈립니다.

환불 금액이 실시간으로 바뀝니다 — 선택·수량에 따라 상품 금액과 배송비 재계산을 즉시 보여줍니다. 전체 취소면 배송비도 환불되고, 부분 취소로 남은 금액이 무료배송 기준 아래로 내려가면 배송비가 환불되지 않는다는 점을 줄에 적습니다 — 확정 후에 알게 되면 분쟁이 됩니다. 발송 전이라 공제는 없습니다.

구성 — 전체 선택 → 상품 체크 → 취소 사유 라디오 목록(시트를 열지 않고 한 화면에서 고름 — 선택지가 4개뿐이라 펼쳐 두는 편이 한 번 덜 누릅니다) → 환불 정보 → 안내 → 하단 [취소 요청하기 (N개)]. 버튼 라벨에 선택 개수를 넣어 무엇을 취소하는지 누르기 직전에 한 번 더 확인시킵니다. 라디오는 C9 결제 수단과 같은 로즈 원입니다.

상품이 1개인 주문 — [상품 수: 1개]로 전환합니다. 고를 것이 없으므로 전체 선택과 체크박스를 없애고 "취소할 상품" 제목 아래 상품만 보여줍니다 — 풀 수 없는 체크를 두면 눌러도 반응이 없어 고장처럼 보입니다. 이 경우는 항상 전체 취소라 배송비도 함께 환불됩니다.

배송비가 있는 주문 — 위 [배송비 있음]으로 전환합니다(22,900원 주문 · 배송비 3,000원). 전체 취소면 배송비까지 함께 환불하고, 일부만 취소하면 남은 상품이 그대로 배송되므로 배송비는 돌려주지 않고 그 이유를 배송비 줄에 적습니다. 두 경우 모두 환불 예정 금액에 즉시 반영됩니다.

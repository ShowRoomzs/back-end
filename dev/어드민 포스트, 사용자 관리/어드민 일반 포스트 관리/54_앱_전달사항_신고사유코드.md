# 앱 전달 사항 — 게시물 신고 사유 코드 변경 (§54 rev.3 · C18)

- 대상: 앱(소비자) 게시물 신고 시트
- 근거: `54_어드민_일반게시물_모니터링_BE_설계서.md` 0-3 · 8-2
- 서버 반영: V192 마이그레이션과 함께 배포

## 무엇이 바뀌나

신고 사유가 **8종에서 6종**으로 바뀌고 코드 문자열이 달라진다. 화면 문구는 C18 확정안과 같다.

| 새 코드 | 문구 | 상세 입력 |
| --- | --- | --- |
| `MISLEADING_INFO` | 허위 · 과장 정보 | 선택 |
| `FRAUD_IMPERSONATION` | 사기 · 사칭 | 선택 |
| `ABUSE_HATE` | 욕설 · 혐오 표현 | 선택 |
| `SEXUAL_CONTENT` | 음란물 · 성적인 내용 | 선택 |
| `SPAM` | 스팸 · 반복 게시 | 선택 |
| `OTHER` | 기타 | **필수** |

없어지는 코드: `AD_DISCLOSURE` · `MEDICAL_CLAIM` · `MISLEADING_AD` · `COPYRIGHT` · `VIOLENCE_HATE` · `PERSONAL_INFO`.

## 앱이 할 일

1. 사유 목록은 `GET /v1/user/posts/report-reasons` 응답을 그대로 그린다. 코드를 앱에 하드코딩했다면 걷어낸다.
2. `POST /v1/user/posts/{postId}/reports`의 `reasonCode`는 위 6종만 보낸다. 옛 코드를 보내면 **400**이다.
3. `detailRequired`가 true인 사유(기타)만 상세 입력을 필수로 연다.

## 배포 순서

서버가 먼저 나가면 옛 코드로 신고하는 구 앱 버전은 400을 받는다. 앱이 사유 목록을 서버 응답으로 그리고 있다면 영향이 없다. 하드코딩한 버전이 배포돼 있다면 앱 업데이트를 먼저 내보내거나 서버 배포 시점을 맞춘다.

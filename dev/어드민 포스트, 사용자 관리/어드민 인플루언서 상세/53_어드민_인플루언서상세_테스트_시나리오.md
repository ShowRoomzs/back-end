### 1-3. 공통 확인 방법

1. 쓰기 한 번마다 **응답 · DB 행 · 처리 이력**을 같이 본다 — `creator`(status · 파기 컬럼) · `creator_sanction` · `creator_withdrawal_request` · `creator_admin_memo` · `creator_admin_history` · `creator_privacy_access_log` · `message`(`card_type`) · `connection` · `message_thread` · `users`(`role_type · status`) · `settlement_payout` · `settlement_history`.
2. 실패 요청은 HTTP 상태 + 응답 `code` 를 보고 **부수 효과가 없는지**(행 · 이력 · 카드 · 지급 행 불변) 본다. 응답 `code` 가 enum 이름과 다른 것: `INVALID_INPUT_VALUE` → **`INVALID_INPUT`**. 나머지는 enum 이름 = `code`.
3. **원값이 응답에 없어야 한다** — 마스킹 상태에서 실명 `김지민` · 휴대폰 `01033918842` / `3391` · 생년월일 `06.02` · 계좌번호 `333301128842` · 주민번호 `900101` 을 **응답 본문 문자열 검색**으로 확인한다(필드 값 비교만으로는 다른 필드로 새는 것을 못 잡는다). 계좌 전체 값 · 주민번호는 **해제 상태에서도** 없어야 한다.
4. 처리 이력은 `GET …/histories` 와 `creator_admin_history` 를 함께 본다. 저장 이력은 `historyId` 가 있고, 파생 행(가입 신청 · 입점 승인 · 사업자 구분 변경 결과)은 `historyId = null` 이다.
5. 운영팀 채널 카드는 `connection.type = OPERATOR_CREATOR` 스레드의 `message.card_type` 순서로 본다(`ACCOUNT_SUSPENDED` · `ACCOUNT_SUSPENSION_RELEASED`).
6. 지급이 걸린 케이스는 **인플루언서 · 브랜드 · 플랫폼 3행의 `status · fail_code · due_date`** 와 정산 이력 `PAYOUT_BLOCKED / PAYOUT_HOLD_RELEASED` 를 같이 본다. 브랜드 · 플랫폼 행이 움직이면 실패다.
7. 소비자 축 `users.status` 는 이 화면의 어떤 조치로도 바뀌지 않는다 — 정지 · 해제 · 탈퇴 승인 · 반려 케이스마다 `users.status = NORMAL` 을 함께 확인한다.
8. 알림(`MemberNotifier`)은 스텁 — 발송 여부를 판정에 넣지 않는다. 호출 여부만 필요하면 스파이로 본다.
9. 응답 시각은 전역 `JacksonConfig` 형식 **`yyyy-MM-dd'T'HH:mm:ss'Z'`**(초 단위 · 끝에 `Z` 고정)이다. 값은 서버 JVM 로컬 시각(`LocalDateTime.now()` · 코드가 시간대를 고정하지 않는다)이고 `Z` 는 형식 문자다 — 시각 비교는 `Z` 를 떼고 초 단위로 한다(18절 #19).

# 어드민 계약 관리 구현 안내

설계서 R1~R6을 `/v1/admin/contracts`에 구현했다. 기존 `ROLE_ADMIN` 인증을 사용하며 계약 조건을 수정하는 API는 없다. Swagger의 **어드민 계약 관리** 태그에서 요청·응답 스키마를 확인할 수 있다.

## API

| Method | 경로 | 기능 |
| --- | --- | --- |
| GET | `/` | 목록: tab, queue, keyword, sort, page(1부터), size(20/50) |
| GET | `/summary` | 검색과 무관한 큐·탭 수 및 조치 수 |
| GET | `/{id}` | 조건, 절차값, 전체 이력, 권한 |
| POST | `/{id}/review/approve` | 모두싸인 확인 3종, 발송 시각·기한 기록 |
| POST | `/{id}/review/reject` | 사유 코드 + 상세 1~1000자 |
| PUT | `/{id}/signatures` | 서명 2종(null로 해제), version 필수 |
| POST | `/{id}/conclude` | 서명 2종·문서 2종 확인 후 체결 |
| POST | `/{id}/expire` | 기한 경과 + dashboardRechecked=true |
| POST | `/{id}/resend/handle` | 미처리 요청 전부 처리; 요청 없이도 기록 가능 |
| POST | `/{id}/documents/presign` | documentType, contentType=application/pdf, fileName |
| POST | `/{id}/documents` | documentType, s3Key, fileName, sizeBytes로 등록·교체 |
| DELETE | `/{id}/documents/{type}` | 체결 처리 대기에서만 삭제 |
| GET | `/{id}/documents/{type}` | 새 다운로드 URL 발급(5분) |
| GET | `/{id}/document-draft` | 제출본 시각으로 캐시하는 PDF 생성본 |

조치 큐를 선택하면 해당 큐의 상태와 정렬이 tab·sort보다 우선한다. 반려는 전체 탭에만 포함되어 개별 탭 합과 전체 건수가 다를 수 있다. 재발송 요청은 계약 단위로 센다.

## 동시 처리와 문서 보관

- 상태 변경은 기존 조건부 UPDATE를 사용한다. 문서 조작·체결·서명 갱신·PDF 생성은 같은 계약 행을 잠그고 처리한다. 서명 갱신은 클라이언트 version도 검사한다.
- 쓰기 트랜잭션은 READ_COMMITTED로 실행한다. 잠금 대기 이전의 MySQL 조회 스냅샷 때문에 문서 존재 확인이 낡은 값을 읽지 않도록 한다.
- 업로드 URL은 15분 유효하다. 발급한 s3Key는 해당 계약·운영자·문서 종류에 귀속된다. 등록할 때 객체 크기·Content-Type·PDF 헤더를 확인한다.
- 업로드 객체를 별도 보관 키로 복사한다. 체결 이후에 과거 PUT URL을 재사용해도 등록된 증거 문서는 변경되지 않는다. 교체한 옛 파일과 임시 업로드는 DB 커밋 후 삭제하고, 트랜잭션이 롤백되면 새 보관 객체를 삭제한다.
- S3 권한: GetObject, PutObject, DeleteObject 및 동일 버킷 내 CopyObject에 필요한 원본 읽기·대상 쓰기 권한. `contracts/*/uploads/` 아래 등록하지 않은 업로드는 버킷 수명 주기로 정리해야 한다. 삭제 실패는 서버 로그에 남는다.
- 파트너 다운로드도 체결 이후에만 새 서명 URL을 제공한다. GENERATED_DRAFT는 어드민 전용이다.

## 마이그레이션과 PDF 실행

`V123__alter_contract_document_add_generated_draft.sql`은 제출본 캐시 시각과 반려 상세를 담을 이력 길이를 추가한다. 큐 인덱스는 V116·V119에 이미 있어 중복 V124를 만들지 않았다.

Thymeleaf 템플릿은 `src/main/resources/templates/contracts/draft.html`이며 제공된 v0.2 양식을 이식했다. 상품 반복, 6종 조건부 분기, 동적 페이지 푸터, 서명면 분리, 금액 한글 표기를 처리한다. 리워드는 기존 RewardCalculator를 사용한다. 입력값은 HTML escape하고 렌더러의 외부 네트워크 접근은 차단한다.

로컬 Chromium 설치와 실제 PDF 테스트:

```powershell
.\gradlew.bat installContractChromium
.\gradlew.bat contractPdfTest
```

일반 테스트는 Chromium이 필요한 `contract-pdf` 태그를 제외한다. 렌더링 결과는 `build/contract-pdf/`에 저장된다. 서버 요청 중에는 브라우저를 다운로드하지 않는다. 설치된 별도 실행 파일은 `contract.pdf.chromium-executable` 또는 `CONTRACT_PDF_CHROMIUM_EXECUTABLE`로 지정할 수 있다.

Dockerfile은 Playwright 1.58.0 Chromium 이미지, Java 21, Noto CJK 글꼴을 포함하도록 변경했다. Playwright Java 의존성과 이미지 버전은 함께 변경해야 한다. 인쇄 옵션은 [Playwright Java Page.pdf 공식 문서](https://playwright.dev/java/docs/api/class-page#page-pdf), 컨테이너 구성은 [공식 Docker 문서](https://playwright.dev/java/docs/docker)를 참고했다.

## 설계서에서 확정되지 않은 항목

- PDF에는 문안 미확정 초안 표시와 제13·14·19조의 법률 자문 대기 표시를 유지한다. 인플루언서 실주소는 수집되지 않아 `[미확정: 주소 수집 필요]`로 표시한다. 쇼룸 URL 주소를 대신 넣지 않는다.
- 생성 전 알 수 없는 서명 기한은 설계서 권고에 따라 전자서명 솔루션 설정을 따르는 문구로 처리한다. 관할 법원도 구체 법원명을 추정하지 않는다.
- 공구 모듈이 없어 체결 상태만 확정한다. groupBuyId는 null이며 공구 생성 성공으로 응답하지 않는다. FE 체결 확인 문구 역시 공구가 즉시 생성된다고 안내하면 안 된다. 이후 공구 도메인이 기존 assignGroupBuy 게이트로 연결한다.
- 계약 알림 채널은 기존 ContractNotifier의 stub 상태를 유지한다. 승인·체결·만료의 양측 호출과 반려의 브랜드 호출 지점은 연결했으며 실제 메일·푸시 발송은 하지 않는다.
- 캐시가 없거나 낡은 PDF의 신규 생성은 검토 대기에서만 허용한다. 발송 이후 새 PDF를 만들어 이미 보낸 문서와 보관본이 달라지는 경로를 막는다. 유효한 캐시는 이후 상태에서도 받을 수 있다.
- 문서 업로드·교체·삭제의 처리자를 남기기 위해 DOCUMENT_UPLOADED·DOCUMENT_DELETED 이력을 추가했다. 생성과 재발송 이력도 포함한다.

실제 S3 업로드와 Docker 이미지 실행, 운영 MySQL에 대한 Flyway 적용은 배포 환경에서 별도 검증한다. 테스트의 외부 S3는 모의 객체를 사용한다.

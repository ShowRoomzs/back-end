## 5. 판단한 것 · 남긴 것

### 5-1. 판단한 것(기획 확인 권장)

- **C1 칩 집계 식을 목록 조건에 맞췄다.** 「반품·교환」 칩은 박스(요청) 단위 → 클레임 행 단위(한 박스 2건이면 2). 탈퇴 차단은 박스 단위 그대로라 숫자는 다를 수 있고 0 여부만 같다. 「열린 문의」의 상품 문의 몫에서 삭제 요청 검토 중인 문의는 빠진다(상품 문의 모니터링 「답변대기」 탭과 같은 식).
- **A1 사유 우선순위**는 판정 순서 그대로(정지 → 계좌 확인 → 세금계산서). 이미 코드가 있는 행은 코드가 이긴다(계좌 확인으로 보류된 뒤 정지되면 계좌 확인이 보인다).
- **B2** 는 이름 외에 `counterpartyType` 을 더했다(어드민은 양쪽 채널을 다 봐서 「브랜드(…)」/「인플루언서(…)」를 정해야 한다).
- **B3** 정책값은 별도 GET 이 아니라 게시물 상세에 붙였다(조치 모달은 상세에서만 열린다).
- **D4** 「합의 대기」에 건수를 붙였고, 정산 · 조정이 모두 0 이면 정의 문구를 낸다.
- **E1 배송 예외 경과**는 경보가 켜진 시각 컬럼이 없어 「무소식 시작 시각」(예외 관리 목록 「경과」와 같은 값)이다. 실제 큐 진입보다 앞설 수 있다.

### 5-2. 이번 범위에서 고치지 않은 것

- **기획 확인이 필요한 것**: 파트너 성과 목록 「집계 중」 행에 진행 중 공구 포함 여부 · 파트너 홈 「다음 지급 예정」 금액(합계 vs 다음 1건) · 스튜디오 「계좌 변경 확인 → 정지 해제」 문구 · 스튜디오 「게시물 조회」 정의(고유 조회자 vs 횟수) · 스레드 정보 바 「서명 진행중」에 양측 서명 완료 계약 포함 여부 · 사이드바 회원 수의 탈퇴 포함 · `/members/withdrawals` 통합 목록 · 스레드 탭 숫자 정의(36 B-7).
- **문구 · Swagger**: 스튜디오 홈 할 일 카드 6종 · 「숨겼어요」 → 노출 중지 · 성과 상세 문구 · Swagger 옛 설명 4건 · 파트너 전환율 「명 / 건」 · 하이라이트 「개 / 건」 · 탈퇴 내역 「지급 예정 / 지급 보류」 · 게시물 노출 중지 409 메시지 · 기한 경과 삭제 처리자 「시스템」 표기.
- **각 묶음에서 남은 것**
  - 클레임 · 환불 `/summary` 는 `userId` 를 받지 않는다(소비자로 좁혀도 탭 숫자는 전체 기준). 브랜드 상세 칩(`BrandPendingChip`)에도 같은 종류의 어긋남이 있어 보인다.
  - 파트너 화면의 사업자 인플루언서 행은 사유와 무관하게 「발행 확인 후 지급」 · 스튜디오 화면의 브랜드 행 BLOCKED 문구는 「지급 보류」 그대로.
  - 해제 뒤 다시 보류되면 `originalDueDate` 는 확정 기준 날짜다.
  - 어드민 홈 사유 환불 「구매확정 후 하자」(시안 「… 반품」) · 브랜드 입점 「서류 3종」(시안 4종 · 첨부 서류가 3종) · 건별 행 제목은 시안과 다르다.
  - 운영 지표: 공구당 거래액 설명이 탭마다 다른 시안 문구는 지표 키 단위라 하나로 나간다 · SLA 준수율 등 일부 정적 정의 문구 · 환불 실패 사유 원문 길이 · 정상 수수료율 설정 중복(`admin.metrics.standard-fee-rate` · `settlement.platform-fee-normal-rate`, 1017 P7 부터).
  - Swagger 예시 시각에 `Z` 가 없다(실제 응답은 붙는다 · 원래부터).
  - 시안끼리 이의 신청 기한 예시가 다르다(같은 10.08 통지 — 스튜디오 S8 10.13 · 파트너 10.14 · 서버는 한글날 제외로 10.14).

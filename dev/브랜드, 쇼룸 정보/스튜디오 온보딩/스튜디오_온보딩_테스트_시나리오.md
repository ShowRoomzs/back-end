## 1. 범위와 판정 기준

- 대상 엔드포인트 **5개**

| 메서드 · 경로 | 인증 | 역할 |
| --- | --- | --- |
| `POST /v1/creator/auth/social/login` | 없음 | 승인 후 첫 로그인 → `registerToken`(5분) |
| `GET /v1/creator/auth/registration-info` | `registerToken` | 읽기 전용 값(계정 아이디 · 예금주 마스킹 · 쇼룸 주소 미리보기) |
| `GET /v1/creator/auth/check-showroom-name` | 없음 | 쇼룸명 형식 · 중복 확인 |
| `POST /v1/common/images?type=CREATOR_DOCUMENT` | 없음 | 통장 사본 · 사업자등록증 업로드(10MB · jpg/jpeg/png/pdf) |
| `POST /v1/creator/auth/complete-registration` | `registerToken` | 필수 정보 저장 → `isNewMember=false` · access/refresh 발급 |

- 화면은 「승인 완료 후 첫 로그인 시 강제 진입하는 활성화 게이트」다. 서버 쪽 게이트는 **`registerToken` 에 `role` 클레임이 없다**는 것 하나다 — `TokenAuthenticationFilter` 가 인증을 세우지 않고 통과시키므로 `/v1/creator/**` 는 401 이고, 위 표의 permitAll 경로만 열린다(TK-02).
- 아래 케이스는 **테스트 명세**이며 통과 기록이 아니다. 「현재 동작(추정)」으로 적은 것은 코드를 읽고 추론한 결과라 실행으로 확인해야 한다(13절).
- 통합 테스트는 H2 + `create-drop`(Flyway 꺼짐)이다. **`uk_creator_showroom_name` 은 마이그레이션(V74)에만 있고 엔티티에는 없어서** H2 에서는 쇼룸명 유니크 위반이 재현되지 않는다(SN-10). 문자열 비교도 MySQL 기본 collation(대소문자 무시)과 다르다(SN-09). 이 둘은 MySQL 수동 확인 대상이다.
- 소셜 로그인(TK-01 · TK-10 · TK-11)은 외부 제공자 토큰이 필요하다 — QA 환경 수동 확인 또는 `AuthService.authenticateSocial` 목으로 서비스 단위 확인.

### 1-2. 공통 확인 방법

1. **실패 요청은 부수 효과가 없어야 한다.** `creator` 행이 그대로(`is_new_member=true` · `showroom_name` · `showroom_address` · `connection_code` · `resident_registration_number_enc/_masked` · `resident_number_registered_at` · 은행 · 계좌 · 서류 URL 전부 `null`)이고, 운영팀 채널(`connection.type=OPERATOR_CREATOR`)이 생기지 않았는지 본다. 트랜잭션 하나라 중간 실패도 전부 롤백돼야 한다.
2. 성공 요청은 응답 + `creator` 행 + 연결코드 + 운영팀 채널 + 메시지를 같이 본다(8절).
3. **주민등록번호 원문은 어디에도 남지 않는다** — 응답 body(성공 · 실패) · 에러 메시지 · 요청 로그(`CreatorCompleteRegistrationRequest.toString()` → `****`) · DB 평문 컬럼. `_enc` 는 `PersonalDataCipher.decrypt` 로 풀면 정규화된 13자리와 같아야 한다.
4. 오류는 HTTP 상태 + 응답 `code` + `message` 를 본다. **`INVALID_INPUT_VALUE` 의 응답 `code` 는 `INVALID_INPUT`** 이고, `REGISTER_EXPIRED` 의 응답 `code` 는 `UNAUTHORIZED` 다(enum 이름이 아니다). 그 밖의 코드는 enum 이름 = 응답 `code`.
5. Bean Validation 은 **실패한 필드 중 첫 번째 메시지 하나만** 내린다(`GlobalExceptionHandler#handleMethodArgumentNotValidException`). 필드 순서는 보장되지 않으므로 문구를 확인하는 케이스는 **한 필드만 틀리게** 보낸다. 한 필드에 제약이 둘 걸리는 입력(빈 문자열에 `@NotBlank` + `@Pattern`)은 둘 중 하나의 문구면 통과로 본다.
6. 시안 · Swagger · 코드가 충돌하면 13절에 적고 어느 쪽으로도 임의 통과시키지 않는다.

- 대상

- 아래 케이스는 **테스트 명세이며 통과 기록이 아니다.** 자동 테스트 유무는 12절, 판정을 보류한 충돌은 13절.

### 1-2. 공통 확인 방법

1. 실패 요청은 HTTP 상태 + 응답 `code` + `message` 를 보고 **부수 효과가 없는지** 본다 — 온보딩은 `seller.is_new_member = true` 유지 · `market` 배송 컬럼 불변, 변경 요청은 `brand_change_request` 행 수 · `status` · `version` · `creator` 컬럼 불변 · 인플루언서 처리 이력 0 · 알림 호출 0.
2. `INVALID_INPUT_VALUE` 의 응답 `code` 는 **`INVALID_INPUT`** 이다(enum 이름이 아니다). 그 밖의 변경 요청 코드는 enum 이름 = 응답 `code`.
3. 변경 요청 쓰기 한 번마다 **세 화면을 교차 확인**한다 — 어드민 목록 · 상세 / 스튜디오 `GET /settlement` 의 `businessTypeChange` · `actions.businessTypeChange` / 어드민 인플루언서 상세 `pendingBusinessTypeChange`.
4. 주민등록번호 원문(뒷자리 `2345678`)은 **응답 본문 · 예외 메시지 · 애플리케이션 로그 · 항목 값** 어디에도 없어야 한다. 원문이 들어 있는 곳은 요청 행 `resident_number_enc`(PENDING 동안) · `creator.resident_registration_number_enc`(승인 후)의 **암호문** 두 곳뿐이다.
5. 대조표는 행 순서 · `fieldKey` · `currentValue` · `requestedValue` · `changed` · `locked` · `source` 를 전부 본다. 값은 서버가 완성한 표시 문자열(`개인 (비사업자)` · `원천징수 3.3%`)이다.

## 6. 파트너센터 온보딩 — 필수 정보 입력

대상 화면: `ui-partner-03-onboarding.html` (rev.1 · **`[v0.30]` 내용 갱신** — 발송 기한 · 제주 추가비 분리 · 버튼 「시작하기」) · 상태 3종. 근거 와이어프레임 `wf-partner-01-가입온보딩` F5.

### 6-1. 화면 위치와 성격 — `FE`·`BE`

어드민 승인 완료 후 **브랜드 담당자가 파트너센터에 재로그인하면 강제 진입**하는 활성화 게이트다. 완료 전까지 다른 화면 접근이 불가하다. 로그인·회원가입 흐름의 연장으로 취급하며, 주 액션 버튼 색상도 §9 로그인·가입 예외(검정)를 동일 적용한다.

상태는 3종이다.

| ID | 상태 | 제출 버튼 |
| --- | --- | --- |
| A | 초기 (반품비·교환비만 기본값 존재, 나머지 미입력) | 비활성 |
| B | 유효성 에러 (일부 필드 미입력/형식 오류) | 비활성 |
| C | 활성화 (필수 8개 전체 유효값) | 활성 — 버튼 문구 **「시작하기」** `[v0.30]`(구 「입력 완료 · 시작하기」) |

> A와 B는 화면 구조상 같은 화면이다. 별도 라우팅 상태가 아니라 **필드별 실시간 유효성 검사 결과가 다른 것**뿐이다. 구현 시 화면 단위 상태값이 아니라 필드 단위 유효성 맵으로 관리할 것을 권장한다(예: `isValid: Record<fieldId, boolean>`).
> 

### 6-2. 반품 수취 주소 — 필드별 문구 — `FE`·`BE`

### 6-3. 수취인 연락처 형식 — §4 담당자 연락처와 의도적 분기 — `FE`·`BE`

두 필드는 유효성 검사 함수를 공유하지 않는다. 재구현 시 하나의 "휴대폰 검증" 유틸로 묶지 말 것.

### 6-4. 배송·반품 정책 — 필드별 문구 — `FE`·`BE`

전 상품 공통 적용 정책이며, 최초 설정은 이 화면에서, 이후 수정은 **기본정보관리(§15-10)**에서 계속 가능하다. 수정 시 진행 중인 공동구매는 기존 값이 유지되고, 새 값은 다음 결제부터 적용된다(화면 안내 문구 그대로). ⚠️ `[v0.30]` 이 적용 시점이 기본정보 관리 상태 설명(「즉시 반영」) · 발송 기한 주석(「이후 접수 주문 · 주문 시점 고정」)과 다르다 → (3) §55 A-9.

| 필드 | 필수 | 기본값 | 입력 제한 | 단위 |
| --- | --- | --- | --- | --- |
| 기본 배송비 | 필수 | 없음 | 숫자만(스피너 제거·음수 입력 차단) | 원 |
| 무료배송 기준금액 | 선택 | 없음 | 숫자만 | 원 |
| **제주 추가비** `[v0.30]` | 선택 | 없음(미입력 시 0원 적용) | 숫자만 | 원 |
| 도서산간 추가비 | 선택 | 없음(미입력 시 0원 적용) | 숫자만 | 원 |
| ~~출고 소요일~~ → **발송 기한** `[v0.30]` | 필수 | 없음 ⚠️ | 숫자만 · **최대 7** | 「공구 마감 후 N영업일 이내」 |
| 반품비(회수비) | 필수 | **3,000** | 숫자만 | 원 |
| 교환비 | 필수 | **6,000** | 숫자만 | 원 |

| 항목 | 규칙 `[v0.30]` |
| --- | --- |
| 제주 · 도서산간 분리 | 제주는 항공 · 해상 운임이 별도라 육상 도서산간과 금액대가 다르고 택배사 요금표도 따로 나온다 — 한 칸이면 높은 쪽 값을 넣어 한쪽 소비자가 과다 부담한다 · **제주 먼저** · 권역 판정은 우편번호 자동(§15-10) |
| **발송 기한** | **공구 마감 후 N영업일**(최대 7 · 영업일 = 주말 · 공휴일 제외 · 연휴만큼 늦어진다) — 소비자 상품 상세에 「공구 마감 후 N영업일 이내 발송」 **자동 표시** · 판매 관리 발송기한 계산의 기준 · **주문 시점 값 고정**((3) §37-1 #4 — 「출고 소요일(결제 + N일)」 폐기) · ⚠️ 기본정보 관리는 「기본 3」인데 온보딩은 빈칸 필수 → (3) §55 B-16 |
| 선택 표기 | 선택 **3개**(무료배송 기준금액 · 제주 추가비 · 도서산간 추가비)만 「(선택)」 — 시안 HEAD의 「선택 2개」는 구 표기 |
| ⚠️ 시안 C 상태 | 발송 기한 필드가 구형(「일 · 영업일 기준」)으로 남아 있다 → (3) §55 D-21 |
| 약관 | 파트너 제9조①의 「출고 소요일」 표기는 정리 대상(P-03) → (3) §55 C-5 |

> `type="number" min="0"` 속성만으로는 음수 입력을 막지 못한다. `-3000`은 `min` 제약을 위반해도 문자열 자체는 입력된다. `-`/`+`/`e` 키 입력과 붙여넣기를 별도 차단해야 한다(구현 방식은 `ui-partner-03-onboarding.html` 하단 스크립트 참고 — How 영역이나 놓치기 쉬워 여기 명시).
> 
> 
> 반품비·교환비는 "필수"이지만 **초기 렌더링부터 기본값이 채워진 상태**로 시작한다. 담당자가 그대로 두거나 수정할 수 있다. 두 필드는 초기 상태부터 유효성 통과로 잡아야 제출 버튼 활성화 로직이 꼬이지 않는다.
> 

### 6-5. 배송 방법 필드 — 삭제 확정 — `FE`

와이어프레임(F5)에는 "택배" 고정 셀렉트가 있었으나, 옵션이 하나뿐이라 입력받을 의미가 없어 시안에서 **삭제했다.** 확장(택배 외 배송 수단 추가) 필요성이 생기면 별도 기획 검토를 거쳐야 하며, 와이어 표기만 보고 되살리지 않는다.

### 6-6. 제출 버튼 활성화 조건 — `FE`

필수 8개 항목(수취인 이름·연락처·주소·상세주소·기본배송비·**발송 기한**`[v0.30]`·반품비·교환비)이 **모두 유효값**일 때만 활성화된다. 제출 시점에 검증하는 방식이 아니라, 입력 도중 실시간으로 검증해 조건 충족 전에는 클릭 자체가 불가능하다.

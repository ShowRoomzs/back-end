### 51-0. 상태 축 — 회원 상태와 탈퇴 심사는 다른 축이다 — `FE`·`BE`

| 축 | 값 | 표시 |
| --- | --- | --- |
| **회원 상태** | 활성 · **정지** · 탈퇴 | 회원 상세 현재 상태 배지 = **목록 상태 열**(어긋나면 안 된다) |
| **탈퇴 신청 심사** | 승인 대기 → 승인(→ 회원 상태 탈퇴) / 반려 | 신청이 있을 때만 레일에 **탈퇴 신청 심사 카드**(신청일 · 경과 · 신청자 · 사유 · `[승인]` `[반려]`) — 회원 상태 배지에 올리지 않는다(승인 전까지 실제로 활성이다 — 공구가 돌고 주문이 들어온다) |

| 항목 | 규칙 |
| --- | --- |
| 축 교차 | **심사 중에도 정지 가능**(현재 상태 카드의 정지 버튼이 살아 있다) · **정지 중에도 탈퇴 신청 가능**(파트너 4-G2 — 정지는 새 일을 막고 탈퇴는 정리하는 일) |
| 상태색 | 활성 = 성공 · 탈퇴 승인 대기 = 경고(운영자 조치 필요 · 원칙 ①) · 정지 = 위험 · 탈퇴 = 중립(원칙 ② 해지) |
| 버튼 | 정지 = **흰 배경 + 중립 테두리 + 위험색 글자** — 꽉 찬 위험색은 **모달의 최종 실행 버튼에만** · 정지 해제 = 인디고(복구) |
| 카드 배치 | 「계정 상태 관리」 카드 **폐기** — 정지 · 정지 해제는 **현재 상태 카드 맨 아래**(구분선 아래). 정지 상태에서는 사유 · 처리자 · 일시 · 상세 사유 전문 · 지급 여부 · 소명 경로가 배지 바로 아래 같은 카드에 모인다(사유 코드만으로는 재검토가 안 되고, 이력 줄에 넣으면 잘린다) |
| 탈퇴 계정 | 정지 버튼 · 조치 액션 없음 — 해지된 계정은 제재 대상이 아니다 |

### 51-1. 계정 이용 정지 — 원칙과 범위 — `FE`·`BE`

| 원칙 | 내용 |
| --- | --- |
| **로그인 허용** | 로그인을 막으면 진행 중 주문을 처리할 사람(브랜드)과 이미 결제한 주문의 청약철회 · 반품 권리(소비자)가 사라진다 |
| **새로 벌이는 일만 차단** | 이미 소비자에게 열린 공구 · 결제된 주문 · 진행 중 정산은 그대로 간다 — 소비자 · 상대방 피해를 만들지 않는다 |
| **숨기지 않고 비활성 + 안내** | 차단 기능은 자리를 지킨 채 회색 비활성 + 안내 한 줄 — 감추면 「왜 안 되지?」 문의가 는다. 안내 줄을 붙일 자리가 없는 아이콘은 **누르면 토스트** |
| 사유 → 지급 자동 결정 | 지급 정지 여부는 **사유로 정해진다** — 운영자가 켜고 끄는 스위치가 아니다(§51-3) |
| 해제 | **회원 상세에서만** · 즉시 · 이력 기록 · 자동 카드 / 알림 |

| 회원 | 차단 | 허용 |
| --- | --- | --- |
| **브랜드**(어드민 15) | 상품 등록 · 새 계약 등록 · 인플루언서 연결 요청 · 「공구 개설 신청」 ⚠️ · **오픈 전 공구의 오픈**(오픈 승인 대기 · 체결 후 오픈 전 계약은 **승인 보류** — 해제 시 이어 간다) | 진행 중 공구의 판매(노출 · 새 주문 유지) · **주문 처리 전부**(발주서 · 송장 · 취소 요청 승인/거부 · 반품 · 교환 검수 · 재발송) · 상품 문의 답변 · 기존 상품 수정 · 품절 처리 · **기본정보 수정(계좌 · 사업자 정보 포함)** · 1:1 문의 · 소통 스레드 · 정산 조회 · 정산 조정 요청 |
| **인플루언서**(어드민 18) | 「공구 신청」 ⚠️ · 계약 서명 · **새 게시물 등록** ⚠️ | 진행 중 공구 운영 · 소통 스레드 · 정산 조회 |
| **소비자**(C20) | 상품 구매(장바구니 · 바로 구매 포함) · 상품 문의 · 팔로우 · 좋아요 · 게시물 신고 · 닉네임 · 프로필 사진 변경(C15-1) | **진행 중 주문 전부**(배송 조회 · 취소 · 구매확정 · 반품 · 교환 — C10 · C10-1~C10-5) · 배송지 관리(C13) · 1:1 문의 · 피드 열람 · 기존 좋아요 취소 |

| ⚠️ | 내용 |
| --- | --- |
| 없는 행위 | 「공구 개설 신청」(브랜드) · 「공구 신청」(인플루언서)은 **존재하지 않는다** — 공구는 체결 시 자동 생성(§29 · X-06). 브랜드 차단의 실질은 「오픈 전 공구의 오픈 보류」다 → §55 D-30(A-05) |
| 계좌 수정 허용 | 계좌를 고칠 수 없으면 「정산 정보 불일치」 정지를 풀 방법이 없다 — 정지 중 **정산 계좌 변경 요청((1) §16)이 해제 근거**가 된다 |
| 인플루언서 새 게시물 차단 | **공구 게시물 포함 여부 미정** — 포함이면 정지된 인플루언서의 **준비완료 공구가 게시물 게이트(§29)에서 막혀** 브랜드 공구가 열리지 않는다 → §55 B-11 |

### 51-2. 정지 사유 · 정지 모달 — `FE`·`BE`

| 회원 | 사유(필수 · 정형) | 지급 |
| --- | --- | --- |
| 브랜드 | 정산 정보 불일치 · **사업자 정보 허위 기재** · 상품 정보 허위·과장 · 배송 지연 반복 · 소비자 응대 불이행 · 기타(직접 입력) | **앞 2종 = 브랜드 몫 지급 정지** · 나머지 4종 = 지급 유지(돈과 무관한 사유로 이미 판매 · 배송이 끝난 대금까지 묶으면 과도한 제재) |
| 인플루언서 | 협찬 표기 누락 반복 · 표시광고법 위반 문구 반복 · 공구 진행 불이행 · 소비자 응대 불이행 · **정산 정보 불일치** · 기타(직접 입력) — 브랜드 목록을 그대로 쓰지 않는다 | 정산 정보 불일치 = 리워드 지급 정지 · 나머지 = 유지 · 고정 지급비는 무관(플랫폼을 거치지 않는다) |
| 소비자 | 정형 사유(시안 예 「운영정책 위반」) — 어드민 13 소관 | 해당 없음 · 소비자 화면에는 **정형 사유만**(상세 사유 미노출) |

| 항목 | 규칙 |
| --- | --- |
| 상세 사유 | 선택 — **「기타(직접 입력)」일 때만 필수** · 사유 선택 전 `[정지]` 비활성 |
| 경고문 | **차단 범위 / 허용 범위 / 지급 여부 / 소명 경로** 네 가지를 모두 적는다 — 무엇이 멈추고 무엇이 계속되는지가 정지의 핵심 |
| 지급 줄 | 사유를 고르면 「브랜드 몫 지급: 지급 정지 — 이 사유는 계좌 · 사업자 확인이 필요해 자동 정지됩니다」처럼 **자동 표시** `[근거 대기-PG]` |
| 통지 | 사유가 알림으로 발송된다 · 브랜드 · 인플루언서는 운영팀 스레드에 시스템 카드(§51-4) |
| 정지 기간 | 시안은 **기한 없는 정지 + 수동 해제** — 영구 / 기한제 미정(어드민 15 ⓧ) |
| 판단 지표 | 발송 기한 준수율 · 브랜드 귀책 반품률 · 취소 요청 거부율 · 문의 답변 시간 · 자동 알림 무응답 · 정지 이력은 **법률 검토 후** — 수치를 정지 근거로 쓰려면 약관 제재 조항(파트너 제25조)에 기준 · 임계값이 있어야 자의적 제재 다툼을 피한다 `[보류 · 자문대기-법률]` · 인플루언서는 게시물 반려 · 숨김 **횟수(사실 기록)**만 |
| ⚠️ 인플루언서 「허위 기재」 | 어드민 18 HEAD · C1 설명은 「정산 정보 불일치 · **허위 기재**일 때만 지급 정지」인데 M1 사유 목록에 허위 기재가 없고 경고문은 「정산 정보 불일치일 때만」 → §55 D-32 |

### 51-3. 지급 정지 — 계정 상태를 따라간다 — `BE`

| 항목 | 규칙 |
| --- | --- |
| 정산 진행 | 정지와 무관하게 **생성 · 정산 확인 기간 · 자동 확정까지 그대로**(§41) |
| 지급 정지 조건 | 정지 사유가 **정산 정보 불일치 · 사업자 정보 허위 기재**일 때만 — **그 회원 몫의 PG 지급 요청을 보내지 않는다**(예약분은 요청 취소) |
| 재개 | **해제 다음 영업일에 지급 요청** |
| 다른 몫 | 정지되지 않은 쪽 몫(브랜드 정지 시 인플루언서 · 플랫폼 몫 / 인플루언서 정지 시 브랜드 몫)은 **예정대로** |
| 구현 | PG 계약 형태에 따라 — **지급대행형** = 해당 셀러 지급 요청 미발송 / **분할 정산형** = 하위가맹점 지급 보류 요청 `[근거 대기-PG]` |
| 정산 화면 | 정산 관리에 **운영자 보류 버튼을 다시 만들지 않는다** — 어드민 07b는 이 상태를 **표시만**(§41-5 · §45) · 「정산 신청 차단」 · 「정산 보류」 서술 **폐기**(정산은 신청 절차가 없고, 보류는 조정 협의 전용이다) |
| 레일 표기 | 「브랜드 몫 지급: 지급 정지」 / 「리워드 지급: 유지 · 사유가 정산 정보와 무관」 — 「정지됐는데 돈은 들어오나요」에 한 줄로 답한다 |
| 운영 현황 | 지급 정지 중 미정산액은 경고색 + 「지급 정지 중」 |
| 탈퇴와의 관계 | 지급이 멈추면 **정산 조건이 풀리지 않는다** — 「정지를 피하려고 탈퇴」하는 길이 없다(파트너 4-G2 · §51-5) |
| 고정 지급비 | 플랫폼을 거치지 않아 정지와 **무관**(모델 B · §29-9) |
| 개선 여지 `[확장 가능]` | 정산 계좌 등록 시 PG 계좌인증 API로 예금주명을 상호와 자동 대조하면 「정산 정보 불일치」 정지 자체가 준다 — 파트너센터 온보딩 · 기본정보 관리 소관 |
